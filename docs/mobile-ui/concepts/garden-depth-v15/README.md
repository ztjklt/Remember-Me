## 已确认的意思

用户已确认：**一朵花代表一组相关回忆，例如厨房里的往事**。

这是一条包含三个画面、两次深入的路径：

| 画面 | 展示内容 | 点击后发生什么 |
| --- | --- | --- |
| 花丛 | 每朵花对应一组真实回忆，显示组名和片段总数 | 选中的花从原位置移向中心并放大，其他花退开 |
| 花朵 | 同一朵花，花瓣承载组内片段或相关小组 | 被点击的原花瓣移出并延展，成为阅读画面的底衬 |
| 花瓣展开页 | 记忆意象、原话、来源、录音控制；有多条时纵向浏览 | 回听或阅读；返回时收回到上一层原位置 |

相同花朵在三层间保持形态、朝向与身份；花瓣展开时允许轮廓拉宽、曲率变柔，但保留浅缺口和底部收束。底衬铺开后再显示内容，文字和图片本身不跟着被拉伸。示意中的第三屏是“花瓣变成页面底衬”的一种理解，仍待用户对视觉方向反馈。

本提案保留既有自然背景、雾蓝花瓣、暖金花心和清晰深绿文字。首层只显示回忆组，不再同时铺出全部记忆点。情感颜色属于记忆标签，不与回忆组的目录层级混为一谈。

## 数量增长与真实数据

花朵不固定为上一版九朵装饰花；有多少回忆组才展示多少有内容的花。本图用既有三段虚构故事形成三个示例组，共 15 个记忆点，没有增添新的记忆事实。名称“厨房里的往事”等属于设计文案。

保留自然五瓣形态，不通过无限增加花瓣承载更多内容：

- 当前“厨房里的往事”使用 E03 的四个既有片段：m1 妈妈的小本子、m3 不一样，也喜欢、m7 终于愿意慢下来、m14 玻璃上的小圈。第五瓣轻淡显示“待绽放”，不伪装成可打开的内容。
- E01 的七个片段可以用五瓣组织：借伞与回应（m10、m11、m12）、窗边灯雨（m13）、慢慢读书（m15）、留好的饭菜（m2）、家人的等待（m5）。这是设计建议，未修改源数据。
- 一瓣只有一条时，直接阅读该条；同瓣有多条时，在展开页纵向浏览带标题与来源的小节，不要求再进入第四层。
- 新的回忆组增加一朵花；同组新增内容应落入合理的小组，或提示拆为新的相关回忆组，不能为凑五瓣将无关内容强行合并。大量花朵时采用分区/分页与搜索入口，位置以稳定 ID 保存，不随每次打开随机变化。

最后三条是建议方案，不代表分组算法、持久化或大数据量交互已经完成。本轮没有冻结共享 Contract。

## 两次转场的先后顺序

**花丛 → 花朵，建议初值 420ms**：

1. 原花轻微响应点击，立即确认选中对象。
2. 同一朵花沿原位置放大、移向画面中心；周围花与枝条缓慢淡出。
3. 背景保持连续，仅做轻微景深变化。
4. 花停稳后显示花瓣标题、组名和返回入口。

**花朵 → 花瓣，建议初值 460ms**：

1. 保留点击到的瓣形，其余花瓣和花心淡出。
2. 这一片花瓣移向阅读区，逐渐展宽为页面底衬。
3. 图片以遮罩揭示，原话和播放控制轻轻显现。
4. 只在用户点击后播放音频。示意沿用 E03 的合成音频时长 01:18，尚未逐句对齐。

时长均为设计初值，尚未做真机帧率或手感验收。建议使用共享元素位置/缩放、轮廓遮罩和内容淡入的组合；复杂连续轮廓变形应先做可撤销的动画实验，再确定原生实现。

## 返回与操作边界

- 返回按相反路径约 300ms 收回，恢复之前的花丛位置、缩放、筛选、花瓣选中态与阅读滚动位置。
- 返回入口始终可见；深层面包屑可直接回到花园。Android 系统返回逐层退回，不能跳首页。
- 快速返回应中断当前过渡，从当前视觉状态继续，不等动画播完；连点不能叠加多个过渡或多次入栈。
- 手指拖动与点击区分，移动后不误入花瓣；触控范围随视觉设置下限，不能只能精准点击一条细边。
- 减少动态时改成短淡入淡出，保留位置与层级提示；大字号下允许改为同一数据结构的列表入口。
- 图像未就绪先显示稳定底衬，失败时仍能看原话、回听；返回上一层后音频暂停。保留原始来源与 AI 意象标记。

以上为后续实施应满足的行为，不是已通过的产品测试。

## 与当前实现的关系

当前 v14 的九朵花是装饰绘图，15 个记忆点仍直接进入浮窗/场景。下一轮如确认本提案，需要将装饰花与真实回忆组绑定，再增加独立花朵视图和花瓣展开视图。上一轮“15 点一枝”的布局规则不能直接冒充此次分层分类方案。

代码实现应等设计反馈后单独推进。先确认分组与两段转场的视觉表达，再在本地网页制作一条真实可点的路径，之后再评估 Android / iOS 的共享元素与手势实现。此处没有新增录音、模型或实时生图能力。
