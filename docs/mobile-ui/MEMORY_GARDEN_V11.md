### 顶部是什么？大小准确吗？

平台/深色/大字号/场景等是**设计工作台**，不进入正式 App。新演示模式完全隐藏它们。手机内的“演示资料 · 不采集声音”是诚实标识示例用的提示，也不是正式 App 的常驻产品功能。

桌面留有足够空间时，演示画布内容区为 **390 × 844 CSS 逻辑像素**，边框另计；窄窗口高度会适配可用空间。宽度不超过 480 的手机浏览器直接使用可用视口，不把桌面框按比例缩小。设计工作台实时显示实际画布宽高。CSS 逻辑像素不等于截图物理像素、手机硬件分辨率，也不能代表原生安全区、软键盘、读屏和双指手感已经通过真机验收。

## 这一版的主线

```mermaid
flowchart LR
  A[档案：记忆花图] --> B[点开：原话冒泡预览]
  B --> C[走进这段回忆]
  C --> D[看记忆意象 / 读原话 / 回听整段示例]
  D --> E[看看同一段故事里的其他记忆]
  D --> A
```

- 五瓣花是信息空间的形状，15 个光点对应 15 条可追溯的原稿摘录，没有填充假的记忆点。
- 温暖、牵挂、成长、善意、沉静是本次人工编排的主题标签。颜色旁总有文字，原生版本应允许用户纠正标签，不把颜色当成模型判断的心理状态。
- 细线只连接**同一原稿故事**里的点；不是模型发现的人物关系、因果或相似度置信度。
- 图上可拖动，放大/缩小/归位，支持鼠标滚轮和双指 Pointer Events；键盘聚焦画布后可用方向键、加减与 0。点位是 48 CSS px 的圆形目标，放大时不随画布无限膨胀。
- 点开先出现原话小卡，二次点击进入回忆。返回保留所选点、图的位置、缩放、搜索、筛选和页面滚动，不要求重新寻找。
- 搜索收入标题栏图标，展开后检索标题、原话、故事名及主题。保留普通列表入口，方便搜索和辅助阅读。
- 没有粒子系统，也没有永不停歇的背景动画。浮窗轻浮现，页面使用已有的渐变/位移动效；减少动态时停用。
- 桌面场景采用左右两栏；手机按意象、原话、声音顺序呈现。场景共同使用暖色海边背景，不让每张生成图片任意决定整个页面的视觉主题。

本轮素材来自工作区 `materials/zh-life-review-v1/` 的 **E01–E03**，叙述者是虚构的林岚。

`memory-garden/data.js` 中的记忆点由人工挑选原稿短句；标题和导语也是演示文案。没有把它们写成 AI 自动提取结果。来源全文可从场景页打开。

新场景播放的是 MP3 真文件，不是递增的假进度。支持播放、暂停、拖动、整段循环、加载失败后重试；切换场景、离开页面、隐藏标签时暂停。声音不会自动播放。摘录尚未做逐句时间对齐，因此明确写“播放整段故事”，不做未经验证的片段跳转。

旧“桂花”录音/核对流程仍是原有状态模拟，不能把新花园中的真实 MP3 播放推广为整个原型都接了录音或模型。新故事与旧桂花示例不共用来源。

## 一致的记忆意象

三张图使用内置 imagegen 工具分别生成，**实测都是 1536 × 1024，3:2**。原始输出不改图，复制到 `memory-garden/images/`；卡片保留画幅。完整实际提示词见 [generation-prompts.json](memory-garden/generation-prompts.json)，素材哈希与来源见 [asset-manifest.json](memory-garden/asset-manifest.json)。

固定部分：温暖但不过分泛黄，奶油纸色、鼠尾草/橄榄绿、灰蓝、少量蜜金；粉彩与水彩叠染、细纸纹、自然柔光、成熟的日常绘本质感。没有 UI、文字、可辨认的人脸、霓虹或玩具般的 3D。可变部分只描述这一段记忆的环境、物件、天气与动作。

同一段故事下的多个记忆点先共享一张图，避免每点生图导致重复、费用与风格漂移。固定提示词能减少漂移，但不能保证完全一致；后续应同时固定可用的参考图、模型/样式版本并做结果检查。若供应商不支持指定尺寸，服务端统一交付画幅，主体保留安全边界，不拉伸内容。

所有图都标为**记忆意象 / AI 绘制 · 非历史照片**。文字与原音是来源，图是表达。图像细节不能回流为新的记忆事实。

### 真正接进 App 时的最小纵向功能（方案，尚未实现）

1. 录音保存后转写，用户核对并保存一个明确版本；记忆点引用这个版本中的原话范围，保留录音 ID 和说话人信息。
2. 用户打开某个记忆点，选择“为这一刻画一张图”。先展示将发送的最少必要文字和场景描述；可以改写、不包含人名，或取消。录音授权不被复用为图像生成授权。
3. 通过服务端图像适配器排队生成。移动端不保存供应商密钥。固定画幅、风格块、负面约束、样式参考与版本，场景提示词只使用已确认的信息；不明人物/地点保留概括描述。
4. 使用按主体、记忆来源版本、风格版本和场景摘要构成的去重键。重复点击接同一任务；成功后缓存到本机，线下演示能打开旧结果。
5. 用户预览“采用 / 重画 / 暂不使用”。新图确认前不覆盖旧图；生成失败不阻止阅读、录音回听或返回花园。
6. 修改原话后，把旧意象标记为“基于旧文字”，由用户决定是否重画。删图与删记忆分开；删除记忆后的派生图/缓存清理由已有数据保留规则明确处理。

建议的 UI 状态：未生成 → 待确认内容 → 排队/生成中 → 可预览 → 已采用；旁支有取消、失败可重试、来源已更新。这里是设计方案，不是新增或冻结跨模块 Contract。

### 深度优先的后续顺序

先选**一段真实录音**，把“核对原话 → 一个记忆点 → 一张意象 → 回听可验证片段 → 纠正后更新”走完，再扩大场景数量。对应现有 Golden Path 和 Windows + Android 现场设备路线。

- 时间锚点验证后，播放器才能从“整段回听”升级为“回到这句话”；没有锚点继续播放整段。
- 多人讨论/采访需要说话人归属和本人/他人说法区别，不能把所有话写成一个人的事实；这一步会影响花图、提示词与意象的归属。
- 记忆超过一屏时先按故事/时间聚合，缩放后展开点，维持稳定布局。不能简单塞数百个点或加粒子代替清晰的信息层次。
- 原生实现复用现有 Compose/SwiftUI 路线：手势、导航状态与播放器由平台管理；图像请求走共享服务端适配层。相关字段通过单独提案协商后再落地。

## 材质与可读性

正文颜色不做 opacity 淡化；只改变容器底色。浅色卡片用 `#FAFBF6 / 86%`，深色用 `#1A2E24 / 84%`。按最差底图（浅卡压全黑、深卡压全白）合成，次要文字对比度分别约 **4.76:1 / 5.01:1**；这只是平坦颜色计算，不代替整页视觉验收。

默认“通透预览”用于本次用户要求的设计比较，可以在工作台切换“跟随系统”或“清晰实色”。跟随系统尊重减少透明度；更高对比度始终强制实色。原生端仍遵循系统无障碍偏好，不能照搬设计预览覆盖。
