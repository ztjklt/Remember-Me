# 0.16.7 连续对话与演示身份修正

2026-10-17，按用户本轮截图反馈实施。陈守义是虚构演示人物；采用现有 ECS、DeepSeek 和小米 TTS。

## 已修正的原因与行为

- 普通招呼、收音确认原先进入记忆检索/未知兜底。现在这些当前交互由 DeepSeek 单独生成，不加载个人记忆；复合问题和人物事实仍走来源核验。没有把固定句子伪装成模型输出。
- Android 原来每轮覆盖字幕。现在完整保留当前通话的双方发言、可上下滚动；查看旧内容时不随新字幕跳走。通话关闭后尚未新增跨通话历史保存。
- 断句窗口从普通 800ms 调整为 1400ms，简易模式 1800ms；“嗯/我想问一下”等未完成开头合并后续句子。它不是无限等候；长停顿可能开启下一轮，但上一轮不会消失。
- 检索原来总拼上一轮问题，污染独立新话题。只为短指代追问带入前文，完整聊天上下文仍独立传给生成器、不能当事实来源。
- 姓名资料确实存在，但通用向量/字符匹配漏掉了自述。姓名问题优先检索授权集合内的本人自我介绍，再交给模型与语义核验；不硬编码陈守义答案，不补编籍贯等未记录信息。
- 人物事实优先按 FACT 回答。问口味时不强行套条件模拟并附带待客、自我辩解；必要条件、否定和来源检查保留。
- 普通招呼也使用有总时限的相同请求备用机制，避免单次上游停顿一直占满等待窗口。完整记忆回答仍执行语义核验，不把未核验草稿播出。
