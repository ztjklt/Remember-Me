# 陈守义演示与语音等待优化

本轮按用户授权延续 DeepSeek、现有 ECS、Paraformer 与小米 TTS，不更换语音供应商。下文记录最初方案；用户后续明确要求清理旧测试账号，当前执行以 `docs/validation/2026-10-17-voice-demo-cleanup.md` 为准。旧测试账号与授权已停用，历史材料只保留于不可访问归档及私有备份。

## 已确认的问题

- “什么时候喝茶”先拿口味原话作候选，核验改成未知，修正再核验；两次网络请求可累计超过 7 秒。
- 3 秒主动取消第一次模型请求再重试，会丢掉正在生成的结果；需要保留全部连续样本比较，不能凭最快一轮决定。
- 演示混用了多个历史人物空间；演示应固定一个清楚标注为虚构的陈守义空间。

## 实施边界

1. 时间问题的低成本候选先检查所选原话是否含时间线索。缺少时可提出 UNKNOWN，仍接受全部来源的原有完整语义核验。不能将这个启发式作为最终答案。
2. 不取消真实修正后的复核：事实来源发生变化时仍需核验人物、时间、否定、未知和冲突。优化错误候选引起的返工。
3. UNKNOWN 语音表达改为“这个我还说不准。”，界面与证据仍标未知。原话逐字保留；生成式 Persona 的自然表达不得新增经历、亲密关系或承诺。
4. 固定小米白桦男声，并为模拟原音和 Twin 回复复用成熟、温和、不拖沓的表达要求。合成声音不等于真人克隆或真人认可。
5. 准备统一的虚构生活材料，使用真实 TTS → 上传 → ASR → 核对 → 记忆处理，不将脚本直接伪装成转写成功。旧数据保留，演示入口固定。
6. 同时测试已知生活问题、相邻追问、未提供的具体事实和超时恢复；记录连续轮次全部耗时、回答原文和失败。旧未知茶时间用例保持资料冻结，不用新故事填平它。
7. 最终交付 3–5 分钟演示建议与实际测试录像。清楚区分模拟 PCM 输入、App 实际音频播放与未验证的真机麦克风/录音豆路径。
