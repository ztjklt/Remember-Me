# 飞书版录音豆查找修正 — 2026-10-16

本人在 iPhone 上实测：飞书已连接录音豆，Remember Me 点击「查找录音豆」持续找不到设备。本轮未将飞书占用连接认定为根因。

## 已确认问题与修正

本地官方 D3200 V1.3.01 集成文档 `build/hardware-sdk-doc.txt` 第 395–416 行及 SDK `module_spplinkKit.h` 的 `startScan` 注释说明：`filters` 是设备 UUID 集合，默认空列表。现有适配器错误传入产品号 `["D3200"]`，可能把实际设备排除。现改为空列表，仍在发现回调校验 `productCode == "D3200"` 和有效设备身份。

SDK 文档区分飞书渠道 `1` 和 soundcore 渠道 `0`。App 没有按渠道过滤；现有 `com.lark.soundcore` 配件协议与后台配件配置保留。没有证据证明修改 `sppScan` 能发现已由飞书连接的设备，本轮保持原值。

## 修复包与验证

为保持手机既有录音与通话行为，使用上次安装的 **1.16.3 / 2026101613** 冻结源码，只修改扫描参数及包版本，准备 **1.16.4 / 2026101615**。当前工作区的 1.17.0 采集／花园重构未混入修复包；持续接收与重点区间也不据此宣称已安装。

准备时已核对基线 manifest 的 128 个文件摘要，最终差异仅为 `SoundcoreWorkAdapter.swift` 和 `project.yml`。含官方 SDK 的 Release 真机目标构建成功，`codesign --verify --deep --strict` 通过，主 App／录音活动扩展版本均读回 **1.16.4 / 2026101615**。没有把构建当成硬件扫描成功，也没有新增或运行模拟实际蓝牙发现的测试。

本轮设备查询「黑幕」仍为 `unavailable`；尚未安装，未进行硬件扫描、绑定或录音。继续安装前需手机解锁连接 Mac，并确保本人的录音／通话已经结束，避免覆盖安装中断正在使用的功能。

本机证据目录：`build/device-bean-scan-20261016-2026101615/`。共享 Backend Contract、后端部署与厂商凭据不变。

## 真机复验

1. 安装修复包后，确认 iPhone 已给 Remember Me 蓝牙权限；前台打开「录音 → 蓝牙连接」，关闭自动同步后查找设备。
2. 飞书已连接不代表 Remember Me 已建立自身 SDK 会话。若仍查找不到，先结束录音并等飞书传输完成，暂时完全退出飞书再查找，以检验连接占用这一假设。尚未证明硬件是否允许两款 App 同时使用。
3. 不要求解绑或重置。[飞书官方说明](https://www.feishu.cn/hc/zh-CN/articles/445044627145-%E5%AE%89%E5%85%8B-ai-%E5%BD%95%E9%9F%B3%E8%B1%86%E4%BA%A7%E5%93%81%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E)指出解绑会清除设备上未同步的文件；飞书已完成传输的文件也会从硬件删除。因此设备列表为空不能推断录音丢失或 SDK 不支持，应单独录制新的短样本复验。
4. 真实绑定、设备状态、30–60 秒录音取回与回听、转写和本人声音归属仍待实体设备验证。构建不能代替这些结果。
