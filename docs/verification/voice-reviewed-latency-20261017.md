# 保留核验的语音提速复测

本轮承接用户的“普通对话尽量 3～5 秒，继续 DeepSeek + 现有 ECS + 小米 TTS，不牺牲回答质量”要求。普通三轮完整 App 测量首播为 **4.796 / 4.329 / 4.536 秒**；更接近听感的数字音频等待为 **5.316 / 4.649 / 4.976 秒**。随后插话测试首轮为 5.306 秒，第二轮核验超时，不能声称所有场景稳定达到 3～5 秒。

## 核验为什么慢，哪些等待可以消除

此前普通事实问答要串行进行两次模型请求：先选择原话，再独立核验。必要的语义核验并非本地 JSON 检查；它要判断答非所问、人物归属、否定和条件、历史变化、材料冲突及错误的“未知”。这两次请求各自可能需要 1～3 秒，并可能触发既有的 3 秒串行恢复。

本轮普通事实问答先提出一条**已获授权的完整短原话**，再交给原来的完整语义核验。不是跳过核验，也没有把词面相似度当成正确率。只有核验通过才返回，原话的否定、条件和归属不截掉；核验看到完整的授权材料、冲突和对话历史。复杂问题、原因分析、含糊指代及需要生成的 Persona 回答保留原流程。核验否定且提出修正时，修改稿仍需重新核验；同一份被否定的答案不能重复投票直至通过。

还修正了两个不必要的开销：

- **重复数据库读取**：21 条测试记忆会触发 43 次证据/向量读取，向量先在准备时逐条取、排序时又取。现改为当前授权事务内批量读取。回归验证候选、排序和证据输出一致，查询数不超过 5 次。没有缓存答案，内容哈希、模型版本和最新授权检查仍保留。
- **标点误触发慢分支**：“刚才说的茶，你喜欢浓一点还是淡一点？”仅因话题引导后的逗号被当成复杂问题，额外选句耗时 2.030 秒。现识别这类明确话题前缀；提交核验的原始问题、历史和证据不变，第二个问题或含糊指代仍走原流程。

核验字段修复时曾丢失完整问题范围与指代约束，已补齐。对“喜欢什么茶”这类开放式口味问题允许回答材料明确提到的浓淡，不擅自把问题缩成具体品种；若用户明确问品种而资料没有，仍须回答未知。

小米音频继续与核验并行准备，仅在最终文字完全匹配并通过核验后才播放。修正稿取代旧稿时丢弃旧音频，表格列的是最终播出稿的首 PCM。没有缩短用户停顿阈值，没有删掉限定条件，没有在核验前播放。

试验过在 ASR 中间结果阶段提前检索；在当前两核服务器上没有稳定收益，并出现 CPU 争用迹象，已关闭 `REMEMBER_REALTIME_VOICE_PREFETCH_ENABLED`。原配置备份保留，没有更换服务商或服务器。

## 最终普通三轮完整流程

单位：秒。没有模型生成或改写原话；三轮都将完整原话交给完整模型核验。TTS 在核验期间准备，仅在核验成功后发送到手机。

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 平时喜欢喝什么茶 | 0.812 | 0.636 | 2.420 | 0.375 | 0.732 | **4.796** | 5.316 |
| 第一次独立开 12 路是哪年 | 0.952 | 0.463 | 1.803 | 0.332 | 0.381 | **4.329** | 4.649 |

其他后端处理包括当前权限/材料检查、结构校验和调度。核验结果就绪到手机首播另外约 0.6 / 0.7 / 0.5 秒，包含服务端最后检查、传输与播放调度；设备与服务器计时位置有差异，不能把它当成单独精确网络 RTT。实际返回内容分别保留淡茶及不喜甜的限定、1987 年及“不是 1986”的更正、完整浓淡口味原话。

三次 DeepSeek 请求分别输出 72 / 50 / 72 tokens，核验材料约 6850 / 3878 / 6233 tokens，没有用删掉证据或缩短推理输出硬上限换时间。完整记录为 `emulator-topic/`，原速音轨与录像为 `rendered-topic/`。数字音频以 10ms 窗口 RMS > 200 判定有声，不能代替真人听感或物理声学延迟。

## 插话与失败恢复

首次插话测试：茶口味首播 **5.306 秒**，核验 2.982 秒；输入下一句后 **231ms** 停止旧音频。下一句“那你一般什么时候喝？”未播放答案，输入结束 **9.693 秒**后显示可重试错误。核验首次等 3 秒、串行重试再等 5 秒，均停在等待模型接口响应头，总核验 8.002 秒。连接和 TLS 分别约 0.12 / 0.10 秒，不是本地重复查库造成的等待。

这是实际 `ProviderTimeout`，不是成功回答；未经核验的预合成音频没有播出。没有供应商内部日志，无法进一步区分服务端排队和模型处理。失败日志和原始完整录屏保存在 `emulator-interruption/`，不作为通过录像。

第二轮首次核验触发 3 秒串行恢复；核验判定已有口味原话不能回答具体时间，改为未知，再次完整核验后播出。最初口味原话的音频被丢弃，没有把它计作成功回答。插话输入至停止旧音频 **387ms**。本轮检查插话、后续回答、正常播完和点击结束释放通话；**未重测退后台暂停**，旧截图不作为本轮证据。
