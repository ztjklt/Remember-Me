# iOS 孪生与语音界面优化

2026-10-14，Asia/Singapore。用户要求继续优化 UI，本轮沿用现有蓝色品牌和原 iOS 功能，集中调整孪生聊天、前台语音和旧聊天记忆。

## 交付行为

- 聊天页采用“和另一个自己聊聊”的本人视角。空状态给出两条可编辑问题，点击只填草稿、不自动发问；已连接且授权时显示直接语音通话按钮。
- 旧聊天记忆及我的理解与表达直接出现在页面顶部；仍保留加号菜单入口。说明明确区分手机恢复最近 20 组消息与已开启的更早／跨会话检索。
- 通话页分成当前声音、用途确认、本人音色进度卡。开始按钮固定在底部，等待条件有可见解释；通话中静音、打断及结束固定在底部，状态文字和图标随实际连接／监听／思考／说话状态变化，不制造音频波形或进度百分比。
- 本人音色设置默认可收起，已有未提交样本自动展开；录制、提交、就绪三个阶段均可辨认。真正 ready 才展示合成试听；来源、推测标签和失败情况保留。
- 历史记忆页突出真实可检索条数、启用开关、搜索、摘要和原消息；空记录、关闭检索及无匹配结果分别说明。
- 正文跟随系统大字号；固定操作区及短开关的文字最多使用 accessibility1，避免其占满屏幕并遮挡表单。触控区域保持至少 44 点。

没有 Backend / AI / Voice 协议、供应商、授权条件、存储和上传时机变更；没有发送模型请求、替本人录音或确认许可。没有更改 Android。

## 验证与修正

Swift 解析、Simulator 构建、Release 签名真机构建通过。第一次构建前有一处生成代码的换行字面量未闭合，修正后编译通过。

首轮 UI 六项中四项通过；展开音色设置后，SwiftUI DisclosureGroup 的容器 identifier 覆盖了录制按钮／待提交文字的 identifier，使两项失败。改成独立展开按钮与内容，保留可读的展开状态，两项复验通过。

极大字号用例发现长用途标签仅部分进入屏幕时，Toggle 被判断可点击但点击不生效，且固定操作区占屏过多。把说明与短开关分开，并限制固定操作区字号；默认声音许可门槛及极大字号确认／开始两项复验通过。UI fixture 均隔离，不是真人声音或云端问答。

原六项及新增极大字号用例共七个不同 UI 用例通过；进一步在深色模式检查聊天主页面、空聊天、历史记忆，三项通过（历史记忆是重复用例），合计九个不同 UI 用例。报告分别为 build/ui-twin-20261014/ui-tests.log、ui-tests-repair.log、ui-tests-large-final.log、ui-tests-chat-dark.log 与对应 xcresult。

已检查正常字号默认通话、已就绪音色、通话中控制、旧聊天、极大字号，以及深色聊天／空状态／旧聊天截图。截图为模拟器隔离样例，没有将预置状态当成本人复刻完成。
