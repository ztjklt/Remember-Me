# 千问真实录音联调 — 2026-10-05

分支：`feature/ai-agent-core`，普通仓库目录，无新增工作树。范围是修复 Android 录音被 fixture 固定句替代的问题，以及身份问题缺少检索结果的问题。

## 配置与契约

- Backend：新增 `dashscope` STT adapter，使用工作空间原生接口及 `qwen-audio-3.0-asr-flash`，上传实际音频的 Base64 Data URI。
- AI Core：工作空间 OpenAI-compatible 接口，`qwen3.8-flash`，`AI_ENABLE_THINKING=false`，部署版本 `qwen3.8-flash-remember-me-20261005`，Memory prompt `memory-extractor-v3`。
- API Key 只在两份服务端 `.env` 中，文件权限 0600，Git 忽略；Android 没有 Key。验收报告不保存 token，包含个人原文的报告也只放在被忽略的本地 build 目录。
- `integration-contract-v0.1.2` 和实验 Agent 契约均未修改，没有数据库迁移或 Android 代码变更。供应商请求中将 Memory 摘要限定为 `AI_INFERENCE`；Evidence 保留原话来源，既有逐字、位置与引用校验继续执行。
- `--serve` 默认 configured；fixture 必须显式选择，两个模式保留独立会话和数据库。旧 fixture 数据没有自动改写为真实数据。

## 实际验收

输入是用户此前从 Android 上传的实际 MP4 音频，244,996 bytes，内容为自我介绍。通过 Backend HTTP 上传到 configured 会话，由持续 Worker 完成全部处理；没有给 Worker 注入转写或模型结果。

| 检查 | 结果 |
|---|---|
| 工作空间 `/models` 与严格结构化输出探测 | HTTP 200，所选模型可用 |
| 真实 ASR | HTTP 200，转写包含姓名、研二身份、研究方向、学院与就业意向 |
| Memory → Persona | Episode ready，5 条 Memory，snapshot revision 1 |
| “我是谁？” | HTTP 200，ORIGINAL，含本人录音 Evidence |
| “我的研究方向是什么？” | HTTP 200，ORIGINAL，含本人录音 Evidence |
| 原文与 provenance | 回答逐字等于授权 excerpt，span 0–63 对应真实转写；模型版本为实际部署版本 |
| 历史 fixture | 数据仍独立保留，没有混入 configured 模型 |

本地详细结果：`build/agent-demo/provider-check/real-loop.json`，`verified=true`。文件含个人材料、不含 token，权限 0600，不提交到 Git。日志在同目录及 `build/agent-demo/configured/`。

## 运行与边界

从项目根目录运行 `services/backend/.venv/bin/python scripts/run_agent_demo.py --serve`。Android 用 `build/agent-demo/configured/session.json` 的三项会话值，并通过 `adb reverse tcp:8000 tcp:8000` 连接 `http://127.0.0.1:8000`。此前的实际录音已经作为 IMPORT 在此会话重新处理，也可重新录音验证；不要继续使用 fixture 凭据。

本次验证是实际音频与实际供应商的服务端 HTTP 联调，没有操作手机界面完成新的真机验收。真实模型的锁定/五维校准没有在本次替用户填写答案；该完整状态循环由离线 HTTP 回归验证。

初次联调出现文本请求超时，配置非 thinking 推理后成功；Memory 原文位置与摘要来源标注曾被校验拒绝，提供程序计算的 span 并约束摘要来源后通过。后续研究方向问答出现一次 AI Core 502 / Backend 503，重试通过，保留在详细报告的 `initial_twin_failure`。未放宽校验，也没有回退固定测试句；仍需针对多条现场录音评估模型稳定性。

姓名同音字仍会有 ASR 误识别，应由本人校准，不能把转写等同于姓名认证。当前证据采用完整短录音原文，因此 ORIGINAL 回答可能返回整段自我介绍；较长录音的分段证据和检索质量尚待后续评估。
