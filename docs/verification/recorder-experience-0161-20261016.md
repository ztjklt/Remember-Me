# 录音体验修正验收 · 0.16.1

## 本次修正

1. 设备弹窗的四行信息压缩为一行：连接状态、电量、剩余空间进度条和百分比。数据仍取自 SDK，未知值显示 —；固件信息收进设备维护。
2. 录音豆页面移除手机“标记重点”入口。设备标记与既有手机补充分别计数；重点详情显示可靠的音频时间及对应文字，不把旧手机标记重命名成设备标记。
3. 录音结束进入同步、转写草稿出现、保存进入记忆整理时自动收起设备弹窗并呈现当前阶段。接收新录音自动返回首页；相同阶段的计时/进度/轮询不反复滚动或覆盖编辑中的文字。

## 原因与 SDK 适配

用户截图中“重点 31”对应的 64.16 秒录音，经只读检查标记元数据，31 个来源全部为 `phone`。旧界面把手机按钮产生的标记混在一个总数里，造成了设备重点的误解。

Soundcore 集成文档列出实时片段的 `isMark`、文件完成的 `markTimeStampList` 和解码的 `onDecodeFileMarkers`。检查实际使用的 1.3.02 AAR，D3200 文件完成路径传入空列表，`DecodeAudioFileManager.decodeInOrder` 仅回调文件成功。只等待最终时间数组不能保证拿到设备重点位置。

本版保留设备标记片段的内容指纹，下载完整原音、解码校验后，在有效的 160 字节 / 20 毫秒帧中寻找唯一匹配，以文件中的位置确定时间；重传去重，连续标记帧合并。直接收到的 SDK 毫秒时间列表仍然接收。没有唯一匹配、格式不符或缺少数据时显示待定位，不用手机时间、回调到达时间或猜测序号换算冒充设备时间。指纹和标记按账号、人物、设备及文件隔离持久化。

SDK 标记不是自动语气重读识别。没有实时标记片段且 SDK 未返回最终时间列表的离线录音，仍可能无法定位重点。部分未匹配片段不应解释为已经全部恢复。旧原音和手机标记保留。
