# 全应用超时排查 — 2026-10-16

时间均为 Asia/Singapore。范围：当前 iOS 录音／转写／记忆／Twin／音色及实时通话调用链、共享 Backend、当前 Android 源码和其历史集成版的区别。保留工作区原有改动；未更改 Backend Contract。

## 已定位的线上故障

本次确实遇到整个 iOS 后端停止响应，不能把用户反馈统称为手机网络问题。

- 发布仍为 `remember-ios-api-054 / ios-latest-f54e295dc7d4`，一个 Running 容器，1 CPU / 2 GiB，最小及最大实例数均为 1。
- `/health`、`/ready`、`/api/v1/service-info` 均在 10–12 秒内无响应。直接连接及读取环境代理设置的请求都失败；curl 的 DNS 0.053 秒、TCP 0.108 秒、TLS 0.180 秒，随后 12 秒收不到首字节。
- 运行日志最后正常请求时间为 18:57:51。19:13:45 查询时仍没有后续完成日志。
- 两次独立 PostgreSQL 只读检查发现：一个 `idle in transaction` 会话持有几乎全业务表的 `ShareRowExclusiveLock`；另一条 `INSERT INTO voice_utterances` 在等 `RowExclusiveLock`。第二次核验时，两者已持续 **1139 秒**，等待方明确指向该持锁会话。
- 源码路径与现场吻合：`read_answer()` 读取答案时取得 publication lock，正常返回前未结束事务；异步语音上传路由又在 API 事件循环直接执行同步 INSERT。当 INSERT 抢在前一个请求的 Session 清理之前开始，主线程等待数据库，清理无法获得执行机会，锁也无法释放，形成应用内自我阻塞。

**19:17:23 已作一次有条件的故障恢复**：重新核对 PID、阻塞关系、语句种类、表名及持续时间后，仅对这条仍在等待的 INSERT 发送 `pg_cancel_backend`。没有终止数据库、重启容器、删除记录、改变授权或发布新源码。取消的是尚未完成的语音写入；该次请求可失败，不能把它算为保存成功。

## 源码修复

### Backend

- `app/api/twin.py`：正常读取答案后显式提交／释放 publication lock，避免依赖延迟 Session 清理。
- 实时及国内语音路由：把同步数据库、对象存储和相关处理放到工作线程，避免拖住 API 事件循环。
- 声音样本先上传，再用短事务重新验证授权、来源和 profile 状态后发布；失败清理孤立上传，不在全局发布锁内等待对象存储。
- PostgreSQL 连接及锁等待增加有界保护；保留现有冲突／不可用响应和授权检查。
- 供应商音色状态读取使用较短的查询预算；复刻创建仍使用原独立预算。

Backend 最终文件、验证与限制见 [Backend 专项报告](BACKEND_TIMEOUT_AUDIT_2026_10_16.md)。

### iOS

- `AppModel.refresh()` 原来把任意刷新超时当作身份失效，清空页面、授权、输入草稿，并结束活动通话。现在短暂网络／服务失败保留当前内容并提示重试；401／403 仍清理访问。
- 成功读取授权列表且已知撤权时，先清理旧访问状态，再读取其余资料；后续资料读取超时不能保留已撤权的聊天或声音。
- 在变更聊天状态前核验内容版本；旧刷新超时不覆盖新版本提示。
- 三种主动撤权成功后令旧刷新失效，声音撤权回包校验原账号与 token，避免迟到结果恢复旧授权或清掉新连接状态。
- 普通录音的状态／转写结果读取对暂时断网、超时和 502／503／504 最多容忍两次连续失败；只重读状态，不自动重传录音或重放写请求。取消及权限错误不重试。
- `memories / episodes / model / questions / consents / calibrations` 六类纯元数据读取显式使用 30 秒等待预算，原来继承 300 秒。录音上传、模型调用和合成的预算保持各自语义。
- 火山 `/status` 实际也续租，但客户端以前只认可 `/lease` 成功，可能在状态请求正常时误判超时挂断。现在核对当前通话后认可两类成功回执；持续断网、撤权和过期仍结束通话。
- 音色页原有两处轮询且每轮重复读取 capabilities。现在只保留一处轮询，并合并进行中的 profile 请求；通话期间停止音色准备轮询。

## 其他发现与覆盖边界

| 位置 | 结果／限制 |
| --- | --- |
| 普通手机录音 | 开始录音本身走本机 AVAudioRecorder，不需要网络；停止后的云端上传、转写和查询会受上述整站故障影响。原音与 Episode ID 在失败路径保留。 |
| 多人录音识别 | `/process` 仍在单个工作线程请求中做实际识别，包含对象存储／供应商等待；可能超过客户端 90 秒。线程隔离可防止拖住整站，但不代表长录音识别等待已全面解决。 |
| 本机离线转写 | 固定 90 秒期限，长音频及实际中文离线模型能力仍需设备验证；没有静默改用其他云服务。 |
| 蓝牙／录音豆 | 本轮没有进行真实取回、锁屏长录或耳机切换验证。 |
| 当前 Android | 18 项单元测试、APK 构建、lint 通过；当前目录是本地录音装配，缺少本机模型权重，也没有真实通话网络实现。 |
| 历史 Android 集成版 | 与当前目录不同；约 15 个元数据请求串行执行、单请求 210 秒且共用 busy，失败清空旧内容。仅只读审查，未改另一工作区。其匿名版本接口本次 200／0.216 秒，不能据此声称全部业务正常。 |
