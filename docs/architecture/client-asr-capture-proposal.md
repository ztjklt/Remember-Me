# 客户端转写接力（2026-10-08）

用户已明确要求：因ECS访问Groq失败，先由客户端取得转写，后端接收结果并继续Agent业务。这里的“本地”是客户端发起既有Groq调用，不重新启用本地Whisper模型。已有报告只验证Windows当前网络路径可用，不代表任意手机网络可用。

## 本次有限变更

保留原上传接口；新增`POST /api/v1/episodes/client-transcribed`，multipart沿用录音字段，另外必须提供`client_transcript` JSON字符串。字段为`text`、`audio_sha256`、`provider=groq`、`model=whisper-large-v3`、`audio_export_confirmed=true`。原音仍必需。请求用真实Actor凭据，所有者与录音授权规则不变。

服务器对原音哈希与声明核对，将原始机器稿与简体核对稿分别保存；机器稿来源标记为client、模型标记client-reported/groq/whisper-large-v3。这只是客户端声明，不能伪装成服务器实际调用或已经验证的逐字音频对齐。导入仍为IMPORT，手机实际录音才用ANDROID_MIC/IOS_MIC。

新增记录直接进入既有EXTRACT/waiting，仍须走transcript-review确认后才能整理、命名、保存记忆与生成人物候选。新路径不排队服务端转写、不自动确认、不接收客户端生成的记忆/画像作为权威结果。失败保留已保存原音。相同幂等键必须对应相同原音与机器稿；不同转写不得覆写已核对历史。

增加REMEMBER_STT_BACKEND=client部署模式：服务端无需Groq密钥，也不会外发ASR请求；旧纯音频入口明确提示需要客户端转写，不能回退fake。其他模式仍兼容旧客户端。新的能力信息明确client模式不证明客户端ASR可用。

## 本轮客户端与验收边界

先提供受操作者控制的电脑工具，复用被忽略.env中的既有Groq配置。分开转写、上传和核对：成功ASR保存不可变检查点，上传允许断点恢复而不重复转写；后台地址显式配置，TLS不跳过验证，凭据不输出。

普通分发APK/网页不内置共享Groq密钥。手机采用何种可稳定访问且不暴露共享密钥的转写通道仍需独立接入；当前电脑工具不能写成“任意手机已可用”。服务器继续负责受权限约束的提取、人物归纳、问答、来源及授权，并非只存放客户端随意生成的记忆。

## 验收

规则测试覆盖：未核对无提取、原稿独立保留、原音哈希、非法payload、跨身份与撤销录音授权、幂等冲突、服务端ASR零调用、确认后的真实既有流水线，以及client配置不回退。真实调用另行记录，不把fixture测试冒充Groq/微信实际成功。

本次无需数据库迁移、无需改变旧v0.1-v0.4接口字段。部署采用新发布版本和只追加端点，旧7853d00发布包不能自动获得此功能；服务器实际更新及两身份全链路未执行时继续标明待验证。
