# 联系方式验证托付 v1

2026-10-17，产品所有者在本会话要求在独立分支同步做好亲友托付，采用已说明的手机号/邮箱验证、无账号跨设备领取、专属录音与多段选择、状态与撤销方案。这是该新增接口的授权及实现提案。基线 55ab8d9；不修改 AI Core、Agent 对话或现有 iOS 协议。

## 流程与范围

本人填写称呼和邮箱或中国大陆手机号 → 专门录音/选已有完整录音，可附文字 → 预览全部开放内容 → 明确确认并保存 → 复制领取链接或发送通知 → 亲友浏览器打开、输入指定联系方式、收验证码 → 查看该份内容。无需注册；验证码证明联系方式的控制权，不证明法定身份。原有账号专属信保持兼容。

首版即时托付，1–30段完整音频或纯文字；专属音频可不转写，不自动进入人物模型。选已有 Episode 时开放预览中的整段原音、核对文字及补充，不开放全部画像、关联记忆或 Twin。只选片段必须未来添加真实裁切资产。本次不启用未来身后条件或 AI 代理授权。

## 新接口

- GET `/api/v1/workbench/subjects/{S}/contact-entrustments`：本人的计划与服务能力。
- GET `…/sources`：可选已核对录音及本人的独立 letter 音频。
- POST `…/preview`：`sources[{kind:episode|dedicated,id}]`，返回完整文字/原音标识和 `source_version`。
- POST 基础路径：接收者称呼、渠道、联系方式、标题、可选正文、sources、source_version、days、`confirmed=true`、idempotency_key。来源和接收者不可原地替换；更改时新建后撤销旧计划。
- POST `…/{id}/notify`：发送领取通知；供应商接受不代表送达或已读。不自动重试不确定发送。
- POST `…/{id}/revoke`：按 revision 撤销，已有验证码及领取会话立即失效。
- GET `/receive/`：独立无账号浏览页面，领取 token 放 URL fragment，随后从地址栏清除；页面不引入第三方资源。
- POST `/api/v1/entrustment-receipts/challenges`：链接 token、指定联系方式；通过后仅向预设地址发6位验证码。
- POST `…/verify`：链接 token、challenge_id、code；五分钟过期、最多五次尝试、单次核销，返回独立30分钟领取 token。
- GET `…/content`、GET `…/audio/{kind}/{id}`、DELETE `…/session`：只认领取 token，每次验证计划状态、期限、来源版本及精确成员关系。不接受此 token 访问账号/主人公 API。

## 持久化与发送

新增独立表，联系方式与链接 token 用稳定服务端 Fernet 密钥加密；查找凭据/验证码用带域隔离 HMAC。无明文验证码、联系方式或票据日志。按 IP、目标联系方式、计划和时间窗持久化限流，重建会话不重置次数。第三方发送在事务外进行，完成后再校验状态；过期/撤销的晚到回执不重新开放访问。

邮件为 TLS SMTP，短信为阿里云 SendSms adapter，均须显式配置。无发送配置时草稿选择仍可用，但不能发出无法验证的托付；测试使用注入的内存信箱，不把它作为生产发送模式。通知/验证码请求被供应商接受不等于已送达；发送失败和超时明确呈现。

领取成功、内容打开与通知状态独立记录，不能伪称已收听。撤销阻止后续读取；已经复制的内容无法远程收回。来源修改/删除/录音许可撤销时关闭旧托付。浏览器定期核验、失效停止播放并清除展示；不承诺能撤回已经传出的字节。

## 验收

两独立接收者隔离、验证码错误/过期/重发/复用、限流、源变更/撤销/到期、跨账号越权、录音播放、供应商失败不假成功、幂等与迁移保留旧信件、Android构建及浏览器领取路径。真实短信/邮件与手机验证须在供应商配置完成后单列，不能用内存信箱宣称上线。
