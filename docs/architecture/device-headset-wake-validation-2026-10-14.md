# 录音设备、耳机与唤醒能力验证方案

状态：条件任务提案。会议 §3；当前授权交付是资料清单、适配器方案及验证步骤。没有官方 SDK／样机证据时不宣称设备已接入，也不启用后台／常驻唤醒。

## 已有与待验证

iOS 当前使用系统音频路线及输出选择器，前台手机／耳机通话，耳机移除、锁屏、后台、系统中断时结束；这些结束路径已有代码和定向用例。当前安装版本核对为 1.8.3 / 2026101408，实际设备麦克风、回声、蓝牙和有线耳机操作仍未记录。

Apple 文档确认路线变化会发送通知，连接与移除分别为 newDeviceAvailable / oldDeviceUnavailable；这支持现有监听路线变化的实现，但不能证明具体耳机已测过。见 [Responding to audio route changes](https://developer.apple.com/documentation/avfaudio/responding-to-audio-route-changes)。

Apple 对 record 类别说明，后台继续录音需要 UIBackgroundModes 的 audio 配置，来电等仍可中断。我们据此只把后台能力视为待实测条件；不能仅加 entitlement 就声称锁屏通话稳定。见 [AVAudioSession record](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/record)。

本机识别必须检查 supportsOnDeviceRecognition；为 false 时识别需要网络，requiresOnDeviceRecognition 不能创造本机能力。因此不能用系统识别选项承诺离线、无限时长或锁屏唤醒。见 [supportsOnDeviceRecognition](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition)。上述官方资料已于 2026-10-14 读取，具体系统版本与硬件行为需设备验证。

## SDK 资料准入与能力表

需要完整设备型号／固件、官方 SDK 版本／来源／使用许可、支持的 iOS／Android 版本、连接协议、示例程序、音频格式、录音列表／传输／控制文档、是否依赖厂商云及其用途、设备恢复／升级说明、样机。会议提及 Work 3200 是待验证对象，不推断任何通用蓝牙协议或未公开 SDK。

| 能力 | 当前证据 | 第一个实测 | 降级 |
| --- | --- | --- | --- |
| 发现／连接／断开／状态 | 未提供官方资料 | 官方示例能连接指定样机，断开及时返回 | 手机录音，不假显示设备在线 |
| start／stop／录音完成通知 | 未验证 | 开始、停止有真实设备状态；停止后文件可取回 | 无控制时仅导入已存在文件 |
| 录音列表／取回／增量同步 | 未验证 | 一段文件可恢复传输，校验大小与校验和 | 手动导入；失败保留设备原文件 |
| 格式／采样率／时间／长度 | 未验证 | 解码和时长一致，明确时钟来源及误差 | 服务端适配格式，不能伪造事件时间 |
| 实时音频流 | 未验证 | 官方 API 支持且延迟／丢包有结果 | 只做文件采集，不接 RTC |
| Marker／暂停／电量 | 未验证 | 分别记录 SDK 返回和硬件操作结果 | 能力为 unsupported，UI 不显示可用控制 |
| 锁屏／后台同步／设备唤醒 | 未验证 | 独立原生权限和持续运行试验 | 前台手动录音／启动通话 |

候选 DeviceCaptureAdapter 只描述 discover/connect/state/capabilities/start/stop/list/fetch/cancel；每个能力返回 supported/unsupported/unverified，且 supported 必须带官方资料和实际探测证据。provider 内部留 SDK 对象、设备凭据和重试；App 上传仍走相同 Episode Contract、Subject／Actor／采集许可与幂等键，不接厂商 LLM 或让手机持有现有模型密钥。

导入必须先创建稳定的设备文件映射，收到完整文件并验证校验和后再上传。一次文件同一 owner 重试只对应一个 Episode；无法取得稳定设备文件 ID 时先用内容校验和＋设备来源映射，不凭录制时间去重。owner／subject 不从设备上次使用者猜测。取回成功不自动删设备文件，删除／同步规则需另行确定。

| --- | --- | --- |
| HW01 | 官方示例连接并完成一次录音／取回 | 型号、固件、SDK、格式、长度、校验和；只保存脱敏结果 |

## 锁屏与唤醒的独立试验

下一提案先区分：已开始通话后的锁屏延续；前台唤醒词；已知设备按键唤醒；设备本地唤醒；手机后台常驻唤醒。它们是不同能力，不能用一项成功覆盖全部。

批准实验后，只用合成测试或知情本人数据，记录麦克风与后台权限、系统版本、10／30 分钟锁屏稳定性、路由、来电、中断、耗电和温升、误唤醒／漏唤醒次数；无测量不填目标达标。持续收音需要单独可见状态、随时关闭和明确留存规则；未知唤醒只提示用户确认，不提交问题或解锁敏感记忆。

实验顺序：本机前台唤醒 → 设备官方唤醒能力 → 后台音频试验 → 独立产品／接口批准。没有能力证据时保留屏幕／耳机可用的手动启动，不承诺全局系统唤醒词。Android 由其负责人独立验证，不从 iPhone 结果推断 Android 支持。
