# 持续采集与重点区间

2026-10-16 Product / Integration Owner 在本会话确认并明确要求「开始吧」：持续采集；一次标记开启重点、下一次关闭重点；两次标记之间的内容不得精简或因重复而吞并；其他记忆可归并；全部原音保留。机器逐字稿可以仅作处理中间材料。这是本次 iOS / Backend / AI Core 增量的直接授权，不启动 Android 或其他 Phase 4 能力。

## 实际设备边界

用户定义的最终交互为佩戴后自动录音、按键切换重点。已提供的 D3200 V1.3.01 公开 SDK 支持已开始录音后的实时 OPUS 获取、标记时间、暂停／恢复和完整文件同步；没有佩戴检测、从 idle 开录或改写实体按键手势的接口。应用在收到实际录音状态后订阅实时传输，不能把连接当作录音，不把恢复命令当作已支持自动开录。实体每次按键是否产生标记、固件的佩戴开录能力仍需真实设备或厂商证据。界面说明这一边界，并可提供同样语义的 App 重点开关。

## 增量 Contract

旧 Capture、会话、Android 形状不变。新增独立 `wearable-priority-v1.schema.json` 定义 WORK_3200 Capture 的可选 metadata 子集：

- `wearable_policy_version = wearable-priority-v1`。
- `priority_ranges_ms`：JSON 字符串形式的 `[start_ms,end_ms]` 数组，相对于本次上传片段。半开区间；重点跨切片时保留所有交集。
- `priority_timeline_complete`：字符串 `true` / `false`。时间线缺失或不能可靠映射时保守保护整段，不允许默默按普通内容精简。
- `transcript_retention = derived_only`：仅请求在成功整理后清理可安全移除的机器转写副本；不能以此丢失来源证据。服务端记录实际完成状态，不把仍为证据所需的原文宣称已经清除。
- 保留现有 `device_file_id`、内容校验、`device_part_index`、`source_start_ms` / `source_end_ms`，以回听原音并保持账号／人物隔离和幂等。

Backend 只接受范围正确的客户端重点提示，不接受客户端的本人匹配、审核结果或派生证据。已认证服务端通过真实 ASR 时间和文本匹配，将重点区间映射成字符范围；任何相交句子均完整保护，缺少可靠映射则保护整段。通过现有 AI 输入 `subject_context.wearable_capture` 传递 `policy_version`、`protected_spans: [{start,end}]` 与布尔 `priority_timeline_complete`，不修改旧客户端必填字段。

## 保存与整理

重点原话由程序按真实转写范围保存为独立、完整的 Memory / Evidence，LLM 摘要不替代这条记录。重复的独立重点区间仍分别保留。重点不赋予说话人身份：未知、亲友、重叠发言继续待核对，不训练本人模型。

普通条目可以在一次提取内合并完全相同、类型／来源／生效时间／上下文一致的内容，合并所有证据引用；保留变化与冲突。跨录音的不同原音和来源不做破坏性合并。相似内容可由 LLM 整理，但不以相似度自动删除历史来源。

全部原音保持原样。成功整理之前保留可重试的中间材料；成功之后可清除重复机器稿、ASR 诊断中的文本副本。仍被精确证据校验、声纹归属、修订和 Twin 引用依赖的 canonical 原文保留为内部证据，并如实记录 `evidence_required`，不能贸然清空使记忆失去来源。本次不批量改写或清除用户已有录音／逐字稿。

来源删除、用途撤回、声音模板失效、人物空间切换仍按现有规则使派生记忆与答案失效；重点不是绕过这些规则的例外。处理失败保留原音和真实失败状态。

## 验证

验证重点开关、奇数次标记到文件末尾、重复回调、跨五分钟切片、缺失／损坏标记、普通精确去重、重复重点保留、多人归属、撤权、删除和失败重试。模拟数据与构建通过不代表真实设备开录／按键语义、蓝牙后台长时间传输或锁屏体验已经验收。最终实际执行结果另记 verification 文档。
