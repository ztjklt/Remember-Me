# LiveKit Twin voice calls — approved iOS slice

Product / Integration Owner direction, 2026-10-13: “按你推荐的 LiveKit 方案，帮我接到现在的 iOS Twin 里，实现用我的声音实时对话和插话打断。” The owner subsequently selected Alibaba Cloud Model Studio CosyVoice. This authorizes this additive real-time call slice and supersedes the earlier local-only/live-conversation hold only for this scope. Provider choice remains an adapter setting.

## Behavior and sensitive boundaries

- Existing Actor login and owner Subject isolation remain authoritative. RECORDING, CLOUD_TWIN and VOICE are distinct, active grants. Each call additionally accepts the versioned real-time audio purpose notice: microphone audio goes to the configured ASR, saved Twin answer text goes to CosyVoice, and audio passes through the configured LiveKit transport.
- Enrollment uses a dedicated 5–15 second own-voice recording, reviewed reference text and explicit own-speaker confirmation. There is no automatic speaker identity claim. Ordinary recordings and call audio are not training data. Only a time-limited signed sample fetch is exposed for provider enrollment; storage stays private. Revocation ends calls, removes local samples and requests provider voice deletion. Failed provider deletion is recorded and retried by maintenance, never treated as successful deletion.
- Backend mints a short-lived, one-room microphone-only participant credential. No provider key, Actor token, voice ID or sample is included in room metadata. Agent dispatch metadata contains only an opaque call ID. Internal worker APIs require a separate service credential and recheck call lifetime, actor, Subject, profile and all grants.
- The worker replaces the generic LLM with the existing Backend Twin answer operation. It plays only a saved, current answer after existing provenance/source checks. The answer's ORIGINAL / SIMULATION / CONVERSATION / UNKNOWN label and answer ID remain visible in iOS. UNKNOWN is displayed without impersonated voice. No speculative unchecked LLM text is spoken.
- LiveKit supplies VAD-based automatic barge-in and clears interrupted playback. Cancellation closes the provider synthesis stream; old turn IDs cannot play into a newer turn. Manual interrupt, mute, hang up, backgrounding, failed connection and revoked authorization stop microphone transmission/playback. Sessions last at most 30 minutes.
- Real-time speech is accepted for automatic question submission only during the explicitly accepted call. It does not become Episode evidence or update the Person Model. Existing recording/transcript review remains unchanged. Multi-turn reasoning reuses the separately approved conversation API and its server-owned answer chain. Completed text answers remain context even if voice playback was interrupted; they are not evidence of the Subject or claims that the full audio was heard.

## Additive API / Contract v0.6

`GET /api/v1/subjects/{subject_id}/twin/voice/capabilities` advertises availability, policy, notices and profile state. `POST /twin/voice/profile` receives a separate VOICE consent, sample, reviewed text, own-speaker confirmation and policy. `POST /twin/voice/calls` receives the CLOUD_TWIN/VOICE references and matching policy; returns opaque call/room/participant identities, WSS LiveKit URL, short-lived join token and expiry. `DELETE /twin/voice/calls/{id}` ends only this actor's call. Internal listen/answer/speech/authorize routes are unavailable with client credentials. Public clients have no arbitrary-text TTS API.

CloudBase runs the API; LiveKit Cloud hosts the media server and Python agent worker (owner selected this route). A self-hosted VM remains an adapter-compatible alternative. Neither belongs in minute-triggered job functions. Production enabling requires actual WSS/TURN reachability and provider capability verification. Missing configuration fails closed and leaves text Twin usable. iOS installation remains deferred per the previously recorded owner preference; simulator and signed-build results are reported separately from real-device/own-voice evidence.
