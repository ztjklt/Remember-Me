# 游客暗号托付与 Twin 内设置

状态：2026-10-16 Product / Integration Owner 在本会话明确修订并要求「开始调整」。亲友就是游客，不要求接收者账号；只凭事先留下的具体私密暗号，进入对应亲友的专属记忆库。本批准替代 v0.12 的新建托付接收者账号要求，不扩大旧计划的权限，不启动自动身后判定或跨设备公开入口。

## 使用流程

本人从 Twin 的「留下数字托付」进入隔离的对话式设置：确认留给谁、输入或在本机录下暗号、核对识别文字、选择完整来源、预览全文和原音、确认私密细节及开放条件后保存。这个引导不把暗号发给普通问答、模型、Episode 抽取或音色训练。本机离线识别不可用时保留输入方式，不自动改用云端识别。临时录音和未保存的暗号在关闭时清除。

亲友进入已有游客模式，在 Twin 说出或输入完整暗号。服务端在普通问答之前核验；成功后只打开这份托付的来源，记忆花园、原音和后续问答共同使用该范围。对应亲友的称呼在本人设置时确定；知道暗号即可进入，不声称证明访客的生物学身份。一次只打开一份托付，10分钟后或主动锁上后退回公共范围。切换时清除旧范围的临时对话。

暗号应是双方共同经历中的具体细节。至少12个有效字符、足够不同字符、拒绝常见口令和泛泛偏好句只是最低筛查；本人还须明确确认它是非公开的私密细节，不能将字符数当成安全认证。包含具体经历的句子不因“我喜欢”开头就拒绝。允许 Unicode、空格和标点规范化；不通过关键词、LLM 相似度或猜测扩大可接受说法。自然说话中包含完整暗号也须在普通问答前识别和脱敏；同一句含多个不同暗号时拒绝，不合并多个范围。

新建托付及发布公共来源时，双向检查暗号与现有公开／其他托付来源是否交叉披露，覆盖原始转写、本人核对后的全文、补充、Memory 和 Evidence。含原音的来源必须具备非空原始转写；这些检查基于已存转写，不能保证机器转写没有漏听，也不能代替本人试听完整原音。暗号仍保存带盐的慢哈希；为检测句中完整暗号，另存使用独立服务端密钥生成的 HMAC 指纹、规范化长度和密钥标识，不保存明文或无密钥快速哈希。

## 接口

独立 `guest-entrustment-v1.schema.json` 定义新接口；既有账号托付和旧 Contract 保持兼容。

| 接口 | 规则 |
| --- | --- |
| `POST /api/v1/subjects/{id}/guest-entrustments/preview` | 本人；`episode_ids`；完整来源预览，返回 `source_version`、全文、原音标志及连带记忆 |
| `GET /api/v1/subjects/{id}/guest-entrustments` | 本人；仅返回计划元数据，无暗号或哈希 |
| `POST /api/v1/subjects/{id}/guest-entrustments` | 本人；`recipient_label`、`secret`、`private_detail_confirmed=true`、`episode_ids`、`source_version`、`handover_consent_id`、可选 `voice_consent_id`、`condition`；不接受接收者账号 |
| `POST /api/v1/guest-entrustments/{plan_id}/revoke` | 本人；撤销后终止已有解锁 |
| `POST /api/v1/guest-entrustments/{plan_id}/secret-index` | 本人；仅提交 `secret`，核验既有慢哈希后恢复检测索引，返回计划；不更换暗号、来源、许可、状态或期限 |
| `POST /api/v1/guest/questions`、`spoken-question` | 先核验暗号，命中时返回不含原句的控制答复；可选 `entrustment_attempt=true` 使用专用暗号输入，失败也不进入普通 Twin 问答或聊天 |
| `GET /api/v1/guest/session` | 增加可选 `scope_version` 与 `entrustment`（仅解锁后给出 `recipient_label`、`expires_at`） |
| `DELETE /api/v1/guest/entrustment` | 锁上当前专属记忆，清除临时前文并退回公共范围 |

`plan` 包含 `plan_id`、`subject_id`、`recipient_label`、`condition`、`status`、`episode_count`、`voice_allowed`、`revision`，增加可选 `secret_confirmation_required`，不返回指纹、密钥标识或长度。公开范围允许为空；只有托付时也能进入游客会话，但解锁前看不到专属内容或接收者列表。花园响应也可返回 `scope_version`，客户端不能把旧范围的晚到花园响应重新显示。

暗号控制答复采用既有 TwinAnswer 形状，`model_version=guest-entrustment-control`、`response_type=CONVERSATION`；`question` 只返回 `[暗号已核验]` 或 `[暗号未核验]`。语音响应的 `text` 使用同一脱敏文字。普通聊天的完整暗号自动匹配；不完整或说错的句子无法可靠地区别于普通提问，因此“说出暗号”专用动作显式携带 `entrustment_attempt`，确保失败内容也不会进入普通 Twin 问答。语音转写仍沿用已告知的临时 STT 适配器，不声称它不经过识别模型。

## 范围和生命周期

- `DIGITAL_HANDOVER`、云端处理和声音许可分别校验。本人音色还需已试听接受的可用档案；计划未开放声音时不能借用公共声音权限取得本人音色。
- 新计划使用独立持久化表和迁移。旧账号托付不自动变成只凭暗号的公开凭据；本人可查看、撤销并另行设置。
- 即时开放和原有 `after_verified_transition` 保留。未来条件仍由事先指定的照护人记录核验，暗号或 Twin 回答不能激活。冻结的本人模型不因游客交流更新。
- 授权依据包括本人许可、完整来源快照、计划状态及版本、激活条件、当前游客会话和解锁期限。范围切换、来源修改／删除、撤权、争议、过期及结束会话均清除临时前文。生成、音频读取与合成发布前重新核验同一范围版本，晚到结果不能转入另一范围。
- 服务端限制尝试频率，重建游客会话不重置设备的限流状态；失败答复不提示暗号、接收者或计划是否存在。
- 封锁期间所有候选输入均返回相同控制答复，不再匹配、计算慢哈希或调用普通模型；不能继续通过响应判断是否猜对。
- iOS 点击锁上即停止私库展示、录音、播放和提问，废弃在途结果；服务端确认已退回公共范围后才恢复使用。锁定失败时关闭本机游客会话。游客录音和音频播放互斥，包括权限等待及音频下载窗口。
- iOS 文字／语音提问及上锁请求携带调用起点的 `X-Guest-Scope-Version`；服务端拒绝旧范围的延迟请求，避免锁定已完成后旧暗号请求再次解锁。初次提问核验若改变范围，客户端不把旧请求改贴新版本发送。锁后状态查询不携带旧版本。未提供该可选请求头的旧调用方保留兼容行为，旧客户端需升级才能获得请求乱序保护。
- 游客文字和临时音频不成为本人记忆、训练样本或声音样本；暗号命中的输入和语音转写在返回客户端和临时对话前脱敏。游客凭据仍不能调用本人管理接口。

## 检测索引与旧数据

2026-10-16 本会话追加要求“修复这个问题”，批准上述保密和竞态修复所需的兼容字段、索引迁移与本人重新核验入口。迁移保留0030已有的计划、慢哈希及所有授权。旧慢哈希不能反推出检测指纹；旧计划或密钥轮换后的计划由本人在原托付卡片私下重新输入原暗号，逐份恢复索引。有效计划的索引不齐备时，候选暗号输入和来源开放停止，直到本人完成全部待核验计划。已撤销且缺索引的旧计划不阻塞其他计划恢复；撤销不再具有解锁能力。当前密钥的已撤销索引仍可脱敏，但失去索引的已撤销旧暗号无法自动识别，可能被当作普通聊天文字；请勿将退役暗号用于其他有效托付。

部署须通过 `REMEMBER_GUEST_ENTRUSTMENT_INDEX_KEY` 配置独立且稳定的高熵密钥（至少32字节），与数据库分开保存，所有进程一致、重启保持，勿复用供应商凭据。缺失或轮换密钥时不静默回退到不受保护的问答，也不自动生成临时密钥。部署前应备份密钥；遗失后只能由本人逐份重核验原暗号恢复。当前本机已在忽略提交的 `.env` 配置独立密钥；此记录不包含密钥值，不代表线上已配置或部署。

## 验收

1. 不提供接收者账号，仍能设置托付；弱暗号、未确认私密细节、过期预览或来源不合格时拒绝。
2. 只有托付而无公开来源时能进入游客，解锁前无专属内容；文字和语音完整暗号可打开正确记忆库。
3. 相近关键词和缺少关键细节不解锁；两个亲友的暗号分别对应独立范围，前文、花园、原音和声音不串用。
4. 完整暗号（含寒暄包裹）不出现在普通问答请求、Episode、TwinAnswer、训练或音色资料、客户端聊天历史中；数据库只保留慢哈希及带密钥检测元数据。
5. 撤销、过期、来源变化和范围切换时停止旧内容，生成／原音读取／合成中撤权拒绝晚到结果。
6. 未来计划在核验前不能打开；旧账号托付不被游客暗号解锁；重建会话不能绕过限流。
7. iOS 实际构建并验证会话内设置、全文／原音预览、游客命中后的状态与锁上操作。真实本人录制、自然说话和手机交接结果另记，不由替身或模拟器推断。
