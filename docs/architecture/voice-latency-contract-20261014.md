# 连续语音提速：兼容接口增量

基于已批准的连续语音方案。公网 `/api/v1`、WSS 事件、PCM 格式、APK 均不变；不新增迁移。

## 私有准备通道

API → 仅绑定回环的 AI Core 新增 `POST /twin/voice-stream`、`POST /persona/voice-stream`。输入沿用原协议且要求 `voice_response=true`。返回 `application/x-ndjson`：

- `draft`：完成确定性结构/引文校验但尚未完成语义审阅的文字，只能用于 API 内存中的声音准备，不是可发布答案。
- `final`：原有全部语义审阅完成后的结果；后端继续执行原有发布和来源校验。
- `error`：终止本轮，不能将此前 draft 转成成功或 UNKNOWN。

API 不转发 draft。首个完整句子的 TTS 可与审阅重叠，队列最多 8 × 16 KiB 加一个上游块；只有最终已审阅首句逐字相同才复用。不同则销毁并重新合成。没有最终结果不得向手机发送文字或声音。每次 TTS 外发前复核当前授权、来源版本和轮次；发送每块音频前仍按原规则检查。取消关闭准备请求和队列。

AI 生成、审阅及允许的修正共用一个请求内 HTTP 连接池，结束即关闭；不跨用户共享回答或资料。`AI_VOICE_CALL_TIMEOUT_SECONDS` 默认 8 秒，限制**每次**语音模型请求；最多调用次数和内容检查不变。它不是整个回答 8 秒完成的保证。非语音路径不受该设置影响，仍使用原超时。

## 数据与启动

同一问答请求可复用已展开的资料，但必须在 publication lock 内重查身份、可见集合及完整 source_basis；版本变更不复用。批量读取只减少相同资料的重复查询，不改变片段及来源。

通话开始时，对已经核对且当前允许用于云端问答的录音登记确定性原文片段，在同一短事务内计算并冻结会话依据版本。这里不提取新记忆、不调用模型、不使用临时 ASR。后续资料变化仍停止当前通话。

可选 `REMEMBER_EMBEDDING_WARMUP=true` 在 API 就绪前加载现有本地检索模型。这是文本检索向量模型，**不是本地语音转写**；声音识别仍使用 ECS 的 Paraformer。已下载模型配合 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`，避免首问检查外部模型站点。

本轮试验过临时 ASR 预准备，但 15 题没有命中且存在派生证据写入副作用；该方案已撤除，不随本轮发布。最终 ASR 到达后才启动问答。

## 回退与度量

应用按原受控流程回退至旧发布目录及配套配置；不回滚、清空数据库或原音。本轮 API 依赖新增私有 AI 路由，回退必须同时切换 API 和 AI。

记录 ASR 最终结果、资料准备、整答通过审阅、首块音频和手机播放确认。审阅时间包含资料准备，不重复相加。输入结束至服务器首 PCM 块不等于实体手机听见有效回答。固定问候、模型成功、模型失败、错误拒答分别报告。
