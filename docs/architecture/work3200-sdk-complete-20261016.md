授权：2026-10-16 产品所有者要求全面检查已交付 SDK、完成适配，并明确要求重点标记影响内容整理；常规步骤自主推进。本提案承接已批准的首页录音方案。Android 1.3.02 AAR 的实际 public 签名是编译依据，配套集成文档解释语义；示例和签名冲突时记录差异。

## 重点如何影响整理

设备通过实时片段 isMark、传输完成 markTimeStampList、onDecodeFileMarkers 返回重点。后两者是毫秒偏移。SDK 不提供 AI、转写或调整模型参数的能力，也未提供公开的写入设备重点接口。App 的标记作为 phone 来源保存在本机，与 device 来源分开。

1. 保留 ASR 供应商返回的句子开始、结束时间和原文，私有保存，不写入通用调用日志。旧录音/无时间轴的供应商继续可用。
2. 标记代表时刻，并不自带重点语句范围。本版本使用标记前 10 秒、后 5 秒作为查找窗口，取相交的完整句子。该窗口是本产品规则，不冒称 SDK 定义。
3. 只有供应商句子可唯一对应本人最终核对文字时才建立字符跨度。改写、重复语句或缺少时间轴不能精确对应时显示未对应；不按字符比例猜时间，不强行加权。
4. AI 收到完整文字和经过验证的重点跨度，优先覆盖这些内容且保留否定、条件、转述和反例。重点提高整理优先级，不提高事实置信度，不自动确认文字、不覆盖本人修订、不更改模型神经网络参数。
5. 服务端校验输出证据，再按证据与重点的交集添加可追溯的 importance 元数据并稳定排序。保留普通记忆及全文。本人可看到重点对应文本与处理状态。

兼容性：使用现有可选 AICoreInput.subject_context 内 recording_highlights v1；不改变冻结协议的必填字段。review/workbench 返回新增可忽略字段。上传端可提交时间点，服务端生成对应关系及处理报告，不能接受客户端伪造 ASR 时间轴/分析回执。

## SDK 覆盖策略

所有 public 业务方法、业务回调逐项列入能力台账。录音闭环留在首页；设备维护放在可展开区域。暂停/恢复只作用于已经开始的录音；开始/结束遵循设备实体按键。蓝牙/SPP 和 Wi-Fi 使用同一校验、保存、试听、上传入口。切页保持 identity-scoped 会话。

日志查询、日志下载、采集开关、时间同步、Find My 开关、删除单个设备文件、解除绑定、重置、组合 OTA 均需有真实适配和结果反馈。删除/解绑/重置/升级只在用户选择具体对象并确认后调用；不能因为审计要求而自动执行。固件升级必须由官方提供对应型号、版本、校验值及固件，不将未知 bin 当作升级材料。

边录边传是 SDK 音频传输能力，边录边出字幕需要额外的解码和流式 ASR；这两者验收分别记录。完整审计不能将 SDK 已提供、代码已接入、模拟测试已过和实物验收通过混为一谈。
