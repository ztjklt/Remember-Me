# 对话回溯与专属信

产品请求（2026-10-17）：用户要求在有对应原因的对话下显示入口，打开旁侧的信笺并播放原音；人物统一陈守义。这是新增跨模块实现的范围依据。

本人明确把一封已发布的账号专属信关联到若干可见证据。只有本次已核验回答实际引用这些证据，且当前账号是本人或该信指定收件人，服务端才返回 `recall_actions`。不会让模型读取私信、推断收件人，或凭关键词宣称存在某段原因。新入口不添加 LLM 请求。关联保存所选有效证据、所在录音的核对文字、音频校验值及讲述人的指纹；修改这些来源、删除记忆或来源不再可用时失效，需本人重新确认。新增无关录音不会撤销既有的关联。

2026-10-17 路线纸演示修订：原先用全空间 `source_basis` 保存关联，会让“先录一段新记忆、再切亲友对话”的正常流程导致全部信封入口消失。现在只缩小关联本身的失效范围；回答的完整来源版本检查、读者权限、当前信件状态和收件人检查保持原有规则。旧版本关联不会自动迁移为有效，须由本人再次确认。API 字段与数据库结构不变。

入口打开时重新验证回答、来源、信件发布状态、收件人及关联。原音按现有受限媒体接口读取；关闭、切后台、失去权限停止播放。公开答案与私信文字保持分开。账号专属信与联系方式验证码托付是两条不同的领取路径，后者的访客凭证不获得 Twin 权限。

信笺采用森林绿与暖纸色，展开正文自适应高度；播放器用实际音频时长，花瓣动效遵循减少动态效果。演示音频及人物材料标明虚构合成，不冒充真实人物原声。
