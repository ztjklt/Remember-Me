# 电话与文字共享聊天记忆

2026-10-14 Product / Integration Owner 在本任务直接要求：“我需要它自动带入上一通电话或旧文字聊天”。此请求批准实时 Voice 从仅限当前电话的历史检索，改为与文字 Twin 共用本人聊天记忆。它覆盖之前新电话不带入旧会话的限制；不改变独立 CLOUD_TWIN / VOICE 授权及通话用途确认。

启用现有聊天记忆时，新通话会自动检索同 Actor / Subject 的此前电话与文字原消息，使用带原消息编号的摘要辅助对话。近期逐字上下文仍限制在当前通话的最近 20 轮；更早的当前电话消息和跨会话消息由历史检索补充，单次最多 12 轮及 10,000 字符。检索会根据当前问题选取相关材料，不声称每次加载全部历史。

每通新电话仍有独立的服务端回答链，首轮没有上一通电话的 parent_answer_id。旧消息作为 recall 来源而非当前电话中已听到的音频。Worker 请求编号继续包含 call_id，避免不同电话重用 turn_id 时拿到旧回答。生成、摘要、发布和播放阶段继续检查当前电话、当前轮次、登录与授权；挂断或新轮次使晚到结果失效，未发布的结果不写入历史。

关闭现有聊天记忆开关时，电话与文字都不进行跨会话检索。清除操作删除派生索引和摘要，并设置历史时间界限；清除前的原聊天不重新索引，也不重新成为当前上下文。原消息和独立确认保存的 IOS_TEXT 证据依旧分别保留、由原入口删除。授权撤销、资料删除或修订继续过滤失效助理内容。

Actor 与 Subject 同时匹配才可进入检索；第三方、其他人物以及亲友会话不混入本人历史。本人消息、助理消息与摘要保持区分。电话识别文本和聊天摘要不自动成为 Episode、人物候选或 Voice Dataset；助理此前的话不能升级成本人人格事实。该改动复用 v0.7 的 recalled_answer_ids、recalled_turn_count 和 history_summary_status，无新增公共请求或响应字段、迁移、提供商配置。

验证使用隔离的 API / 数据库路径及可观察的假提供商：上一通电话、旧文字、当前通话超过 20 轮、关闭／清除、Actor / Subject 隔离、跨电话 turn_id 重用，以及挂断／新轮次发生在摘要或回答生成时的发布保护。测试不代表真人声音或人格质量测评。

本次实际执行：`cd services/backend && .venv/bin/python -m pytest -o addopts='' tests/test_realtime_voice.py tests/test_chat_memory.py tests/test_twin_conversation.py -q`，60 passed，2 项现有依赖弃用警告。完整结果保存在本地 `build/voice-shared-history-tests.log`；本提案记录代码与测试，部署结果由交付记录另行说明。

新电话首轮优先带入同 Actor / Subject 的最近一段会话末尾最多6条，然后以相关性补入其它旧聊天，仍受12条／10000字总预算。简单寒暄也能保留上一段语境；后续轮次按当前通话链接续。未保存的独立验证题不启用此入口。
