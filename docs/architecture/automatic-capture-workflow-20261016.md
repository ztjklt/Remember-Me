# 自动转写与累计分析 · 0.16.0

用户在 2026-10-16 的实机反馈确认录音、下载、解码已成功，并明确要求按以下流程直接实施；这是对旧版逐段同意上传流程的更新。

## 交互

新录音落盘后自动上传、转写，机器稿立即存入服务器，并缓存为本机草稿。用户可直接阅读、修改文字、填写补充；仅保留一次“保存到记忆”。原音和机器稿保持独立。保存后生成本段记忆，再自动排队对累计有效材料进行人物归纳。AI 观察保留引用、来源版本及待确认状态，不冒充本人确认的事实。

首页只显示录音入口、当前同步/转写状态、最新文字草稿与保存结果。电量、固件、容量、文件导出和连接日志留在设备管理。试听成为可选操作。手机录音与录音豆使用同一自动处理路径。

## 实现边界

- 新录音持久记录自动处理意图，串行上传并使用既有幂等键；旧档案不因升级而批量外发。失败保留原音，可重试；重启、返回前台继续未完成工作。账号/空间切换取消旧队列并隔离草稿。
- 草稿与人工保存分开。自动转写不是人工核对；编辑草稿在本机持久化，点击保存使用既有 transcript-review PATCH 原子确认。
- PATCH 可选增加 `cloud_analysis_consent_id`，校验本人空间及独立 CLOUD_TWIN 授权后，记录自动累计分析意图；旧客户端不受影响。新客户端“保存到记忆”覆盖文字整理及累计分析，不再要求第二个确认框。
- 本段 MODEL 阶段成功后，同一事务生成累计人物任务。已有排队任务合并新录音，运行中的任务允许一个后继任务，防止遗漏新材料。人物任务继续检查授权与材料版本，过期结果不发布；自动任务可有限重试，错误可见。
- 定时刷新采用非阻塞轻量录音状态刷新，避免每 8 秒全量串行请求并禁用整个界面。录音账本与草稿文件操作离开主线程。进度变化去重。
- 不承诺进程被系统强杀期间继续上传；持久任务在重新打开 App 后恢复。厂商连接、计时、Opus 下载/解码修复保持不变。

## 验证

自动排队/重启恢复/幂等重试/身份切换；草稿持久化与确认后退出草稿；累计任务合并、来源变化、撤销授权、失败恢复；Android 单元测试、构建、lint，模拟器完整 UI 和屏幕截图；服务器隔离测试与虚构账号端到端验证。模拟器画面注明模拟硬件事件，不作为实物验收。
