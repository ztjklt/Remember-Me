# 人物整理的来源预算与后续 RAG 接入边界

2026-10-12，本地 A01 实验。新增补记、留言、封存接口见 companion-contract-proposal.md。

## 本轮已经实现

人物候选生成复用现有权限和有效性解析器，解除的只是整个人物资料合计 24,000 字符这一处限制。按 Episode 汇集其全部有效证据；单批最多 24,000 字符、最多 12 批。重复 evidence ID 只有内容相同才去重。单段完整来源超过批次上限，或批次数超限，会在任何模型调用前明确失败，不切掉句尾、不截去否定条件。

每批的 model/prompt、引用和反例均校验，全部通过后一次性发布待核对候选。后一批失败不能留下前一批看起来已完成的候选。每次调用前和最终保存时复查资料、所有权与云端许可；模型网络调用期间不持有数据库写锁。超限问题没有改成无限上下文。

候选确认和封存是本地证据比对，不发送模型，因此使用无模型输入预算的解析方式；它们继续执行原来的来源/授权/版本校验。否则会出现“可以分批生成，却不能确认”的协议断层。

`AI_PROFILE_VERIFY_CANDIDATES` 是本地实验开关，默认关闭。本轮运行启用它：生成后再检查归属、支持、限定和遗漏的情境，结构不合格整批失败，不合格候选不入审核队列。另加一个保守的字面规则：候选声称他人被错怪、冤枉、误诊或撒谎，而其引用没有该表述时，拒绝这项候选。这只是特定高风险断言的拦截，不等于通用语义校验。

真实 A01 仍出现模型审阅漏掉“错怪”，由技术复核拒绝并补规则。通过模型审阅不等于本人认可；未核对、冲突和失效的候选仍不能作为确定人物理解。没有提高稳定人格或相似度评分。

## 仍未解决的规模问题

- 当前批处理是按完整录音分组，不是完整的跨批全局归纳。位于不同批次的支持、例外与变化仍需现有关系建议和本人核对；不能说已经自动找全。
- 相同转写文本去重不能证明两次讲述是独立事件。`independent_episodes` 的历史字段只作旧协议兼容，不能解释为独立印证次数。界面使用“多段来源的观察”。后续应以已确认的事件关联判断复述。
- 新录音尚未实现只更新受影响的所有故事/人物节点的完整增量调度。全量刷新只适合本轮小样。
- 问答仍采用现有有效全文路径和原有预算；本轮没有冒称已将 Twin 改成新 RAG。

## 队友 RAG 后端的预留合同

尚未收到端点、鉴权、模型或协议，当前没有外部调用和整库上传。建议先在测试接口对齐以下信息，再实现适配器：

1. 输入：query、当前 subject、服务端计算的可见有效 evidence ID、每项版本指纹、最大条数/字符预算。身份与授权来自勿忘我后端，不接受客户端传来的 reader/owner 声明。
2. 输出：命中的 evidence ID、检索分数、检索器版本、可选命中位置。命中位置必须在本地来源中校验；不能把对方返回的改写当原文。
3. 本地再次按当前权限重取文本；返回了未授权、已删除、过期或不存在的 ID 就丢弃。不能信任检索服务承担最终权限裁决。
4. 补齐同一故事的必要上下文、纠正与反例后再计算预算。预算不足要明确说明，不能悄悄截掉限定。
5. 模型返回前继续复核资料/权限版本；资料变化返回 SOURCE_CHANGED。没有命中可以诚实未知，检索不可用不能伪装成“本人没有留下”。
6. 对方若需要托管向量库，先对齐更新、撤权、删除传播和日志保留。补记、草稿、未审核候选不自动进入本人索引。

对比验收至少分为：小材料有效全文、当前本地检索、新 RAG 三路；同一模型、同一权限、同一资料版本。分别记录关键证据召回、限定/反例遗漏、回答事实、成本和延迟。暂不凭空填检索效果数字。
