# 人物理解材料版本与权限检查分离

2026-10-11；兼容修正，不新增路由、枚举或数据库迁移。

## 问题

原 `source_basis(include_profiles=False)` 仍包含 Consent 和 StoryGrant。Android 每次明确同意云端问答后新增授权记录，即使来源文字未改变，也会使已确认人物候选变为 stale。

## 规则

1. 人物候选的 `source_version` 是不透明的**材料依据版本**，采用 `profile-material-v2` 域标记。包含 Subject、Episode、MemoryItem、Evidence、PersonTrait、GraphFact、ModelRevision、MemoryRevision；不包含授权记录和派生候选自身。
2. 新增／撤回云端同意、故事授权，不自动删除本人已核对的本地人物理解。读取、生成、播放分别执行当前权限检查；撤回云端同意仍禁止后续模型调用。
3. 模型任务另行保存完整 `source_basis`，包含权限及人物状态。在模型返回后的短事务内重新检查所有者、云端同意与完整版本，再发布。期间不持数据库写锁；变化后失败，不自动重复调用模型。
4. 来源内容、删除、修订变化仍使原候选保守失效。本轮没有完成按单条候选依赖做局部失效优化。
5. 旧版候选不自动重算 hash，不自动恢复确认。保留旧状态及来源；重新归纳后走正常核对接口。真实用户仍须自行审核，虚构样例的技术复核不等于真人认可。
6. 亲友仍只读取获授权的故事、情境观察等内容；本修正不将所有者私人候选下发给亲友，也不增加任何故事授权。

## 兼容与回退

JSON 字段及状态枚举不变，现有 APK 可直接受益。资料整体版本与候选材料版本不再可混用或自行解释。没有更换问答协议、模型供应商、提示词或数据库结构。

应用回退到旧版后，新版候选也会保守显示为失效，不会被错当作已确认理解。恢复服务程序不覆盖数据库、原音或审核历史。

## 验证

见 [修复与实跑记录](../agent-loop/PROFILE_VALIDITY_FIX_2026-10-11.md)。测试包含新授权、撤权、来源编辑／删除、旧 hash 失效，以及模型调用中人物审核状态变化；真实调用与模型双桩测试分开报告。
