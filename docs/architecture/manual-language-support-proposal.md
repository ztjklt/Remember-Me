# 手动用词与录音补充：兼容性提案

2026-10-08 用户明确要求提供手动输入生僻字、方言与设定，并授权完成 Agent、移动端与交付。此提案记录本轮跨模块行为，不改变现有模型供应商或共享回答枚举。

- 新增 Owner 私有 `GET/PUT /api/v1/workbench/subjects/{subject_id}/vocabulary`，载荷 `{text: string}`，最多3000字符。词汇表不是记忆，不自动送模型、不自动共享、不自动批量替换人名。
- `PATCH /api/v1/episodes/{id}/transcript-review` 兼容增加可选 `supplement`（默认空，最多3000字符）。用户在核对时选择加入本次说明；提交后与文字一起不可变。重复提交必须正文、说明都一致。
- 原始ASR、核对文字、补充说明独立保存。补充不拼入 transcript，模型转写从未收到创作稿。补充在处理阶段以手工记忆入库，`model_version=owner-input`、`metadata.origin=owner_supplement`，使用现有 `CALIBRATION` 人工澄清来源和 `owner-supplement:` 引用；没有音频逐字偏移。不得生成 ORIGINAL 或把说明标成录音原话。
- 补充只在故事首次核对、首次授权前写入；已处理故事通过现有修订机制更正，不允许偷偷改已共享说明。整段故事授权页明确包含原音、核对文字和本人补充。词汇表本身不随故事分享。
- 本人补充的存在不会使原音失效；删除或纠正它仍按既有失效与撤权规则处理，不能从元数据复活已删除文字。未授权故事的说明不进入读者模型输入。
- 新增 `0012_subject_vocabulary`，只建独立词汇表，不改旧录音。先在SQLite副本升级再迁移运行库。
- Android与网页均提供“我的用词”与“本次补充说明”；iOS旧请求不带该字段仍可用，新UI另行接入。共享AI输入与输出Schema保持不变。

验收包括：词汇表跨身份不可读；保存词汇表不会发模型请求；补充与原始ASR分离；幂等确认；实际问答使用明确说明且来源为本人补充；Reader只能在故事授权后读取；删改/撤权令旧回答失效；页面清楚标识补充不在原音中。
