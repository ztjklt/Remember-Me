## 交付契约

普通账号登录 → 原音保存 → Paraformer → 核对/书面补充 → 微信 Deepseek-v4-flash 整理 → 故事/人物候选 → 邀请领取 → 本人批准 → 亲友听原音/来源问答 → 补问/补录/主动重新分享 → 撤权。

现有 StoryGrant 是唯一阅读权限来源。新增邀请只协调身份及本人确认；24 小时过期，数据库只留随机邀请码哈希。创建与批准均核对完整录音范围/资料版本；一批原子批准，重放不重复授权。云端问答权限独立确认。撤销邀请分享只能撤销该批新建 grant，不影响此前独立授权。读者领取时不返回私密故事。

兼容新增 /api/v1/service-info；/api/v1/workbench/subjects/{subject}/sharing/preview、invitations、recipients；/api/v1/workbench/invitations/claim；邀请 action 端点。旧路由、TwinOutput 及六类记忆枚举不变。

## 实现与复核范围

- 账号：只由管理员 CLI 创建新空间，不自动认领旧空间；重置撤销设备令牌和配对码，并使正在验证旧密码的登录失败。
- 分享：完整录音授权，故事展开全部来源；领取不建立权限；批准短事务复核来源版本，批次原子；既有独立授权不被邀请撤权误伤；云端问答单独选择。
- 手机：注册关闭时隐藏注册；自然视觉沿用；无需输入 actor_id；刷新/退出/切换移除旧访问和播放。内测 APK 独立包名 `.internal`，不覆盖开发包中的本机原音。
- 数据：0016 仅追加，不导入旧同学编号； PostgreSQL 测试库和恢复库均独立于 remember_me。配置备份只留服务器受限目录。
- 验收：最终必须记录真实模型逐题语义、网络路径、APK 哈希、迁移及真机状态；53 个返回不能被计为达到 54 问门槛。设备不存在或质量未过必须保留未通过状态。

Review Focus: 邀请领取/批准并发、重复批准和部分授权失败、来源在预览后变化、独立旧授权撤销边界、云端使用限制、账号重置期间登录、退出后迟到数据/播放、内部模型修正是否越过原有证据校验、部署是否误用生产数据作为测试写入、签名和 IP TLS 是否真正验证。

### 事实问答策略的实际取舍

v5、v6 各完整 60 问，均 58 个响应、2 个错误；**都未验收**。v5 把“不是说在某职业工作”改成“没在该职业工作”；v6 把同事父亲的工作扩展成同事的工作。重复增加语言要求与模型审阅仍有漏检，不能再以 HTTP 成功率衡量质量。

v7 的逐字摘录探索中，模型重抄 ASR 文本会改字或标点，正确被本地校验拒绝。该探索中途停止，保留已完成结果，不能计作完整 60 问。

v8 内测事实问答采用 **模型选来源编号 → 程序复制有效原文 → 模型检查相关性/覆盖/归属 → 服务端再校验来源与权限版本**。模型不能自由改写事实句。单条完整本人原文为 ORIGINAL；多条材料与书面补充组合为 SIMULATION，明确标注核对文字/本人书面说明；没有答案为 UNKNOWN。人物理解仍由独立候选任务生成并由本人确认，不使用此模式冒称已完成自由人格表达。风格化回答仍关闭。

该取舍保留多要点、跨录音、来源与未知边界，降低事实重写风险，但回答可能较长且保留 ASR 错字；这是本次内测的具体限制。编号存在与原文逐字相符仅证明引用真实性，不证明选段完整或历史事实真实，所以仍必须完整复跑 60 问并逐条复核。v8 未过门槛不切换 ECS。
