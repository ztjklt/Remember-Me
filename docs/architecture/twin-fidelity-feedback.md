# Twin 相似度的反馈与验证

2026-10-13，Product / iOS Owner 要求确保 Twin 越来越像用户。本次在已授权的 calibration v0.4 和本人审核流程中补齐入口与表达消费；没有新增 API 字段、同意范围、数据库结构或训练服务。持续进步要用本人评审和新问题验证，不能由录音量、聊天量或模型自评分推出。

## 本次接通

- 简化 iOS 对话页显示通过核对的措辞结果，限有效 SIMULATION / available；原话不改写，过期、拒绝、缺失或空结果回到内容依据。明确标注措辞参考已确认范例、回答仍是推测。
- 有证据的有效答案可以锁定，再录本人真正的回答、核对转写、等待记忆处理，再比较决策、理由、价值优先、情绪反应和表达。录音复用原流程；个人声音克隆仍未上线。
- 校准锁定的是用户看到的措辞。之前只锁 answer，漏掉 expression；现在保存有效表达文本及其模型版本，原话和失败表达保持旧行为。已锁定内容不会被后来的措辞变化覆盖。
- 对话页直接进入人物与表达核对，比较完成后可进入既有候选流程。校准差异只作诊断；本人录音是证据，模型比较或 Twin 自己说的话不能自动确认成性格。确认表达范例后还需本人显式启用表达参考。

## 怎样判断是否更像

1. 先保存同一组问题的旧版本回答、有效材料版本、模型/提示词版本及出处。
2. 用户讲出真实回答与理由，核对文字；候选中的情境和例外仍由本人确认。未确认推测不作为确定人格使用。
3. 更新后再问未用于反馈的新问题，包括普通情境、条件变化和反例。不能拿刚刚听到的答案复述成功当作预测能力增长。
4. 本人逐题分别判断记忆是否正确、选择/理由是否像自己、措辞是否自然；可以标相近、部分相近、不像或材料不足。表达比较应保持事实内容一致，遮掉新旧版本标签。
5. 保留旧版本有效问题做回归；新增有效资料导致合理变化要注明。无来源编造、错误人物、忽略条件或越权访问不能被更多“相近”票抵消。低于旧版本的结果应保留问题并修正，不能报告自动单调增长。

单次校准没有总体“人格还原率”；NOT_OBSERVED 不计作正确或错误。自动 schema / 引用核对仅验证程序边界，LLM 语义审核也可能漏错。真实用户的未见问题评审尚未进行，本轮不能给出用户级相似度提升结论。

## 保留的限制

当前人物候选仍按整体材料版本保守失效；新录音可能使旧确认理解需要复核。原文、历史审核和真实变化保留，系统不会自动恢复旧确认或替用户接受新理解。按单项来源局部失效、长期盲测趋势、自动晋级/回退尚未实现，不能声称它们已上线。参见 profile-material-version-proposal.md。
