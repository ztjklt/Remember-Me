# 记忆花园：自动展示故事与事件

2026-10-16。Product Owner 在本聊天明确修订：花园以整理后的故事／事件为主，不展示所有记忆；「AI 做出事件后直接展示，然后主用户模式下用户觉得不合适可以直接删掉」，随后要求开始实施。

## 本次行为

本人随后明确要求把图谱和时间线合成一页，事件沿时间线排列，右侧复用已有素材图；点击查看详情和相关原音，提供手动修改与删除。删除范围已明确为「删除事件及整理内容，保留原音」。


- 已有记忆提取产生的 `EVENT` 自动成为事件卡片。没有字数、录音时长或记忆数量门槛；不能为了凑故事补写人物、时间、地点或情节。
- 已有 narrative 中来源有效的 `story` 在主用户花园直接展示，包括 `pending`，无需先确认。系统整理标明 AI 整理，已确认记录保留本人核对标记；展示不把服务端 pending 改成 confirmed。
- 一条 EVENT 对应一张卡片。同段录音中的不同事件不自动合并，只有共享具体证据的资料才关联；已有 story 优先展示，避免相同证据重复出花。
- 偏好、人物名字、关系和其他零碎记忆继续保存在底层，不单独生成花园卡片；它们可作为有证据关联的故事详情／图谱分支。
- 主用户可在故事详情或长按菜单删除。narrative 故事复用现有 revision 校验的 reject；EVENT 复用已有 Memory 删除。两者都保留原始 Episode 录音和原文，删除事件可能使相关理解与旧回答失效。
- 已拒绝故事的 evidence_ids 阻止相同 EVENT 作为回退卡片重新出现。读取过程中／读取失败时不绕过故事状态展示 EVENT；明确不支持 narrative 的旧服务（404）可展示 EVENT。
- 原有本机移出／恢复仍是单独的展示选项，并兼容之前保存的 episode 隐藏编号；EVENT 后来整理成 story 时继承本机隐藏选择。
- 首页不再分开时间线／图谱两个模式。时间线中每个事件带有证据关联的人物／事件分支，右侧从已有十种素材图中稳定选图，保留原图比例，大字号仍保留右侧插图。时间明确标注为录入时间，不把模糊人生阶段解析成虚构日期。
- 点击事件打开详情，直接列出相关来源原音；不必先进入另一层记忆详情才能播放。
- 手动编辑标题和正文。既有故事按 revision 校验后更新；EVENT 的展示编辑通过已有接口新建有相同证据的 story，不改写原始 Memory、Episode 或转写。修改仍保持 pending，不自动确认人格／表达。保存后主动刷新花园。编辑和删除都保留用户打开时的来源／版本上下文，拒绝过期或跨空间操作。

## 范围

本次为 iOS 既有接口上的展示与操作修订，不增加 API、schema、迁移或 AI 生成任务，不自动 confirm 人物模型、表达范例或同一事件归组。常规录音处理已有 EVENT 提取会自动进入花园；更长 narrative 故事仍由现有整理任务产生。

游客继续使用独立、本人明确开放的完整来源接口，只有只读权限。本人的自动故事展示不会自动开放来源；删除故事卡片也不冒充撤销此前开放的整段录音。整段来源删除及开放范围管理仍通过各自现有入口执行。
