# 旧聊天摘要与检索（iOS-first）

2026-10-13 Product / Integration Owner 在本任务直接要求：“把旧聊天的长期记忆也接上，让它能总结和检索以前聊过的内容，不要只记最近20轮，越来越了解我”。本提案记录该请求批准的实现，基于包含实时 Voice 的 e6a1c6b，不替换现有提供商。

近期20轮仍用于逐字上下文；新增同 Actor / Subject 的跨会话历史语义检索及有来源的摘要缓存。只对本人所有者的 conversation_mode 启用，继续要求有效 CLOUD_TWIN。旧单轮请求及亲友请求保持原行为。原始本人消息与助理消息分开；失效助理内容不进入检索、摘要或回答。过去的问句、假设和助理建议不能变成本人人格事实。摘要只是导航，回答及复核仍看到检索到的原始消息。

新增可关闭及清除的聊天记忆设置。清除设置时间界限并删除派生索引与摘要，旧聊天不会重新索引；独立确认保存的 IOS_TEXT 记忆仍沿用既有删除入口。摘要与索引不进入人物候选、Voice Dataset 或校准；本人自述可帮助自然对话了解偏好，持久人格判断继续走本人审核。

摘要按检索到的原消息生成并缓存，使用既有主模型及 schema worker。摘要失败时使用原消息检索，显式记录不可用状态；不把失败计为摘要成功。库中历史不受20轮限制；单次检索材料有预算，不声称模型同时读取全部历史或无限精确记忆。

v0.7 为响应增添旧聊天来源与记忆状态，新增本人聊天记忆读取、开关、清除接口；旧请求不增加必填字段。内部 Twin 输入加入独立 recall/summary 字段。迁移0020接续0019实时声音，不重置既有数据。后台部署针对独立 iOS CloudBase，保留当前 RTC 参数，Android ECS 不改。
