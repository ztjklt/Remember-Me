# Android 0.8.2：花田浏览与记忆阅读打磨

## 这次解决什么

继续采用 PR #85 已认可的蓝花、枝叶与自然背景。0.8.1 恢复了素材，0.8.2 补齐浏览和阅读中的具体问题，不重新发明花形，也不把原型里的固定故事或厨房意境图放进真实账号。

| 原来的表现 | 本版处理 |
|---|---|
| 同一朵花放大后，返回再进入变成100% | 按当前身份、空间、故事和本组记忆保存相机位置；返回及切换标签可保留；撤权后清除对应故事状态 |
| 单指划过未放大的花，页面不易上下滚动 | 100%时单指交给页面，双指缩放；放大后单指拖动花朵，仍可归位 |
| 背景只能盲点轮换 | 花田及设置使用原素材缩略图选择：草地、湖畔、林间、海边、月下、花径；保留按页面自动选择 |
| 记忆正文、模型归纳、引用同一层次 | 明示来源类型，区分记忆正文和完整核对依据；保留书面补充说明，不虚构时间对齐 |
| 多段来源的播放按钮堆满页底 | 固定一个播放器，通过来源选择切换；长文和所有依据滚动阅读，返回入口保持可用 |
| 播放后花田被大播放器挤占 | 花田使用紧凑播放器，仍有真实播放/暂停、定位及停止；详细阅读页保留完整操作 |
| 深色花田上的系统栏使用黑图标 | 随花田及应用明暗调整系统栏图标对比度 |

背景是装饰，不是历史照片，也不代表改变了故事事实。“花径”复用0.8.1已经打包但未开放入口的原始素材。本次没有增加图像生成服务。

## 验证边界

缩放状态问题先在0.8.1安装包复现：测试期望返回后125%，实际100%。修正后以同一断言检验，没有删除失败条件。

新增双指测试还发现连续事件可能在重绘前用旧相机覆盖缩放、以及花瓣点击竞争手势的问题。实现改为在一次手势内累计相机状态，超过触控阈值才接管；保留正常点击与100%时的页面滚动。该项曾失败，修复后使用同一双指操作通过，并未以按钮缩放代替。

真实操作检查使用专用虚构账号和已经完成真实处理的原音、记忆，App通过IP HTTPS直连ECS。这里只修改客户端；不更新后端、不迁移数据库、不改变模型及权限规则。专用测试授权在撤权检验后恢复。没有新发起ASR、LLM提取或人物质量评测。

八段来源加200%字体另使用显式布局测试资料，不写入服务器，不调用模型，不作为八段真实音频通过的证据。截图与真实ECS流程分开标注。

最终APK、校验值及本轮测试结果见本目录配套交付清单。原0.8.0、0.8.1包及截图保留。

## 仍未完成

- 网页完整连续镜头、逐瓣形变没有全部移植；现有过渡沿用可关闭的原生淡入淡出。
- 按真实故事生成意境图、iOS花田移植及新版实体手机验收仍未完成。
- 多来源真音频、完整TalkBack和不同厂商机型还需进一步验收。现有多来源布局测试不能代替这些项目。
- 人物理解与问答质量不属于本次视觉验证；本版不新增“人格准确度”或模拟好结果。

安装升级应覆盖同签名版本，保留本机原音；不要为更新卸载。
