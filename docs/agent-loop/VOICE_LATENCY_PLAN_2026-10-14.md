# 连续语音延迟优化

基线：`21e960e`，ECS 应用 `1e4a8ea`。用户要求尽可能把有效语音回复压到约两秒；目标不是已完成的保证。

## 约束

保留微信 DeepSeek、Paraformer、小米普通 TTS，完整语义审阅、来源/权限复核与轮次取消。不得播放未审阅文字，不用问候或占位语计为模型回答。旧录音和失败结果保留。不修改饮食项目。

## 实施与验证

1. 在 ECS 隔离副本分解检索、生成、审阅、TTS 耗时，固定原有问题和输入音频。
2. 根据剖析优化重复资料准备、冷启动及连接成本。先写行为回归，再改实现。
3. 使已经完成的独立工作重叠；如果准备提前进行，仅缓存候选，最终问题、权限、来源或答案变化时丢弃。审核未通过时禁止输出音频。
4. 分别统计新问题、重复问题、追问、UNKNOWN、人物模拟、失败、打断，不把缓存或固定话术混入新问题成绩。
5. 检查改动后在隔离 ECS 实跑同批材料，再决定是否升级当前服务。Android 协议兼容；真实手机起播/回声无设备则不声称验收。
