# 连续语音与会议要求对照

需求依据：队长《Remember Me 产品功能完善文档》，2026-10-13；用户批准的本轮实施计划。文档原件不改动。实现使用单 API 进程会话，不另建人物事实库。

| 要求 | 本轮实现位置／处理方式 | 验收边界 |
|---|---|---|
| 持续收音、自动接话 | Android AudioRecord → 认证 WSS → Paraformer realtime → 逐轮 Twin → 小米 PCM 流 → AudioTrack | 供应商实跑、模拟器和实体手机分别记录 |
| 插话打断 | 本地声音检测先停声，再取消旧轮次；ASR 临时结果兜底；音频与播放确认均带轮次 | 自动协议打断不是人耳测得的打断延迟 |
| 连续追问 | 只传已播完的完整句，未播完标记中断；历史只作指代线索 | 引文及人物事实仍须来自当前获授权材料 |
| 低延迟 | 本轮检索、短回答提示、完整审阅后分句合成；记录各阶段 | 保留模型审阅，不能承诺一至两秒；固定问候单列，不当作有效记忆回答速度 |
| 人物完善与语音校准 | 新增先锁答案的语音校准入口；已有录音、核对、比较；完成后流式播报比较说明 | 未核对前，盲测答案读接口及声音接口都不可用；原普通校准兼容 |
| 多人共同回忆、亲友观察 | 复用现有署名贡献、人工审核与授权；补记选择带上已确认故事关联的完整视角 | 本轮没有新增二至三人同场说话分离，也没有外部声纹服务 |
| 声纹注册与识别 | 保留独立适配边界 | 尚未实现；不得充当访问凭据 |
| 密语与专属实时对话 | 现有指定账号留言继续可用 | 本轮未新增密语解锁；不能把留言播放称为专属实时对话 |
| 身后托付 | 需独立确定执行人、可靠确认、撤销机制 | 未实现自动触发；不会用未登录天数开放资料 |
| 记忆花园、局部保护 | 沿用真实故事、授权和来源页面 | 本轮没有新增局部密码；现有权限在通话、检索、音频中继续复核 |
| 快速删除 | 保留已有修订和删除接口 | 花园移出与底层删除的完整新交互仍待单独实现 |
| 录音豆 SDK | 保留手机录音与硬件适配边界 | 无实体设备；没有声称 SDK 支持远程唤醒或持续音频输入 |
| 通用耳机、唤醒 | 声音设备变更／音频焦点丢失暂停；手动恢复 | 无实体耳机验收；没有后台唤醒词监听 |
| 宣传片 | 可使用本轮真实实跑素材 | 不展示未实现的多人声纹、托付或自然实时性能 |

## 数据和判决规则

1. 语音会话不自动建 Episode、Memory 或人物理解。本人需要留下新经历时，使用原来的“讲一段 → 核对 → 整理”；亲友使用署名补记。本轮尚无“从通话中截取一段直接保存”的入口。
2. 每轮先过滤身份、故事授权及云端使用许可，再检索完整材料及关联纠正、条件和反例。每个输出块发送前复核资料版本；资料变化则停止，不能偷偷重问模型。
3. 补记总量与模型预算分开。小批量全部传递；超过预算时按已审核故事关系扩展检索结果。未关联的补记、尚有分歧的补记保守保留，超限明确请求具体问题。大量未关联材料的自动语义分组仍未解决，不能宣称长期规模问题已全部解决。
4. 人物模拟仍使用本人确认且当前读者可见的理解和表达范例。按原话模式进入通话时，回答偏原话检索；选择分身模式需要既有开关与有效人物资料。
5. 评测分开记录接口成功、事实／归属／条件、来源支持、未知边界和声音结果。合理改写不因字面不同判错；人工没有听过的音频不写成人工听读通过。
6. “你好”“谢谢”等严格匹配的社交控制使用固定服务提示，不调用或冒称 DeepSeek 人格回答。带人物事实的新问题不进入此捷径。

## 确定性审查修复

独立代码审查发现六项问题，均落实修复：补记反例丢失、后台迟到启动、播放确认跨轮错配、重复 WSS 连接、取消与请求登记竞态、语音盲测答案旁路泄漏。针对性测试及全套 PostgreSQL 结果见本轮实施记录。实际声学回声、慢速说话、耳机、来电仍须实体设备。
