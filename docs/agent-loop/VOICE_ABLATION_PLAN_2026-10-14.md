# 语音 A/B/C 与录音豆声纹核查

用户已同意：A 保留审阅；B 同资料同模型取消阻塞式模型审阅；C 在 B 上试验尽早合成首句。本轮是隔离能力实验，不改正式服务、公开注册、APK 或分享规则，不推送 GitHub。

基线 `34c8092`。复用已获授权的虚构陈守义资料和真实音频，原 ASR 与金标准不混用。实验工具只接收后端按身份/有效性筛出的资料；不改正式 QuotedTwin 默认行为，也不以伪造“审阅通过”实现 B。

## 实施

1. 阅读 Android 1.3.02 / iOS 1.3.01 SDK 的公开接口、文档；核实声纹注册、比对、分离是否存在，以及音频输入边界。
2. 用现有微信凭据实测 SSE，记录首 token、完整输出、实际返回模型、usage、失败。密钥只读取服务器配置。
3. 编写隔离 runner：A 调用现有选择与审阅；B 只调用同一选择提示词并执行现有确定性来源校验；C 流式接收同一结构化选择，在完整首个要点可验证时开始原文语音合成，继续验证最终结果。相同提示词避免把换提示产生的差异误归因于流式传输。
4. 对真实材料按轮换顺序对照；保留失败和模型输出，人工按原始资料复核，模型自评不是金标准。若 C 的短 JSON 基本一次返回，明确记录收益不足；另行评估自然语言首句流式，不混成同一对照组。
5. 记录测量起点：模型阶段实验不冒称停说到手机起播，不把旧 ASR 耗时加到本次模型时间伪造整链路结果。声音仅保存在私有实验目录，线上审核不变。

## 最小验证

SSE 分帧/UTF-8、结束与截断、错误、未知引用；仅完整有效要点触发合成；最终失败须保留 partial_failed 状态，不因已经有声音标成功。取消任务需停止后续 TTS。SDK 无设备只报告静态能力与接入方案，不假称声纹准确率或真机解码通过。

Ruling: 先做模型及 TTS 关键路径隔离对照，因为目前没有批准更换供应商，且需要先验证微信 SSE。它不证明 Android 已实现完整 LLM 逐句播放；成本是还需后续手机接入验收。
