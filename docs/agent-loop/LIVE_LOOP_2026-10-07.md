## 2. 独立录音状态循环

为避免破坏月度基准，另建虚构许川 Owner/Reader 与7段短音频（initial/private/supplement/correction/change/answer/calibration）。每段经实际TTS、STT和云端提取路径；没有直接写入业务事实表。

- 补充：新录音关联旧记忆，确认后可回答邻居关系。
- 纠正：2010年改为2012年，旧答案过期；私人纠正未分享时Reader得到UNKNOWN，受影响的旧故事音频不可访问。
- 变化：2019年从苏州搬到杭州，当前地点可回答杭州，历史材料仍保留。
- 私密：另存私密故事，Reader看不到正文、原音，私密问题UNKNOWN。
- 补问：Reader提交问题，Owner录音回答并关联；未授权前回答录音ID不暴露，主动授权后可用于Reader问答。
- 校准：先锁定Twin答案，再生成并提交校准回答音频，实际微信模型返回5维差异报告；之后的事实变更可使旧校准变陈旧，属预期。
- 引导：读取真实问题列表，完成稍后/恢复操作。
- 删除：通过API删除一条未共享的测试记忆，列表即时移除。私密短故事此次提取为空，删除动作因此使用另一条未共享的校准记忆。
- 重复：完成3轮“修改→旧答案过期→重新问答”和“授权→Reader问答→撤权→原音/新问答拒绝”。

最后额外做了真实云模型并发检查：修改、删除、撤权各3轮。请求仍在处理中时执行变更，9次均HTTP409 / SOURCE_CHANGED。不是用受控fixture代替的结果。额外删除仅发生在独立技术测试空间，因此该空间最后状态不再保留全部早期演示内容；完整顺序证据在report.json中。

## 3. 本次修复的实际阻塞

1. 模型改写了正确证据却标成ORIGINAL，原先导致问答校验失败。现在模型只选择一个有效SUBJECT证据，程序逐字返回原文；不存在的引用、推断来源、多来源或超过200字符仍拒绝。
2. 人物候选缺少明确JSON结构、长来源ID容易写错。加入完整schema和短编号映射，所有返回编号仍严格核验；不猜测修复不存在的引用。提示版本profile-proposals-evidence-v2。
3. 后台任务占用唯一模型槽时，前台问答立即503。问答/校准改为最多等待15秒，之后仍明确失败；模型调用仍串行，不自动重调。
4. 确认后的短录音返回空记忆无法再整理。增加Owner明确触发的reextract-empty接口与网页/Android按钮。只有没有任何历史MemoryItem行的ready录音能使用；不能复活已删除记忆、重复排队或覆盖非空结果。
5. 微信提取提示明确区分单条不确定、事实纠正和真正无内容；无依据quote直接失败，不能静默过滤成“空数组成功”。共享Contract及后续证据校验保留。
6. 实际调用日志记录端点、请求/响应模型、提示哈希、HTTP、耗时、finish_reason和usage，不记录密钥或全文。最早三段提取发生在新遥测启用前，不补造缺失usage；既有模型版本和处理事件仍保留。
