## 在手机里怎么找这些内容

- **今天**：主区域“讲一段”，进入独立录音流程；“继续整理”和“我的录音”承接未完成记录，不把录音文件全部铺在首页。
- **档案 → 花田**：同一批真实内容沿花径排列。复用原设计的正面、侧面、杯状花形；点花 → 点花瓣 → 阅读依据 → 听完整原音 → 返回原花。列表和查找是替代入口。
- **档案 → 人物 → 了解这个人**：四视角位于首屏，具体条目在其下，能展开来源。
- **档案 → 人物 → 记忆侧面**：八个统一四字标题先给内容预览，无材料时才显示“还没聊到”。
- **全部录音**：仍保留原音、处理状态和核对入口；未形成记忆的录音不会因此消失。
- **查找**：即时文字匹配；提交后另给后端相关检索结果。只有“问一问”进入生成问答。

花朵位置按故事 ID 保留，不按刷新随机分布。环境草地与虚化景物不是记忆数据。聚焦使用约620ms的缩放/淡入，花瓣使用同一花形局部高亮；这是2.5D实现，尚不是完整三维形变或真正连续的共享元素镜头。

## 本轮发现并处理的问题

1. 一次四段材料的故事整理返回不支持的字段，完整校验拒绝了输出。未放宽 schema；保留失败，缩小到相关两段/单段后有界重试成功。失败响应正文未完整留存，不能声称已定位具体字段。
2. 两条初次记忆受 ASR 断句影响，把不完整原因、末尾说明当成事实，技术复核排除。原音、原 ASR、初次模型结果仍保留。
3. 取消旧记忆补录后可能沿用旧关联，改为取消/普通“讲一段”清除关联，并在录音页展示当前目标。
4. 后台保存失败后普通刷新清除错误，可能被界面误当成保存成功。改为仅音频与元数据均保存成功后发布完成标记。
5. 八维总览的搜索原先只影响子页，现总览也显示真实匹配结果；测试断言实际人物行，不能由输入框满足。
6. 非本人来源原先可能标成“本人原话”，现按书面补充、转述、系统归纳、外部材料和核对文字分别标注。
7. 后台刷新时原音的“暂停”也会暂时禁用，现已加载来源的暂停/继续不受普通请求繁忙状态阻挡；新下载、来源准备和权限失效清理保持原规则。

设备测试保留了失败历史：首次播放未等界面请求就绪；大字号测试按“当前启用”定位节点，在权限刷新时丢失目标；另一轮实际发现播放暂停被刷新状态禁用。分别修复等待/定位及上述播放状态后重跑，没有删掉播放或暂停断言。草地分条蒙版的横向接缝也在截图审查中改成了连续渐变。
