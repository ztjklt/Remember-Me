# Agent 核心补验：完整问答、人物确认和真实云端校准

2026-10-08。本机 `codex/agent-integration`；未 push、merge、publish。此报告补充此前30段月度处理，不替代历史结果，也不代表手机产品已经交付。

## 实际改动

1. Twin 在已经由服务端过滤的材料内，按问题的精确词片相关性排序，保留全部原文、证据 ID、时间注释、矛盾标记与已确认理解。没有用标准答案检索，没有增加24,000字符预算，没有把同音人名自动合并。
2. `twin-compact-v4` 增加字形差异和部分已知信息处理；真实全量问答暴露了新的主语/因果错误，保留失败批次。
3. `twin-compact-v5` 进一步要求逐句核对主语、转述题不附加爱好、未说明原因时不从共现推出因果。目前运行服务使用v5。
4. 新增可恢复的 `tools/monthly_eval/cloud_core_loop.py`，在独立身份空间验证真实Groq、人物候选审核/ADD、先锁定回答的校准。不是替换现有后端实现，不自动批准所有候选。
5. 问答审阅工具支持为新批次单独保存审阅，避免覆盖旧60问结果。运行说明中混杂的旧身份路径与本地Whisper启动说明已标清。

- 三轮中，错误爱好归属不再出现；未分享的本子保留原因和私人位置均为UNKNOWN。

- 15项中10项所问要点有支持、5项仍需质量修正、0项上述实质错误；来源机械检查0错误。

**这不是v5完整60问验收，更不是生产准确率。** 固定问题上三轮未重现错误，只说明本轮修复有改善证据；不能保证任意问法都不会再错，也无法单独归因于排序或提示词。

## 独立真实云端人物/校准循环

与30段基准分开，新建虚构许川的Owner/Reader空间。复用有原始哈希记录的小米音频，重新经Groq处理，不复用旧本地ASR。

实际执行：

1. 初始音频 → `groq/whisper-large-v3` → 授权的非完美ASR技术核对 → `Deepseek-v4-flash` → 3条记忆，原音API回读SHA一致。
2. 模型生成3个人物候选。助手逐条看实际原文后，只通过Owner更新接口确认“平时喜欢不加糖的茶”这一候选，动作ADD，保留审核理由与历史。单段来源只标情境化观察。
3. “2010年搬家”候选没有保留原文“后来要核对”的不确定性，未批准；“核心价值观”的概括也没有直接批准。不会因为生成了候选就全部用于问答。
4. 询问“工作收入和家人安全冲突如何选择”，获得有来源回答后锁定。
5. 锁定时间 `2026-10-08T08:43:54.708971Z`；随后小米TTS请求开始时间 `2026-10-08T08:43:54.720905Z`。新生成19.36秒虚构回答，原稿只用于TTS，不作为ASR或Twin输入。
6. 新音频 → Groq → 核对 → 1条记忆 → 微信模型五维校准。报告说明安全优先的决策一致，本人回答多出“不是所有情况下都不要挣钱”的条件；情绪维度NOT_OBSERVED。
7. 比较前后的记忆和人物候选一致，报告没有自动修订它们；完全未分享的空间对独立Reader返回404。

这是**合成音频的真实服务调用和状态循环**。没有真人参与或人工听读。模型报告使用“真人回答”的措辞不改变测试素材实际来源。建议追问“哪些情况下更倾向收入”也需改成更中性的问法，不能当作无条件可用的引导。

测试脚本首次把预期的404私密空间隐藏误当异常；修正断言后从完成的检查点恢复，没有重新生成音频或再次调用已完成的校准。故障说明保留在状态文件。
