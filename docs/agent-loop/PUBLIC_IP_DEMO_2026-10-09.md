## 网络问题与修复

| 层次 | 修改前证据 | 本轮处理 |
|---|---|---|
| 后端 | 8877 内部 ready，四个服务 active | 未修改应用服务 |
| 8443 | 主机已监听、UFW 已允许当前 IP；电脑连接超时，服务器未捕获对应 SYN | 停用本轮新增的 8443 监听和 UFW 规则，保留配置文件；不再要求新增云侧端口 |
| 80/443 | 同时探测的 SYN 到达服务器，来源为 `183.6.9.111`；UFW 只允许旧地址 `120.236.174.183` | 仅增加当前来源到 TCP 443 的 UFW 规则，不新增 80 的权限 |
| HTTPS 路由 | 443 默认站点原为博客 | 新增 IP 站点；博客只移除 IPv4 `default_server`，命名域名和 IPv6 配置保留 |
| 访问范围 | 自用 IP 白名单 | Nginx 仍仅允许当前出口与本机；登录和故事权限仍由后端校验 |

没有读取或修改阿里云安全组。Edge 接管超时，电脑操作工具随后因不能可靠识别网址而停止；没有绕过浏览器限制。443 可达性来自实际抓包和外部 HTTPS 结果，不能据此描述控制台内完整规则。此前请求用户补 8443 的步骤已不再需要。

新配置 `/etc/nginx/sites-available/remember-me-ip443.conf`；原配置备份 `/root/remember-me-ip443-backup-20261009/`。模型服务、PostgreSQL 和内部 API 仍只监听回环地址。新入口将客户端伪造的转发头覆盖为实际连接来源。

IP HTTPS 使用受限信任的自用证书，Android debug 包已有对应公开证书；未关闭证书或主机名校验。私钥只在 ECS，证书到期日为 2027-01-07，届时需要更新证书和测试包。普通浏览器不会自动信任此证书，本轮不把它称为公开网站上线。

原博客验证：`skyspace.cloud` 返回页面与 `/var/www/blog/index.html` 的 SHA256 相同；`www.skyspace.cloud` 仍 301 到原域名。此项是路由/内容检查，博客原证书已有过期问题，诊断请求忽略其证书错误；勿忘我的 IP 连接始终正常校验证书。没有 SNI 的旧客户端现在获得 IP 站点证书，是 IPv4 默认入口的明确变化。依据：[Nginx HTTPS/SNI 文档](https://nginx.org/en/docs/http/configuring_https_servers.html)。
