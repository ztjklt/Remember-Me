## 实际部署了什么

生产应用源码固定为 `6f6d0e6ae1f2649e71d80573ba3f415e32153caa`。后续 CI 和交接文档提交不改变这次已验证的产品源码。

| 部分 | 本轮变更 |
| --- | --- |
| API | 人物条件化回应、亲友贡献、声音配置与播放、来源和权限复核；兼容原账号与故事接口 |
| AI Core | 已确认人物理解参与 Twin；按要点审核事实支持、遗漏与表达；保留原话查询 |
| 记忆后台任务 | 继续 Paraformer → 文字核对 → DeepSeek → 证据保存；WORK_3200 也必须停在核对环节 |
| 人物后台任务 | 生成带情境、支持与例外的候选，并启用候选验证；不自动代替本人批准 |
| PostgreSQL | 从 0016 增量升级至 0021；新增亲友贡献、人物上下文、合成声音、原始贡献 ASR 与审阅摘要 |
| Android | 保留花田、人物和简明模式，融合此前右侧对话的按钮、任务反馈、确认和音频交互；加入云端 Twin/补记/声音接口 |

ECS 的 API、记忆任务、人物任务和 AI 四项服务均切到 `/opt/remember-me/releases/paired-twin-20261013`。模型密钥只在服务器；注册关闭；原公网 HTTPS 范围、SSH 规则和同机博客未改动。普通账号仍从服务端解析身份，不接受客户端自称 owner。

陈守义样例仍是原来的虚构材料：记录者可访问 10 段，亲友可访问获授权的 8 段。没有把两段私密故事一起开放。A01 陈国梁的完整原稿和本地运行库没有迁入公共演示空间。

## 遇到的问题与处理

1. 原 Android 私有 Mac runner 超时取消；改用 GitHub Ubuntu 构建。首轮 Ubuntu 的 `sdkmanager` 不在 PATH，改为官方镜像的显式路径后完整通过。没有删除测试。
2. 冻结版本的年份问答正确引用了两段文字，但标签为 SIMULATION。原发布脚本只接受 ORIGINAL，属于验收误拦。发布检查改为核对模式、模型、有效版本、引文，以及完整的“1987 年，不是 1986 年”修订语义；产品引用校验没有改变。
3. 首次正式部署在备份脚本的 CRLF 换行处退出，尚未备份、迁移或切换；恢复旧服务。控制脚本增加执行前 Bash 语法检查，并通过标准输入执行规范换行副本，保留冻结源码哈希。第二次完成恢复演练与切换。
4. 隔离人物回答仍有不够紧凑的问题：正文存在“未回答部分”，但结构化 coverage 可为 complete。该语义呈现不一致保留为待修项，本轮不宣称人物回答质量已经充分验收。
5. 人物理解与直接记忆有时指向同一段引文，来源面板重复显示。它使首轮自动定位失败，也使阅读冗长；本次保留有效证据，后续应在展示层按来源片段合并，同时保留全部证据关联。

## 录音豆：现在完成到哪里

已读取比赛材料和真实 Android 1.3.02 SDK 公共签名；iOS 资料版本为 1.3.01。

| 能力 | SDK 提供的能力 | 本轮交付 |
| --- | --- | --- |
| 授权/会话 | 离线与在线结果、license 到期、token 过期 | 状态机、续期边界、旧回调/跨账号隔离；不伪造 license |
| 扫描/连接/时间/列表 | 蓝牙扫描连接、状态、电量、存储、时间同步、离线列表 | 真实 Java 调用桥编译通过，主 App 尚未实例化 SDK |
| 文件导入 | 蓝牙/Wi-Fi 传输、实时数据与标记回调 | 原始/派生音频分开保存，哈希、作用域、幂等台账、恢复检查；本轮优先蓝牙离线链路 |
| 录音控制 | 暂停/恢复已有录音 | 没有把它冒充从空闲开始或结束录音；新录音仍由设备按键发起 |
| 音频 → 现有后端 | 厂商 raw Opus 尚缺实机封装确认 | WAV 格式检查、WORK_3200 来源上传与核对链；不把 Opus 改名冒充 WAV |

**还没有真实设备接入、完整 SDK runtime APK 或设备 UI。** 现在的 JVM 假回调和编译证明接口与规则准备，不证明蓝牙下载、音频解码和现场工作。

请向厂商要齐三类材料：

1. `get_token` 完整请求、签名、响应和续期协议，用户/设备绑定定义；现有 app_key 不等于完整协议。
2. 1.3.02 完整 Demo/POM/依赖及比赛二进制分发范围。SDK Kotlin/依赖版本与当前 App 不同，需要独立打包验证。
3. 当前固件的 30–60 秒原始录音、实际回调序列、解码样例和双声道含义。现有 Paraformer 配置选第 0 路，需确认是否会遗漏另一路。

到场按“授权 → 配对 → 设备按键录音 → 列表 → 下载 → 解码和试听 → 上传 → 核对 → 记忆 → Twin”逐步验证，再补断连、重复导入和账号切换。Wi-Fi 加速、实时传输和 OTA 暂不作为首轮前提。由于授权与解码材料尚缺，不能承诺现场必然只改一项配置。
