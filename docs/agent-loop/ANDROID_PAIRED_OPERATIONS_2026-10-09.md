# Android 双角色受限内测操作及交付说明

状态以本轮验收记录及 APK 清单为准。本文件解释使用流程；列出某项操作不等于它已在真机验收。

10月10日更新：正式ECS版本`c2e17fc`已启用；两台模拟器使用相同交付APK、直接IP HTTPS完成三轮分享/播放/撤权循环（18阶段）。原音导入及模型处理另有正式服务器接口验收。实体手机、全程新麦克风录音和恢复行为仍未完成，详细证据见[最新验收记录](PAIRED_DELIVERY_RECOVERY_2026-10-10.md)。

## 安装与连接

- 内测包名 `me.remember.app.internal`，版本 `0.7.0-internal`。与开发包独立，不覆盖开发包里的本机原音。
- 默认服务地址 `https://39.108.183.47`。无需购买域名、填写 actor_id 或设置模型密钥。
- 只有现有网络白名单覆盖的出口可用。切换手机热点或其他 Wi-Fi 后不能连接，应检查访问名单；不要通过关闭 TLS 校验解决。
- 普通账号由管理员准备；注册保持关闭。两个账号独立登录，不能使用同一个账号假装双角色。
- IP 测试证书到期日为 2027-01-07。浏览器系统不信任它，不表示 App 也不信任。App 只对该 IP 信任已包含的证书，其他地址仍用系统信任。
- 后端负责 Paraformer、DeepSeek、存储与权限；手机负责录音、保存本机原音、播放、核对与展示。服务器未启动/网络不可达时仍应保留已经保存的原音。

## 记录者的操作

1. 登录自己的普通账号，在“今天”同意本次录音，开始、暂停/继续、完成；先试听原音。
2. 同意云端识别后上传。看到“已保存”不等于已整理完成。等待转写后进入“核对转写”。
3. 修正名字、方言或误识别；“再补充一点”填写口述中没有的说明。机器稿不覆盖，书面补充不标为录音原话。
4. 明确确认文字并整理。失败时保留原音与已有文字，按阶段重试；不要重新录一份假装原任务成功。
5. 在“档案”看故事、记忆和人物视图。人物理解先是候选，查看条件与依据后再确认。
6. 在“我的”选择要分享的录音或已确认故事，预览全部原音/文字范围。跨录音故事会展开多段完整录音。
7. 单独选择是否允许云端问答，生成邀请码。把邀请码自行交给亲友；应用不会替你发送消息。
8. 亲友领取后，核对唯一账号名及昵称，批准。只有批准成功才开放内容。批准时材料有变化，重新预览创建邀请。
9. 在待答问题中选择回答、稍后或拒绝。新录音/书面补充按正常核对整理流程处理。
10. 新回答不会自动分享；为已经确认的亲友再次预览并批准，可省去重新领取邀请码。
11. 撤销本次分享只撤销这一批新产生的授权；更早独立授权须在相应录音条目撤销。

## 亲友的操作

1. 登录自己的普通账号，在“我的”粘贴邀请码，领取后等待本人确认。领取成功不等于能看故事。
2. 批准后刷新或等同步完成，点击空间名进入获授权空间。
3. 在首页或档案打开故事、播放完整原音。没有可靠时间对齐时，不提供虚假的逐句定位。
4. 在“对话”明确同意这次使用云端模型后提问。区分本人原话、材料整理和未知；展开来源核对。
5. 没有材料时提交希望本人补充的问题。问题和模型回答不会反向变成本人的事实。
6. 等本人补充并主动分享后，再查看新材料。撤权后后续请求受限，App 同步后停止相关播放并清除入口。

## 服务端实际状态流

录音文件保存 → 转写排队/进行中 → 待本人核对 → 本人提交核对稿/书面补充 → 提取与证据校验 → 持久化记忆 → 候选人物理解/故事关联 → 本人审核 → 分享预览 → 邀请领取 → 本人批准 → 受权限约束的读取/问答。

补充、纠正、后来变化分别保存；纠正使旧事实失效，时间变化保留前后；不覆盖原音。模型调用期间不持有数据库写锁，返回后复核资料/人物理解/授权版本，变化时返回可重试状态而不是发布旧答案。

## 管理员维护

- SSH 别名：`remember-me-ecs`。四个服务为 `remember-me@api`、`@ai`、`@worker`、`@profile`。
- 在当前后端运行环境加载 `/etc/remember-me/api.env` 后，使用 `python -m app.account_admin create 用户名 --name 昵称` 或 `reset 用户名`。密码交互输入，不放命令参数；reset 会撤销已有设备会话。
- 专用内测账号可由 `tools/round_two/provision_ecs_pair.py` 创建，复用同一管理员函数。服务端凭据只写 root 可读文件，本地交接副本只放忽略目录，不进 Git。
- 固定内测签名保存在本地忽略目录。不要换签名重新发同包名，否则已有安装无法正常升级。
- 若证书更新：先核对 IP SAN、有效期和服务端证书，更新仅针对该 IP 的公开证书资源，重建签名 APK，分别验证受信与错误证书拒绝；不得使用 trust-all。

## 部署与回退

1. 冻结版本、APK 哈希、模型配置、迁移号与完整质量报告，门槛失败不得切换。
2. `bash tools/round_two/backup_ecs_paired.sh /opt/remember-me/releases/paired-COMMIT` 备份数据库、原音和配置。显式填写本次候选目录，恢复到明确命名的测试库/目录，验证原音哈希及该候选的新增迁移；恢复记录保存实际迁移源码目录。
3. 新发布目录安装相同源码。本轮后端复用已验证的依赖环境；AI Core 使用另建的生产依赖环境，补齐运行时需要的 `jsonschema`，没有修改原正式 AI 环境。被引用的发布目录和 `.venv` 必须保留，不能因“旧目录”就删除。代码、依赖和模型配置分别记录。
4. 使用 `switch_ecs_paired.py` 切换前再次校验质量清单和恢复记录；停止 API/后台任务后追加迁移，更新服务，验证就绪和版本。
5. 失败时回退应用目录及本轮修改的服务配置。新增表保留；不降级数据库、不清空任务、不覆盖或删除原音。
6. 从实际允许网络验证 IP HTTPS、普通账号、真实 ASR/提取/问答和邀请；只验证 loopback `/ready` 不算手机连通。
