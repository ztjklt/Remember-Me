# 本地 Twin 体验与后续部署准备

这一轮不部署 ECS，也不推送 GitHub。现有云端 APK 保持原状；本地调试 APK 用于 Android 模拟器，连接电脑上的真实 API 和云模型适配器。

## 启动与进入

在 Remember Me 本轮 checkout 根目录运行现有 Python 环境：

```powershell
& 'D:/codex_work/remember-me-agent-loop/services/backend/.venv/Scripts/python.exe' -X utf8 -m tools.a01_local.runtime start
```

如果8891或8892已在运行，启动器会拒绝重复启动。先查看 `services/backend/var/a01-20261012/runtime/processes.json` 和相应日志。不要通过删库、换账号、重复转写来解决连接问题。

网页入口为 `http://127.0.0.1:8891/workbench/companion.html`。模拟器使用 `http://10.0.2.2:8891`；本地debug仅允许回环来源的这一地址别名访问账号接口，不把该HTTP特例用于ECS。

现有本地账号保存在忽略的 `services/backend/var/a01-20261012/private/local-accounts.json`。选择陈国梁虚构人物空间。本人和亲友是两个真实会话，不是客户端角色开关。

服务模型：Paraformer；微信 `Deepseek-v4-flash`；小米 `mimo-v2.5-tts-voiceclone`。模型密钥由现有本机配置加载，不写入 APK。

## 按三个任务体验

**看人，再聊。** 档案→人物→已确认的理解，左右切换；“查看情境与来源”展开原话。对话保留“找他说过的话”，本人开启表达后可选“与 AI 分身聊聊”。声音生成失败只重试声音，不重复问答。

**用补录更新理解。** 本人回答页→“和我的想法对照”，先锁定答案，再录制/导入本人新回答。转写核对和整理完成后比较。比较结果只是建议；确认人物更新另行操作。新材料分享给亲友仍需明确授权。

**亲友补记。** 本人开启贡献许可；亲友导入或录制→保存原音→转写→核对→提交。本人可接受、拒绝或保留分歧。作者和本人分别允许用于对话后，Twin才可引用。撤回后原音和新问答受限。接受一项观点不会把它变为本人的记忆或人格。

## 数据与恢复

本轮SQLite及原音目录：`services/backend/var/a01-20261012/runtime`。

迁移顺序为已有0017、0018人物回答依据与独立补记音频、0019虚构声音配置和读者声音许可、0020原始ASR字段。迁移前已有SQLite备份和完整性检查；旧数据没有原始ASR时保留空值，不用显示稿伪造。

录音保存、ASR、核对、记忆整理、问答、声音生成分开记状态。失败保留原音。专用补记不会作为本人Episode上传，专用留言也不会绑定一整段无关录音。撤回的音频不应从旧URL继续读取。

## 以后升级ECS时必须准备

这不是当前已执行的部署记录：

1. 从本轮代码形成固定发布版本，先审查保留的其他本地改动；不要直接打包整个var目录。
2. 在PostgreSQL副本验证0018–0020、授权事务与并发探针。本轮六项PostgreSQL实库测试未运行。
3. 备份数据库、音频、现有配置并验证恢复，再准备新发布目录。
4. 同一版本更新API、AI Core、记忆和人物后台任务。服务端设置 `REMEMBER_AI_TIMEOUT_SECONDS=100`，大于Persona含排队的90秒总预算；仓库后端默认30秒不能直接沿用本轮分身路径。正式环境关闭 `AI_PERSONA_FICTIONAL_DEBUG_TRACE`；不得把本地注册与HTTP回环特例复制为公网设置。
5. 若启用虚构演示音色，单独配置其主体、参考WAV和Xiaomi密钥；不可把任意账号上传内容视为已授权真人声音。
6. 复用现有IP HTTPS和内测签名构建服务器版APK；先用两个普通账号跑完整授权与撤回，之后才切换客户端。

没有合适服务器版ASR或声音连接时应保留明确不可用状态，不把密钥嵌入APK或自动换供应商。
