# 录音豆能否支持声纹：接口核查与落地路线

结论：可以利用录音豆采集的音频另做声纹识别；本次提供的 SDK 没有查到可直接调用的声纹注册、身份比对或说话人分段接口。设备连接成功不等于已经认出了讲话的人。本次为代码和文档核查，尚无实物声纹实测。

## 已核实的输入能力

核查来源是本机 `D:/sdk_rm1013` 的 Android 1.3.02、iOS 1.3.01 公共接口与集成文档；不把域名里的 `speaker` 或 SDK license 的 `verification` 当作声纹功能。

| 项目 | 供应商材料中的依据 | 当前判断 |
|---|---|---|
| 获取正在录制的音频 | `acquireRealtimeAudioData`；guide 304、316–332 行 | 有能力；设备需已开始录音，不能据此声称支持远程启动 |
| 实时音频片段 | `onReceiveAudioFragment` 的 `audioData`、`sequenceNumber` | Opus，每片段 20ms；可用于排序、保存和后续解码 |
| 离线录音 | 文件列表、蓝牙/Wi-Fi 传输及处理回调 | 有接口；适合先做录完后的人物归属 |
| 音频格式 | guide 740 行 | 无文件头的 Opus，文档标注 16kHz、16bit、双声道、20ms/160byte；须用实物核对包长、固件及解码产物 |
| 讲话者身份 | MAC、UUID、fileID、isMark | 都不是人的身份；双声道也不代表一人一个声道 |
| 声纹算法 | 对 guide、Android public API/class list、iOS interface/header 搜索 | 未发现注册、比对、声纹向量、说话人分段接口；仅对这批公开材料成立 |

仓库当前已有 `Work3200Session`、导入日志、SDK 桥接样例，以及 `WORK_3200` 上传后等待核对的规则。`Work3200Audio` 明确只是 PCM/WAV 校验器，不是 Opus 解码器；样例 `onReceiveAudioFragment` 尚为空。声纹模板、模型推理、身份建议和用户确认页面均未实现。

## 三种不同能力

1. **说话人分段**：判断 00:02–00:08 是甲，00:09–00:15 是乙；没有注册样本时只知道是不同人。
2. **声纹识别/比对**：将片段与已经同意注册的声音样本比较，建议“这段可能是陈先生”。
3. **声音复刻**：把新文字读成某种音色。不是身份识别，也不能用复刻测试证明真人识别可靠。

20ms 适合传输，不代表 20ms 就能可靠判断身份。应先累计含实际人声的片段；最短时长和置信阈值要由录音豆的实际噪声、距离和讲话样本校准，不从文档编一个准确率。

## 对勿忘我的具体价值

- 本人和亲友一起讲故事时，先分段，再提出署名建议，减少把亲友的经历归到本人身上。
- 本人核对后，本人讲述进入自己的记忆；亲友讲述进入署名补记，不能自动变成本人性格。
- 整理录音时提供“只听本人/听亲友补充”的入口，并保留原始整段音频。
- 帮助筛选声音复刻的候选样本，剔除他人插话；仍需独立的声音使用许可。

声纹仅帮助归属，不代替登录、故事授权、密语或托付解锁。多人重叠、过短、噪声太大、不认识的人应返回“未确定”，让人点选；不为了填满姓名强行匹配。

## 可落地的数据链

```text
SDK 录音/Opus 包 → 去重与排序 → 实际解码成 PCM
    ├→ ASR：带时间的文字
    └→ 人声片段 → 说话人向量/聚类 → 注册样本比对 → 身份建议
对齐文字与建议 → 人工确认发言人 → 本人记忆或亲友署名补记
```

建议第一批做**录完后的分段和归属**，不把声纹识别塞进每一轮语音接话的阻塞路径。已登录用户的单人语音聊天可以继续运行，录音豆双人回忆单独验证。以后若要实时标注说话人，可让识别与 ASR 并行；归属未确定之前不自动保存为本人事实。

拟议数据边界（还不是已发布接口）：

- 声音样本：所属账号、参与者、原音来源、模型版本、独立许可/撤回状态。
- 片段：录音 ID、开始/结束毫秒、候选说话人、分数、unknown/overlap 状态。
- 核对记录：建议身份、人工确认身份、确认者、版本；推测不能覆盖确认。
- 记忆引文继续记录“是谁说的”和“说的是谁”；这两个角色不能合并。

声纹向量和注册原音与私人资料同样保护，不放进客户端公开资源；撤回后清除可用模板并停止新匹配。

## 可借鉴的现成实现

- [3D-Speaker](https://github.com/modelscope/3D-Speaker)：官方仓库提供声纹比对、说话人识别与分段，以及中文 CAM++/ERes2Net 系列预训练推理入口。适合首先评估中文场景；公开基准成绩不是我们录音豆的成绩。
- [SpeechBrain SpeakerRecognition](https://speechbrain.readthedocs.io/en/latest/API/speechbrain.inference.speaker.html)：提供声音向量和文件比对接口，可用于较小的注册/匹配对照。

本次没有在 ECS 安装新的重模型或上传真人注册样本。先手机采样可验证模型接口；最终仍需豆子实录来检查编码、距离和噪声，不以合成音频充当真人识别验收。

## 验收分两步

1. 无设备准备：明确并实现独立适配器、PCM 合同、时间对齐、unknown/人工改名和撤回流程；SDK 断包/重复包必须保留并报告。本次完成的是能力核查及这些边界的设计。
2. 拿到设备：两名知情参与者分别注册、交替讲话、插话、加入第三个未注册的人，分别统计错认、漏认、未确定和人工修正次数；增加扬声器重放与 Twin 播音样本，防止把播放声记为新的本人讲述。

未完成项：实物解码、算法选型实测、注册与删除接口、分段对齐、人工确认页，以及对现有记忆/贡献的端到端联调。尚不能宣称“拿到豆子即自动认人”。
