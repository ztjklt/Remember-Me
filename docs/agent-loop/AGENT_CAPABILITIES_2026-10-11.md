# 当前 Agent 究竟做什么

这是一套带来源、权限和修订流程的记忆整理与问答系统。模型提供语义处理，服务端负责记忆状态与权限，客户端负责记录、核对和呈现。没有训练出一个完整人格，也不是几个模型自由交谈。

## 和直接询问大模型相比

| 环节 | 当前系统增加的能力 | 仍然存在的限制 |
|---|---|---|
| 留下 | 保存原音、机器稿、核对稿和书面补充，确认后才提取 | 转写错误仍需要核对；音频未可靠逐字对齐 |
| 记住 | 提取带来源的记忆，保留否定、人物、时间；补充、纠正、变化分别处理 | 本地结构和引用校验不能保证每项语义解释正确 |
| 组织 | 提出故事、人物指代、情境观察、表达范例、寄语及八维标签 | 跨录音关联仍需审核，未实现全自动可靠组织 |
| 理解 | 人物候选带条件、支持证据、反例及 ADD/SUPPORT/CONFLICT/CHANGE | 样本少时只能是局部观察，不能当稳定人格 |
| 回答 | 先按授权与有效性构造材料，再回答、核对引文与版本 | 当前偏向保守引用；会漏答、拒答或表达生硬 |
| 更新 | 已失效来源不进入新结果；调用后复核，变化时返回 SOURCE_CHANGED | 不能远程收回别人已经听到或保存的内容 |

八个侧面和四个视角属于组织、检索和浏览方式，共用同一批证据，不是八个模型或四套人物数据库。

## “两个 Agent”和早先四个职责如何对应

从使用者角度，可区分为两个助手：**记录者的整理助手**与**亲友的了解／问答助手**。这两种效果已有实现，但共用同一套服务端事实和授权，不运行两套互相对话的事实系统。

| 早先名称 | 实际代码形态 | 状态 |
|---|---|---|
| Main Twin | 在线来源问答核心；可选表达风格处理 | 有真实模型调用；不等于可靠模仿本人思维 |
| Memory Keeper | 核对后的异步提取、来源保存、记忆修订任务 | 已实现；提醒为独立、自愿开启的设备能力 |
| Portrait Reader | 有权限约束的人物／叙事视图读取 | 已实现；本身不需要另一次 LLM 对话 |
| Psychological Learner | 人物候选与更新关系后台任务 | 已实现局部、情境化归纳；不推测隐藏心理或诊断 |
| 引导与校准 | 规则选择一个待答问题；先锁定 Twin 答案再收集本人答案 | 已有流程；本次 UI 修订未重新跑校准验收 |

亲友的问题只成为问题单。模型回答不会自动变为本人记忆。本人补录核对完成后，仍要重新授权才能让亲友使用。

## 当前看得到的成效

陈守义新版十段合成样例共有 61 条当前有效记忆。经过技术复核的叙事材料有 10 个故事、5 项人物记录、7 项情境观察、2 项表达范例、1 段寄语。八个侧面均有来源支持，但数量交叉，不能加总成人格完整度。

**2026-10-11 后续修复已部署 ECS**：此前新增 CLOUD_TWIN 授权会令旧候选过度失效。现在材料依据与权限检查分离，生成期间仍复核全部资料与权限。旧 5 项 stale 保留历史，不直接恢复。真实 DeepSeek 重新生成 3 项候选，经虚构素材技术复核确认 2 项、拒绝 1 项；当前共 2 项有效 confirmed、2 项 rejected、5 项历史 stale。

具体保留的是喝茶口味偏淡，以及“平安回家比多跑一趟重要”与家人等候的明确关联。被拒绝的是把一次延后回答扩大为普遍决策倾向。连续三次新增问答同意后，已确认理解仍有效，来源修改或并发撤权依旧阻止旧结果生效。[修复、真实结果与限制](PROFILE_VALIDITY_FIX_2026-10-11.md)。

以上含模型提取及人工技术整理，不是全部自动生成，更不是虚构人物进行了真实本人认可。此前 12 个问答开发检查有实际调用与逐项记录；本次页面调整没有重跑完整 60 问，不可把 UI 通过当作模型准确率通过。详见 [0.9.0 验收记录](IMMERSIVE_GARDEN_ACCEPTANCE_2026-10-11.md)。

## 下一步最值得深化

1. **画像有效性与故事关联质量**：已修正授权导致的过度失效；下一步区分同一事件复述和不同事件支持，明确人物指代、模糊时间、来源缺口，形成可以直接接受或改正的少量建议。
2. **人物理解变化**：把“一次观察→其他经历支持→出现例外→本人解释”展示为有条件的变化链。不能只增加标签数量。
3. **亲友视角归纳**：目前读者读获授权的已审核故事／情境观察，不能读取所有者完整私人候选；尚未实现按每位亲友可见材料独立重新归纳人物模型。
4. **回答组织**：在引用与权限约束不变的前提下改善答全、多问题分点、读起来像解释而不是拼接。更强模型可以对照测试，但不能代替系统约束。
5. **引导与反馈**：现有补问按冲突、亲友问题、缺少时间排序；还需要更自然的采访节奏、指代澄清和用户反馈闭环。
6. **真实使用验证**：使用志愿者自己的材料验证是否理解恰当。合成故事可以验证工程链路，不能证明“越来越像真人”。

## 代码依据

- `services/backend/app/api/twin.py`：权限过滤、有效来源、已审核故事、人物条件、可选表达、返回前版本复核。
- `services/ai-core/app/quoted_twin.py`、`grounded_twin.py`：要点选取、引用与回答约束。
- `services/backend/app/narrative_worker.py`、`profiles.py`：后台故事／候选生成及来源校验。
- `services/backend/app/api/narrative.py`：四视图与按冲突／亲友问题／故事缺口选择补问；读者不复用所有者完整私人候选。
- `services/backend/app/profile_updates.py`：人物理解关系与更新。
- `services/ai-core/app/calibration.py` 及对应后端接口：校准任务，不直接自动改事实。
