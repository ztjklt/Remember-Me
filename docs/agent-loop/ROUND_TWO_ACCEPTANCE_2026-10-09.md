## 现在能实际操作什么

1. 在档案中选择一至两段已核对讲述，明确同意后交给真实微信模型组织故事、人物与情境观察。
2. 查看草稿引用，编辑内容与原文称呼；确认、撤回、移出来源、拆出故事，查看修改历史。每次修改都重新核对。
3. 在人生足迹、重要的人、在意与选择、声音与表达四个视图浏览同一批材料；一条材料可以属于多个内容维度。
4. 从故事展开实际核对文字并播放完整原音；发生时间模糊就保留模糊原文。没有假音频片段定位。
5. 查看人物候选的情境、支持与例外；使用原有 ADD / SUPPORT / CONFLICT / CHANGE 管理入口。候选不自动当作人格。
6. 单次提出一个有理由的补问，支持稍后、跳过；已有亲友问题仍通过录音关联并另行授权。
7. 从本人文字逐字选取“给你的话”与表达范例；收信人标签不授予访问权。风格默认关闭，开启后依旧标注系统生成。
8. 网页花簇绑定已确认的故事 ID；点击回到实际故事。Android 延续自然配色、品牌和原生控件，先用清楚的列表承载内容。

核对仍依赖人的判断。来源逐字存在能证明引用可定位，**不能证明机器转写准确，也不能自动证明摘要推断成立**。

## 故事组织：失败历史完整保留

使用已有三位虚构人物的30段历史音频与ASR。**本轮没有重跑TTS或ASR，没有用创作原稿覆盖ASR，也没有宣称人工听读通过。** 后续模型只接收已授权的有效核对材料；gold答案只用于检查表。

| 真实实验 | 完成 / 失败 |
|---|---|
| 每人整月输入，v1 | 0 / 3 |
| 每人整月输入，v3 | 0 / 3 |
| 两段一组，v3首轮 | 9 / 6 |
| 仅六个失败批次，v4一次复查 | 2 / 4 |
| 仅四个失败批次，v5最后一次复查 | 3 / 1 |

最终15个不同的两段批次中14个完成，不是首轮14/15。失败原因包括字段不符、把多个地点拼成一个“原文”字段、别名不在引用中；最后一批仍因额外 `content` 字段被拒绝。没有删除校验或自动丢弃错误条目后冒充成功。

共56份模型草稿。选定材料经助手技术核对后，12份确认、4份拒绝、40份仍待核对。拒绝包含：ASR事故肯定句与相邻否定冲突、旧年份状态没有交代、将自我定位当人物实体、结论没有所引来源支持。确认者是虚构材料的技术审核，不是真实记录者本人认可。

其后额外创建3条人工选取的原话/寄语，以及2条故事拆分验证记录。最终记录状态不是模型产出的准确率，不能混算。

另外，对三个人各执行一次真实人物候选刷新：公交司机、消防员完成，人生回顾人物遇到45秒上游超时（504）。定位日志后仅对该超时任务显式复查一次并完成，原失败保留在 `profile-refresh.json`，复查在 `profile-timeout-recheck.json`。新候选包含有直接口味依据的观察，也出现把测试素材中“不要编造”的写作要求归纳成稳定倾向的风险。所有新候选保持待核对，没有因为API完成便自动确认。`*-profiles-final.json`还包含此前历史候选，不能把文件里所有条目都算作这次新生成。

## 两轮60问：程序成功与内容可靠分开

两轮都是开发回归集，使用同一批原有问题。`initial` 为原问答配置，`checked` 加入一次同模型回答检查。二者不是独立留出集，也没有足够重复次数支持统计性的提升结论。

| 运行 | 返回回答 | 明确失败 | 人物问答可靠性验收 |
|---|---:|---:|---|
| initial | 59 | 1 | 未通过 |
| checked | 56 | 4 | 未通过 |

主要问题：

- `bus_driver-q08`：初轮把过去与现在住址说反；第二轮该例答对，仍不能证明稳定修复。
- `bus_driver-q09/q10`：最初漏答，第二轮转述仍使用“他/某人”，没有完整说明是谁的父亲。
- `bus_driver-q19`：第二轮先说不知道，再给出原因，同模型审查未拦住。此后增加确定性守卫，失败用例先红后绿；**守卫后尚未重跑第三轮60问**。
- `life_review-q04/q07/q08`：模型把不同ASR字形当成同一人/地名变体，未经本人确认；语义检查仍可能放过。
- `life_review-q11`：初轮有材料却拒答，第二轮回答了两位李青的区分；属于单例改善。
- 来源中存在许燕/许雁、梁书/两树、无息/吴熙等识别差异。引文可定位不代表识别的字就是正确姓名。
- 复合问题的风格测试出现“他用自己的方式理解”指代不清；风格层没有改善，也没有替代事实核对。

技术阅读检查了两轮答案；针对部分问题核对了引文和原材料，**没有完成全部120份回答的逐事实、逐引文独立人工评分**。因此不输出虚假的准确率、人格相似度或胜出百分比。

新增 `AI_TWIN_VERIFY_ANSWERS=true` 使用同一模型检查来源支持、矛盾、回答要点及UNKNOWN是否有理由。它是可能漏检的防线，不是证据裁判。失败保留为处理失败，不转成UNKNOWN，也不自动改写并重试。

## 仍未完成的产品部分

| 原计划目标 | 当前边界与下一步 |
|---|---|
| 人生阶段 → 故事 → 记忆 | 已有故事层与原文时间；人生阶段总览、可靠排序和变化视觉仍需深化 |
| 人物关系详情与回忆线索 | 已有别名确认、文字搜索与人物条目；跨故事关系详情、物件/照片线索入口未完整实现 |
| 读者独立人物理解 | 只呈现全部依据可见的已核对观察，未实现读者范围内的独立模型再归纳；没有复用私人画像 |
| 一次观察→支持→例外→本人解释→更新 | 原有状态与接口保留、新视图接入；完整真人语义与手机变化链未验收 |
| 分问题列已知/未知 | 提示与检查已约束，仍有漏答和不当关联；下一步应提供可审核的逐问题要点及来源，不能靠追加宽泛提示解决 |
| 表达风格 | 可关闭、可追溯、接口真调用；尚未证明效果，不能将合成角色当本人认可 |
| 移动花园与iOS | Android故事列表可操作；完整花园镜头、iOS编译、实体手机与读屏待验证 |
| 独立评测 | 未冻结前不建立“已通过”留出成绩；12段新材料/60问及5组自愿本人—亲友任务尚未执行 |

语义质量门槛未通过，不以这次实现作为“数字分身可靠性完成”或对外发布的依据。优先改进转述实体确认、时间条件、逐问题要点和引用支持；随后按相同材料与模型配置比较旧版、有效全文基线和新方案，完整报告失败与调用成本。
