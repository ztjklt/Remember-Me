# 提前检索、输入精简、Smart Turn 与比赛 API 实测

本轮结论：实现并实测了提前检索与可逆输入精简，离线运行了 Smart Turn，测试了比赛提供的六种文字模型。**没有达到稳定两秒，也没有证明这批改动整体优于上一版。候选已回退，不能作为提速成功版本交付。**没有推送 GitHub。

## 运行范围与最终服务器状态

- 基线：`paired-voice-streamed3-20261014`；试验：`paired-voice-next-20261014`。
- Android：同一个 `0.11.2-internal`，公网 IP HTTPS/WSS，不使用 SSH 隧道或 ADB reverse 承载业务。
- 试验完成后 ECS 已恢复基线，四个服务 active，`/ready` 返回 ready；数据库、原音没有回滚或删除。
- 候选目录、本地代码、备份与全部成功/失败结果保留。备份：`/var/lib/remember-me/backups/paired-20261014T133605Z`，此前已隔离恢复验证。
- 最新视频是候选实验录像，不是“当前服务器已稳定两秒”的证明。

## 实现与实际收益

| 项目 | 实现 | 本轮观测与判断 |
|---|---|---|
| 提前检索 | 临时识别防抖，单轮最多两次准备；不调用回答模型；按最终问题、历史、身份、授权、来源版本精确复用 | 第一段三轮最终查询均未命中预取选择。ASR 最后才补齐“故事”“茶”“淡一点”等词；不能用前半句话的检索结果顶替最终查询。没有证明提速 |
| 输入精简 | 重复字段转为列名、共用字段和行，原文完整；可逆还原；语义审阅仍使用完整原结构 | 同一批 WeChat 请求的可比较样本输入 token 降约 3.1%—5.5%，不足以消除模型等待；某些小包/混合窗口包可能变大，尚未加收益门槛 |
| 取消 | 关闭/结束准备时通知工作线程；快照加载与检索返回处检查取消 | 协作取消回归通过。正在运行的单次同步编码需返回后退出，不能强制瞬间杀死线程 |
| Smart Turn v3.2 CPU | 官方权重，16kHz PCM，8 秒窗口，两个 CPU 线程，独立实验环境 | 45 次推理（15 个不同音频片段各重复三次）中位 68.32ms。完整三问均判断结束；六个截断片段有五个也判断结束。截断片段并非自然停顿，不能据此计算真人误判率；没有上线接管结束判断 |

最终本地 AI 相关测试 **85 通过**；隔离 PostgreSQL 相关测试 **40 通过**；独立审阅发现的预取线程取消边界已修复。测试通过只说明对应约束，不代替延迟与内容验收。

## Android 同题、原速测试

复用此前三段完全相同的合成问题音频，依次为公交故事、插话转问喝茶、继续问浓淡。音频送入 App 实际通话 PCM 通道；真实调用 ASR、记忆、WeChat 和小米。绕过模拟器系统麦克风，**不是实体手机收音/回声验收**。

计时：问题最后有声采样到 App 回答第一段有声采样；10ms RMS 窗口阈值 200，AudioTrack 播放进度同步。保留输入尾静音、TTS 前静音及所有等待，视频不加速。

| 运行 | 公交故事 | 转问喝茶 | 连续追问 | 结果 |
|---|---:|---:|---:|---|
| 历史基线录像 | 4.259s | 3.175s | 2.551s | 之前的单次记录，不是本轮同时随机对照 |
| 候选第一次 | 4.759s | 14.610s | 2.770s | 完整走通；第二轮模型超时后重试 |
| 候选第二次 | 失败 | 未执行 | 未执行 | 两次 8 秒模型期限耗尽，App 明确失败；未删除失败记录 |
| 候选第三次 | 4.294s | 2.711s | 4.553s | 完整走通；为最后一次实跑，非挑选最快录像 |

两段成功录像均完成插话，输入新问题起点到旧播放停止约 **302/303ms**（包含输入前静音，非纯语音检测耗时）。第一段 52.40 秒，第三段 45.50 秒。

第三次各阶段（秒，模型列由同轮日志对应；其余为边界残差，不称为纯网络耗时）：

| 环节 | 公交故事 | 转问喝茶 | 连续追问 |
|---|---:|---:|---:|
| 停声到最终识别/轮次启动 | 0.878 | 0.671 | 0.816 |
| 资料准备与检索 | 0.489 | 0.496 | 0.626 |
| 模型完整选择请求 | 1.893 | 1.072 | 1.474 |
| 其余校验与转交 | 0.282 | 0.245 | 0.230 |
| 结果就绪到第一段有声播放 | 0.752 | 0.227 | 1.407 |
| 合计 | 4.294 | 2.711 | 4.553 |

因此等待不只是 DeepSeek：有的轮次 TTS/播放准备仍超过一秒。把某次接口首包误当作手机端有效回答时间，会低估体验延迟。

另有隔离协议脚本的一次连续运行出现 `AUDIO_RATE_LIMIT`；同次其他两问返回成功。它没有被算成完整连续测试通过。上述两次 Android 完整运行未出现该错误，原因尚未充分定位。

## 比赛 API：同材料测试结果

使用用户明确提供的网关及密钥，只发送虚构且获授权的样例资料。密钥仅存受限私密目录，不放源码、APK或报告。六模型先各一题探测；随后对 WeChat、比赛 Flash、Nova 做七题对照，覆盖公交故事、茶、追问、1987纠正、解释旧1986、未知密码、旧杯子原因。

七题完整包与七题精简包各一轮；另对两个 DeepSeek 请求关闭思考；对比赛 Flash 再试低思考。合计 **69 次请求**：六次初筛加63次扩展。顺序串行、小样本、配置分组，不能当作普遍模型排名或供应商 SLA。

下表是63次扩展测试汇总，延迟中位数仅对完成严格 JSON/引文校验的请求计算；失败另列，**不等于语义正确率**。

| API | 请求数 | 结构与来源校验通过 | 首正文中位 | 完整结果中位 | 失败 |
|---|---:|---:|---:|---:|---|
| 现有微信 DeepSeek | 21 | 20 | 1.604s | 1.702s | 1次超时；成功也有12.916s长尾 |
| 比赛 DeepSeek V4.1 Flash | 28 | 19 | 1.807s | 1.861s | 超时及输出预算耗尽，详见原始结果 |
| 比赛 Nova Pro | 14 | 11 | 2.993s | 3.044s | 2次超时、1次所选来源超出接口结构约束 |

其他模型仅初筛一题：GLM 首正文4.798s（JSON解析失败），Qwen Max 7.720s，Kimi K3 4.493s，DeepSeek Pro 7.275s。这些只有一次结果，不能据此认定它们总体更差或不适合后台分析。

**思考开关是明确待解决项。**比赛 Flash 默认消耗思考 token，有的512 token预算全部用于思考；发送 `thinking.type=disabled` 后仍返回思考 token，低思考也未消除失败。不能说关闭已生效，亦不能把因小预算截断的响应解释成模型智力不足。需要主办方确认路由参数透传/非思考配置；若用于后台分析，应另测足够输出预算，不沿用语音短响应限额。

内容检查发现：年份纠正与未知密码在正常返回中能保留；喝茶会重复引用；旧杯子“为什么没扔”出现过错误 UNKNOWN；旧年份解释有时同时引用“尚未核实”和后来的纠正却缺少清楚衔接。输入可逆不保证模型选材正确。本轮没有证据证明比赛 API 的人物分析整体更好。

## API 速度如何判断、下一步怎么做

没有统一的“一般API多少秒”。至少区分首正文、首个可播放且有效的短句、完整答案和手机开始有声播放；思考内容与“让我想想”不算有效回答。本次带资料的正常请求常在1—3秒量级，长尾达到8—20秒，这只是本项目的实测范围。

当前约1.6秒首正文对于文字问答尚可用，但对于**全链路2秒**偏慢：ASR、检索、TTS与网络/播放还要占时间。目标预算可探索为收尾0.3s、准备0.2s、模型0.7s、声音/传输0.6s、余量0.2s；这是工程目标，非已完成指标。

下一步优先：

1. 在进入通话时准备已授权人物资料，避免每个未完成短句都做完整检索。预取选择只有问题和版本相同才复用；较长讲话的预取收益单独测。
2. 先查明比赛网关非思考参数；实时聊天和后台深度人物整理分开选模型，不让长思考占用接话路径。
3. 进一步减少重复表达结构并设置压缩收益门槛，保持关键原文、否定、条件、修订和反例；重新做语义对照，不能用截断换速度。
4. Smart Turn 与 VAD 联合做自然停顿影子测试，先测误抢话，再决定提前收尾幅度。
5. 对新的低延迟服务，先测同一ECS出口、同一材料的首有效句及长尾，再决定切换。官方 tokens/s 不是手机首次出声时间。
