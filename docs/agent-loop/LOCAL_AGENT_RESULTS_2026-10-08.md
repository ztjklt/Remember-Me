## 自动更新建议接入

共享后端仍为唯一事实与权限存储。新增：

- `POST /api/v1/workbench/subjects/{subject_id}/profile-candidates/suggest-relations`
- AI Core 内部 `POST /profile-relations`
- 后台任务 kind=relations；迁移0014追加来源、模型版本和建议证据字段。旧行默认 owner/candidates。
- 模型调用前后都检查所有者、云端授权及来源/人物版本；调用期间不持数据库写锁。
- 模型仅产生 ADD/SUPPORT/CONFLICT/CHANGE 建议。必须通过既有确认接口才影响当前理解。
- CHANGE 时间短语必须逐字出现在原文；不存在的来源、跨领域目标和完全重复原文的 SUPPORT 被拒绝。
- 网页人物页增加识别按钮、系统建议来源及确认/拒绝；没有引入另一套 Agent 事实库。

SUPPORT 已通过真实音频产品链路。另有 3 个**独立合成文字探针**实际返回 ADD、CONFLICT、CHANGE；
其记录在 `relation-text-probes-v1.json`。这些不是另三条音频端到端验收。
来源校验不等于语义完全正确：同义复述是否为同一次事件仍需审核；候选可能夸大稳定性。
本次 SUPPORT 应用保留旧的情境化表述，不直接采用新候选里的“稳定偏好”措辞。

## 本轮裁定及代价

1. 定位提示仅从原文取逐字片段，并保留全部授权材料，不新增一次推理调用。
   代价是增加输入长度且可能错误引导注意力；固定60题和改写题已实际暴露该风险。
2. 关系识别作为显式请求的后台任务，沿用云端授权；建议可自动生成，采用仍由本人确认。
   代价是多一次用户操作，尚未验证自动后台触发策略。
3. v7整批不优于历史v6，因此v6继续默认，v7仅为显式实验。
   代价是v6已知的遗漏仍未解决；不能把本次确定性安全修复写成问答质量已全部过关。
4. 独立审查覆盖代码与边界，不承担实际音频、模型和新账号验收；执行者依据真实调用与逐题记录另行核对。
   代价是仍可能漏掉语义错误，且未做人工听读，不能据此宣称生产可用或人格还原准确。

已完成一次独立终审和一次重要问题修复。剩余轻微问题暂缓：超长故事返回的
`notice`/`unavailable_episode_ids` 尚未在人物页展示专门提示，当前显示通用空态；
后端仍明确拒绝不安全或超预算材料，没有截断后伪装成功。

下一阶段先处理两类模型失败（结构化输出失败、错误主语/漏答），固定旧题和改写题复测，
再把本轮关系建议操作接入Android并进行设备验收；满足这些门槛前不以云部署代替质量验收。

## 复现入口

Python 环境需安装项目既有后端与AI依赖，密钥仅使用已有服务端被忽略配置。
本机后端8877、AI8879；先执行 `alembic upgrade head`，再运行 `services/backend/run_workbench.py`。

`tools/monthly_eval/ordinary_account_loop.py --run <新名称> --stage initial` 创建新测试账号并保存真实候选。
操作者阅读来源后显式指定 `--confirm-candidate <ID> --stage supplement`，再运行 `--stage relations`。
阅读建议后指定 `--confirm-update <ID> --stage remaining`，最后运行 `--stage verify` 与 `--stage questions`。
已有检查点成功步骤不会重放，失败/结果未知的写操作会停下要求先核对服务状态。

固定60题：`qa_round.py --round <新轮次> --recognition-run relay-compact --protocol <实际版本>`。
没有开启实验时不得将协议标签写成v7。原始答案、云端调用日志、逐题审阅均在ignored var保存，不提交密钥或本机账号。
