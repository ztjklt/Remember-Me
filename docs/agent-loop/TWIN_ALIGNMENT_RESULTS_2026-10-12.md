## 2. 与计划书的记忆分层对齐

1. **原始经历层**：录音、实际ASR、核对文字和Evidence。书面补充、亲友补记与本人原声保持来源区别。
2. **事实与故事关系层**：MemoryItem、GraphFact、NarrativeRecord、修订及历史；建立时间、关系、同事件和故事关联。当前使用关系数据库，不宣称已实现通用图数据库。
3. **人物理解层**：确认的ProfileCandidate及支持、反例、情境、变化；供人物页和Twin读取。旧PersonTrait仍有兼容用途，尚未完全统一为一种人物数据。

八个侧面和四个人物视图是上述材料的浏览投影，不是十二套事实库。Twin回答、模型审核意见、亲友提问不自动成为新的人物记忆。

RAG负责找到材料，后端负责判断能不能使用：先根据真实账号、空间、故事授权和有效性构造集合；检索器只返回ID、指纹和分数；本地重取原文，补齐同录音有效材料及已确认的关系。来源、授权或人物理解在调用中变化时返回SOURCE_CHANGED。不跨模型调用持有数据库写锁。

反例不可见不能只留下支持结论；纠正失效原文不能因全文或检索而复活。完整上下文超过24,000字符或256项来源时明确失败，不截掉后半句。详见 [三层与RAG合同](../architecture/rag-memory-layers-20261012.md) 和 [Twin兼容接口](../architecture/twin-review-rag-contract-20261012.md)。

## 3. 最终判决规则

这里有两种判决：**运行时是否交付某句话**，以及**验收时这题表现是否合格**。它们不互相替代，HTTP 200也不等于答对。

| 检查 | 判决方式 |
|---|---|
| 来源和权限 | 程序核对引用ID、逐字引文、作者、许可、当前版本和预算。越权、过期、假引文必须阻止。 |
| 每个回答要点 | 模型检查所引材料是否支持完整意思，保留否定、时间、人物、范围和必要条件。正确的独立要点保留；无据、语义不确定的点及依赖它的点删除。 |
| 漏答 | 单独记partial，并指出尚未回答；不把已正确回答的事实判错。partial不计为整题全部合格。 |
| 正确未知 | 材料确实没提供事实、未来决定或本人新态度时，可以UNKNOWN且通过这部分验收。已知部分仍要回答。 |
| 程序/模型故障 | 格式失败、检索不可用、超时或整答被否决时明确失败，不能伪装成UNKNOWN。 |
| 表达质量 | 重复、略啰嗦、措辞不自然与事实错误分开记录；不因文字与参考答案不完全相同就否决同义正确答案。 |
| 改变意思的遗漏 | 截掉“不”、把“有时”写成“一直”、忽略关键反例、把女儿观点变成本人态度，属于内容错误，不是普通漏答。 |
| 原文与模拟 | “他确实说过”核对文字与归属；“如果参考他的做法”核对已确认条件性理解。模拟不能产生新经历、关系、承诺或本人现在的决定。 |

程序和模型看同一个最终呈现视图，避免模型只看不含署名的草稿而误判。唯一新增姓名例外是所选补记的**完整作者名**可以只在程序署名前缀出现；其他人名仍需正文和实际所引材料支持。全文某处存在同名，不能证明当前人物指代正确。

运行时先生成，再做一次语义审阅；不会反复询问直到得到“通过”。暂时性传输错误或结构修正受现有90秒总预算、单次45秒、最多3次请求限制。审核本身可能错，开发验收另外查看实际答文与来源。

界面只保留AI分身、相关故事、必要的部分未回答提示，不显示审核理由、指纹、业务ID或“技术复核通过”。`coverage=complete`只表示问题各部分已处理，不是事实真值认证，也不是人格准确率。

## 4. 为什么此前没有全量验收

具体责任已经拆开，不能把全部失败归为“模型不聪明”：

- **程序误拦**：v7署名原文题中作者已经由程序展示，但机械规则要求它还得在引文正文出现。v8修复了这个可复现错误，保留其他姓名检查。
- **审阅视图不一致**：v6审核看裸草稿，把实际已有署名判成没有；v7让它审同一渲染器输出。
- **部署依赖遗漏**：v6本地RAG真实请求失败，因为A01环境未安装项目已有检索依赖。已补装并使用既有固定版本中文BGE缓存，真实路径重跑成功。
- **生成/选证问题未完**：朋友与孩子的表达差异题，模型没有把姓名与所述事实的引用链选对；结构修正后仍未交付。不将它宣称为事实答错，也不降低人物归属约束来算通过。
- **语义审核漏检**：v6私密故事题用未知加了一句不相关公开原话，虽没发现实际私密原文泄漏，仍不合格。v7针对相关性修复后该题返回UNKNOWN。
- **呈现问题仍有**：v8署名题同一整段重复两次；这是重复和阅读负担，不应错误统计为两次事实错误。

## 7. 剩余问题与下一步

1. **姓名与事实的选证**：先解决L05的指代链，再冻结版本完整回跑历史集；既不能自动同名合并，也不能把漏选引用归结为人格理解全错。
2. **表达重复与延迟**：全文摘录不该同段重复，人物详情同文来源也需合并展示；本地检索首次加载和两次LLM往返较慢，应单独优化，不能取消必要条件核对来换速度。
3. **记忆持续更新**：跨批支持/例外完整归并、同事件复述去重、只使受影响理解过期仍需推进；现有全局版本变化可能使无关理解过期。
4. **外部RAG**：待队友提供真实接口、鉴权、索引更新与撤回协议后接适配层；目前不能只填一个URL就承诺接通。
5. **交付环境**：本地r2融合已经构建，ECS、实体Android、iOS和真人声音认可分别验收；本地实测阶段没有推送或部署，后续团队交接单独记录。

此轮结论：三层材料向Twin的接线、可选本地RAG、逐项审核和右侧交互融合已经有可运行实现及实际样例；**全部语义质量、跨端部署与完整人格效果仍未验收**。
