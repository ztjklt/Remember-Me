| API | 登录、上传、核对、故事/来源读取、邀请批准、撤权和手机接口。 |
| worker | 持久化任务、调用Paraformer转写、等待核对后调用记忆整理，失败保留原音。 |
| AI Core | 调用现有微信DeepSeek，执行结构/证据校验、问答及人物归纳逻辑。服务器不安装大模型权重。 |
| profile worker | 处理人物理解候选及更新，保留来源与审核状态。 |

PostgreSQL保存账号、故事、证据、授权、修订和任务状态，原音存储保留音频。Android录音与展示通过原IP HTTPS访问；模型密钥仍只在服务端。不会顺带开启公众注册、扩大安全组或部署iOS应用。

## 5. 除了题目对错，还发现的产品问题

| 问题 | 实际依据与影响 | 后续处理边界 |
|---|---|---|
| 答案过长 | 有些“谁/在哪里”的问题返回两三段原文，需用户自行找重点。内容受支持不等于好读。 | 保留可展开原文，另做受证据约束的短答；不能先无校验改写来追求流畅。 |
| 人名识别遗留 | 历史转写中有梁舒/梁叔、许雁/许燕、呈贡/成贡。 | 使用现有核对与用词入口，由本人修正；不依据评测标准答案自动写回。 |
| 生成等待与全局忙状态 | 手机提问期间多项操作由同一busy状态禁用，慢请求影响浏览和退出体验。 | 后续把网络任务状态与浏览/播放解耦，并保留退出后迟到响应清理；当前不把等待时长伪装成准确进度。 |
| 首页层级偏重 | 已存模拟器截图中，测试身份长名称、身份按钮和原音播放器占据首页上半部，开始录音需要往下看。 | 测试名称清楚标虚构即可，正式显示精简；播放器改为可展开的紧凑控制，核心录音入口前置。当前冻结APK不含这轮布局优化。 |
| 人物视图仍依赖材料与本人核对 | 云端实际生成3候选、4建议；只技术确认一条情境化观察后，另外两个视图可以为空。 | 不以填满四张卡片为目标；确认入口要让本人看懂条件与例外，不能把候选数量当理解程度。 |
| 运行恢复有明确规模边界 | PostgreSQL空闲任务死锁已修复；profile进程启动恢复仍按单worker设计。 | 本次只启用一个profile worker；增加多实例前先实现租约与故障回收，不能直接横向复制进程。 |

以上将程序正确性、语义质量和使用体验分开记录；问答门槛通过也不会把这些项目自动变成通过。
