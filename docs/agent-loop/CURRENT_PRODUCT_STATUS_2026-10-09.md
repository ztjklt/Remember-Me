## 三条链路不能混为一谈

1. **历史 Android 模拟器链路已经实测**：原生录音/播放 → PC 上的后端调用 Groq → App 核对和书面补充 → 微信 DeepSeek → 保存记忆 → App 来源问答。音源是小米虚构合成语音注入虚拟麦克风，不是真人/实体手机测试。历史 APK 属于这条路线；新 IP 版见第 3 项。
2. **新客户端 ASR 链路已经ECS实测**：电脑工具调用 Groq → 经SSH转发的已验证HTTPS上传原音+机器稿 → ECS等待核对 → 真实微信处理 → PostgreSQL保存 → 来源问答与独立读者授权/撤权。服务器不再调用ASR。历史本机SQLite小样为4记忆、3候选；ECS初始小样为4记忆、2候选，后续7段完整结果见新报告，不混用计数。
3. **Android 公网业务连接已验证，ASR 尚需电脑**：IP 版 App 不经 SSH/ADB 即可登录 ECS、看故事、播放原音及提问；仍限已授权网络出口，免文件搬运的 ASR 和实体手机尚待完成。

## Agent 与原先概念的对应

不是八个记忆Agent加四个画像Agent。当前是共享证据与事实存储，加记忆整理、人物候选/关系任务、在线问答及校准；保留职责，不为凑数增加模型对话。

“八大记忆”没有按八套独立数据库原样实现；当前以现有类型、上下文、人物领域组织。“四个画像”有四视角基础，但人生时间线、人物关系、选择情境及表达特点的完整产品体验没有全部做完。不能把有分类页面等同于已经实现数字人格。
