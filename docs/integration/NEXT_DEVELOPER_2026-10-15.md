# UI 对齐、补交材料与下一位开发者任务

## 1. iOS 需要补交的最小包

不是让队友上传整个电脑目录，只需把实际构建所用的以下内容提交到清楚命名的分支，并给出 commit SHA：

- 最新 Swift 源码：登录/空间、录音库、LiveKit 通话、声音登记/匹配状态、人物模型、托付页面。
- `RMDesignTokens.swift`、`ForgetMeNotFlower.swift`、`Shared/RecordingActivityPresentation.swift` 及相关 Assets；当前声纹分支只有旧版客户端。
- Xcode 工程或可重建的 `project.yml`、Package.resolved/其他依赖锁、entitlements、Info.plist、主 App 和 ActivityKit 扩展 target；签名 team 的配置方式，**不提交私钥/描述文件/登录凭据**。
- Soundcore SDK 的合法获取与本地放置步骤、精确版本/依赖；专有二进制不因为了交接就公开复制。
- 手机版本/构建号、对应后端 release 和地址、功能开关、已通过/未通过任务。
- 声纹 bug 最短记录：哪个账号/空间、先点什么、说了多长、是否首次登记、屏幕提示、时间、能否继续聊天、有没有误写到本人记忆。私密原音/向量/Key 不发公开 Issue。

当前仓库说明最新签名安装为 1.13.1，但不能从当前 `apps/ios` 重建这个版本；应先解决交付缺口再宣称 UI 已同步。PR #90 的旧客户端增量也应保留比较，不能被最新后端分支中的旧 `apps/ios` 覆盖。

## 2. UI 统一的是用户任务和风格，不是互拷组件

Android Compose 与 iOS SwiftUI 保留各自平台实现。先统一下表语义，再对齐间距/颜色/动效；用户截图是设计要求，旧网页和未接真实数据的漂亮原型不能作为已经装进 App 的证据。

| 页面 | Android 当前入口/结构 | iOS 对齐要求 |
|---|---|---|
| 今天 | 讲一段、继续整理、我的录音；补问可展开 | 一眼知道如何开始，上传/整理确认在对应步骤 |
| 档案 | 花田/人物主入口；全部录音次级入口；亲友内容有入口 | 尚未整理的录音仍能找到，不能只有花朵才找得到原音 |
| 花田 | 人物空间→故事花簇→花瓣内容→依据/原音；列表/查找可替换 | 真数据、固定位置、返回原位；背景花不能冒充故事数量 |
| 人物 | 已确认理解横向浏览；了解这个人/记忆侧面分段；四视图/八侧面 | 先内容后分类，有条件与例外；不要再堆一屏分类数字 |
| 对话 | 查找记录/与 AI 分身聊聊；语音聊聊 | 原音和生成声音按钮分开；是否保存聊天讲清楚 |
| 我的 | 主题、简明模式、权限、账号、待处理/分享、数据与帮助 | 平台权限用系统入口；退出与切空间清理旧内容 |
| 简明模式 | 核心任务：讲一段、听故事、聊一聊 | 管理与审核进入次级页面；不靠把全页字体放大来适老化 |

Android 设计基线可复用的值（来自 `core/designsystem/Theme.kt`）：

| token | 浅色 | 深色 |
|---|---|---|
| 主色 | `#355C43` | `#B5D4BA` |
| 背景 | `#F4F5EC` | `#14251E` |
| 阅读表面 | `#FAFBF6` | `#21372B` |
| 正文 | `#233C31` | `#EEF3E9` |
| 次级文字 | `#496052` | `#B7CABB` |

间距 4/8/16/24/32/48dp，基础圆角 8/16/24dp；具体内容组件另有局部圆角，不必机械统一成一个值。iOS 文档描述的新版纸色/蓝色/五瓣花与 Android 自然苔绿方案有差异；**先拿到真实组件与当前截图，再由队伍选定最终基线**，此表不是擅自宣布必须把 iOS 全部改绿。

约束：小按钮有清楚可点击区域与语义；支持返回、100%/200%字号重排、浅深色、减少动态效果；长文稳定背景；不恢复已经取消的双指缩放工具条。日常页面仅保留“AI分身、本人原话、待核对、仅自己可见”等必要短标签；“技术复核、来源指纹、分类不代表准确率”等说明留在帮助/验收文档，不铺成小字。

## 3. 推荐演示路径与失败后的退路

使用[下载与账号说明](../agent-loop/ANDROID_0121_QUICK_START_2026-10-15.md)，不要下载 Actions debug 包。公开演示账号只放虚构材料。

| 顺序 | 要演示的价值 | 现场操作 | 若失败 |
|---|---|---|---|
| 1 | 原音确实留下 | 本人“讲一段”20–30秒，保存并试听 | 原音留在录音库，先不重复录/卸载 |
| 2 | 自动纠错可核对 | 转文字→查看修改→确认整理 | 模型忙时保留原稿，从该阶段重试；可使用已有纠错样例说明 |
| 3 | 记忆能被探索 | 花田→故事→花瓣→原音→返回 | 列表/全部录音是同一资料的替代入口 |
| 4 | 理解有条件 | 人物→具体理解→条件和来源 | 读者看不到时检查授权，不假补一张卡片 |
| 5 | 内容会更新 | 纠错样例问“杯子现在每天喝茶用吗”→展示新依据 | 模型调用失败与不知道分开，展示保存的来源 |
| 6 | 能连续交流 | 陈守义账号进入语音聊聊，说公交→插话喝茶→追问浓淡 | 保留实际等待；故障时结束重连/回文字，不假播放预写答案 |
| 7 | 亲友可独立进入 | 两个会话邀请领取→本人批准→播放→撤权 | 不共用 owner 身份冒充亲友 |

声纹、录音豆、iOS 真机问题单列演示，不将 Android 当前没有的入口讲成已实现。若使用已有视频，清楚说是同日云端实跑录像，等待没有加速。

## 4. 明天现场的最短检查表

- 两部手机的 App 版本、服务器 release、账号和人物空间拍在同一张记录表里。
- 每端分别走一次手机麦克风→上传→核对→记忆→原音，不跨手机或电脑代跑其中一步。
- iOS 普通通话先用默认音色验证，声纹/复刻逐项开启；把“不能聊天”和“没入库”分开记录。
- 用不同账号查看同一故事的授权结果，再试撤权；未播放完被打断的句子不算已听见。
- 只改一个模块，再复跑同题；记录原始失败，不只留最好的一次。
- 写明实机/模拟器、真模型/fixture、已部署/仅代码，以及未通过项；这份技术记录不塞进产品首页。
