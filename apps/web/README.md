# 勿忘我 Web 体验

这个客户端复用现有 ECS 后端。`client/` 提供对齐 Android 的花田、人物和对话界面；录音、导入、核对等管理操作继续复用 `services/backend/app/workbench`。没有复制数据库、启动另一套模型、修改 Android / iOS 或发布到云平台。

**0.2.0：默认体验只有陈守义。** `/app/` 通过服务端配置的精确 subject ID 读取当前独立陈守义演示空间；不按姓名或空间列表第一项猜测。旧账号的录音与记忆没有被删除。已确认理解与提取记忆分别标注，未确认候选不显示为人物结论。

## 本机启动

需要 Node.js 22 或以上，无第三方 npm 依赖。Windows 在此目录运行：

```powershell
./start-local.ps1 -Demo
```

打开 <http://127.0.0.1:8770/>。`-Demo` 从仓库外 `../chen-demo-20261017/demo-account.private.json` 读取已存在的陈守义独立账号，也可传 `-DemoAccountFile <绝对路径>`。文件内容仅进入当前服务进程环境，不写入浏览器或构建产物。私有本地演示强制 loopback 绑定。去掉 `-Demo` 则使用普通工作台登录；不回退到旧花田/亲友账号。

也可以：

```sh
node build.mjs
node --env-file-if-exists=.env server.mjs
```

以 `.env.example` 为配置示例。默认回环地址监听；网关通过 Node 原生 HTTPS 直连后端，不继承 HTTP_PROXY / HTTPS_PROXY，不关闭 VPN，不跳过证书验证。当前 IP 测试证书来自 Android 仓库内已跟踪的公开证书。它并非永久的生产证书；后端换证时更新 CA 配置。

## 这版能做什么

- 一键进入当前陈守义空间；普通账号登录保留在工作台管理入口。
- 沿花径点花、点读花瓣、分页/列表阅读、精确文本搜索、来源与授权原音回听。
- 人物页显示四视角、八侧面、已确认理解轮播与支持/例外依据；卡片可左右滑动或用按钮翻页。
- 事实问答和生成式陪伴保留本页逐轮消息、回答类型及依据。会话不落盘；当前 HTTP 接口每次独立提问，不能据此宣称已实现连续语音或上下文会话。
- 语音回答按钮仅在当前后端声音配置允许时出现。当前陈守义连续语音使用 App 专用通道，HTTP voice/profile 未开放合成，网页不显示伪可用的通话/播报按钮。
- 浏览器前台录音 / 音频文件导入，云端转写、本人核对、整理，保留各步授权。
- 使用现有“陪伴与亲友”页面，查看亲友补记、专属信和只读版本的已实现功能。
- 手机底部导航、桌面适配、manifest、主屏幕入口。PWA 的安装菜单因浏览器而异，不能当成已完成真机安装验收。

本版没有接 Android 的录音豆 SDK、后台持续采集、PCM 连续语音通话，也不自动复现原生花田的全部镜头效果。WebSocket 不能像 Android 一样自由设置 Authorization 请求头；实时语音需后续实现受控的服务端 WSS 桥接及 WebAudio 输入输出，不能把 token 放 URL 来绕过。

## 同步方式

1. **业务数据**：始终使用同一后端、同一账号及权限。App 新增并处理完成的数据在 Web 刷新后可见；Web 修改也会影响同一账号的 App。换成独立 iOS CloudBase 后端不是换一个 URL 就能兼容。
2. **业务逻辑**：ASR、AI、记忆、人物、授权、版本失效继续在后端维护一份。工作台管理脚本直接从现有源文件构建；新客户端只投影服务端数据。恢复前台（超过 15 秒）、手动同步及前台每 60 秒重新取数，并重验已展示回答；失败会清空旧内容，避免继续展示失效来源。
3. **网页版本**：运行 `node build.mjs`；`node build.mjs --check` 检测源文件是否已变化。构建从 Android `MemoryMap.kt` 提取四视角/八侧面文案与映射，直接复制原生花形、藤蔓、场景资源。`GardenProjection.kt` 哈希变化会阻止构建，要求核对 `client/model.js` 和隔离测试后更新 `native-compat.json`。`dist/build-info.json` 记录 Git SHA、源文件 SHA-256、构建时间和产物哈希。未提交改动以文件哈希为准。
4. **新增原生交互**：Kotlin / Swift 界面不会自动变成网页。新增 API 字段后先保持旧客户端兼容，再补网页对应操作。不要自动部署未验收开发版。

## 后端兼容与安全边界

浏览器 → 同源 Web 服务 → 固定 ECS 后端。浏览器持有 HttpOnly 会话 Cookie；网关先严格验证 Host、Origin 与跨站来源，再将自己的会话 Cookie 转为后端已支持的 Bearer 请求，避免现有反向代理的 Origin / Host 差异。不转发其他 Cookie，不转发用户提供的目标地址，不设置开放 CORS，不关闭后端权限判断。原始接口请求和授权失败原样返回。

所有身份/故事/音频 API 响应 `no-store`；Service Worker 仅提供导航断网提示，不缓存私密数据。当前沿用后端 30 天会话策略。退出调用后端撤销当前凭据。公共网关集中转发会共享后端的 IP 限流，规模化开放前需要评估限流和并发；演示入口另有每来源 5 分钟最多 8 次登录限制。

## 以后部署

现在只本机运行，尚未部署 Launch。可使用任何支持 Node / Docker 与 HTTPS 的托管服务：

```sh
node build.mjs
node package-release.mjs
# 进入上一步打印的 release/<版本> 目录，这是经过白名单组装的构建上下文
docker build -t remember-me-web .
```

容器端口 `8000`，健康检查 `/healthz`，反向代理须保留公开域名的 Host。运行时设置 `WEB_PUBLIC_ORIGIN=https://实际域名`，并按需要设置服务端演示账号、后端地址、证书和安装包 URL；不能把真实密码写进 HTML 或镜像。部署包只包含客户端、网关、公开证书和空配置示例。Dockerfile 使用 AWS ECR 公共 Node 镜像，尚未在本机/Launch 实际构建或验收。

先测试 HTTPS、域名 Host、后端出网、Cookie、上传限制和麦克风，再交付公网链接。手机麦克风需要 HTTPS 或本机安全上下文；电脑上的 `127.0.0.1` 链接不能直接给评委手机使用。APK URL 未确认时界面不显示虚假的下载入口。
