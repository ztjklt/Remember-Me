> 以下保留 v1 分析背景。当前 v2 已用独立陈守义账号替代旧双账号入口，增加 `client/` 原生风格花田、四视角/八侧面人物阅读与逐轮文字对话；录音管理仍复用原工作台。当前实施及同步方式以 [README](README.md) 为准。没有删除旧账号材料，也没有部署或修改云端服务。

## 结论

可以复用现有后端先做真实 Web 体验。当前分支 `codex/work3200-device-20261016` 在分析时为 `fbbab928bf1c`，公网 `/api/v1/service-info` 返回 API `0.7.0`、release `9f70117ee6ae0ad27e8910cfb753a640169018e5`、注册关闭。代码提交与云端发布不同，不能把本地所有能力当成已上线。

不是从 Android Kotlin 页面自动转换：仓库本来就有真实网页业务客户端 `services/backend/app/workbench`，与只有固定样例的 `docs/mobile-ui/prototype.html` 不同。本版复用前者的 `app.js / companion.js / narrative.js / live-garden.js`，构建时复制并记录哈希；使用现有品牌植物素材，没有将静态原型数据混入真实账号。

## 需要改哪些地方

| 项目 | 当前代码证据 | 本版处理 |
|---|---|---|
| 运行入口 | `app/main.py` 把工作台挂在后端 `/workbench` | 新增 `apps/web`，可独立运行前端及轻量网关，后端保持原位 |
| 登录与会话 | `api/accounts.py` 返回 HttpOnly Cookie 与可撤销 actor token；`security.py` 校验权限与 cookie 来源 | 浏览器严格同源；网关检查 Host/Origin 后，把会话 Cookie 转为既有 Bearer 协议，密钥不进网页 |
| 现有代理差异 | 实际向公网登录发送公网 Origin 得到 422“请求来源与服务地址不一致” | 不修改生产代理，使用后端本就支持的原生客户端认证方式；不能靠 `Access-Control-Allow-Origin:*` 或关 TLS 修复 |
| TLS | Android 内置 IP 测试证书 | 网关只信任配置的后端 CA，浏览器以后用部署域名的正常 HTTPS；本机回环预览不弹证书警告 |
| 无需安装的体验入口 | 后端目前关闭自助注册 | 服务端可配置公开虚构账号的一键登录，提供亲友样例与独立练习空间；普通账号仍可登录 |
| 手机使用感 | 工作台已有网页表单，原生 UI 是另外的实现 | 加移动底栏、响应布局、主屏幕 manifest / 图标 / 安装说明；保留实际业务控件 |
| 文件导入 | 老工作台把非 MP4 文件一律命名为 webm | 修正共享网页脚本，保留导入文件名；录制文件按 MIME 选择扩展名；没有更改上传合同 |
| 故事 / 人物 / 问答 | workbench / narrative / companion / twin 已有接口 | 直接复用，权限、来源、候选确认、撤权继续由后端决定 |
| 录音转写 | MediaRecorder + multipart Episode + transcript-review | 保留既有上传、转写、核对、整理链。麦克风必须在安全上下文并经用户许可；本轮先用合成文件验证链路 |
| 自动校对 | 后端已有机器稿、纠错记录；原生端提供更多稿本对照 | Web 当前保留机器稿与可编辑核对文本，尚未做到 Android 所有逐项纠错控件同等体验 |
| 连续语音 | Android WSS 通过 Authorization header、PCM 输入、轮次与实际播放回报 | 暂未迁移。浏览器需受控 WSS 网关 + WebAudio 采集/重采样/播放/中断；不能简单把 native WebSocket URL 放进页面 |
| 录音豆 / 后台采集 | Android SDK、权限、前台服务 | 不迁入首版；浏览器前台录音不能视为原生后台采集等价物 |
| 安装包 | APK 已有独立发布流程，候选版本仍在更新 | 通过 `WEB_APK_URL` 配置已确认的链接；不把 APK 当成可在普通网页里运行的程序 |

## “网页里的 App”有哪些选择

1. **当前路线：响应式 Web / PWA**。链接直接打开；支持的浏览器可添加主屏幕，以独立窗口使用。同一后端，同一数据。视觉与操作可以接近 App，但系统级蓝牙、后台任务、声学行为不同。
2. **WebView / Capacitor 壳**。以后可把 Web 装进安装包，但只是包装这个 Web 客户端，不能自动继承已有 Kotlin 功能，商店发布与原生权限仍需维护。
3. **云手机 / 远程 Android 画面**。实际上运行 APK 并把画面传到浏览器，可以展示原生界面；多人需要独立实例、账号与录音通道，还会增加延迟和资源成本。本次没有实现，现阶段也不作为默认体验路线。

用户已决定先做 Web、部署平台以后再定，因此本版没有访问或修改 Launch，也没有云发布、服务器迁移或 Git 推送。若继续 Launch，使用已核实的 Dockerfile/ZIP 云托管入口；它部署的是 Web 服务，不是把 APK 变成网页。

## 后续同步的实际含义

```text
Android ──────────────┐
                      ├─ 现有 ECS Backend ─ PostgreSQL / 原音 / 任务 / AI Core
浏览器 ─ Web 网关 ────┘
```

- **共享数据库，不搬业务数据**：同一账号、Subject 与权限下，原生端的新记录处理完成后刷新 Web 可见。还没上传的手机本地录音不会自动出现。
- **服务逻辑统一**：后端发布后，兼容旧合同的规则更新自然生效。新的界面功能仍需有对应 Web 控件。
- **源代码同步**：拉取团队认可的版本后重建；构建哈希检查确保没有忘记更新网页产物。部署时固定 release，不追着开发分支自动上线。
- **协议边界**：Android ECS 与 iOS CloudBase 当前分叉，账号/存储/声音传输也不同。本版针对 ECS；不宣称两套服务已统一。
- **测试边界**：网关/页面联调、合成音频文件的真实处理、实体手机麦克风、真机安装与公网部署分别记录。前两项通过不能替代后三项。
