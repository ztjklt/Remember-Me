# iOS 移动 UI 对齐

基线：PR #77，`e146ac56f080299676fed40653394b97a37bd270`；本地分支 `codex/ios-ui-alignment`。本次没有修改 `Network.swift`、Backend Contract、供应商 SDK 或共享后端。

## 已实现

- 原生 TabView 改为“今天 / 档案 / 对话 / 我的”；录音与记忆在档案内分段，支持对已加载内容的本地文字筛选。
- 七组语义色以 Color Assets 的 Any / Dark 形式提供；取消强制浅色。固定字号改为系统可缩放文字样式，正文稳定实色。
- 首页保留真实问题能力，补上真实最近三段录音；录音改为独立全屏流程，底部固定暂停 / 保存 / 核对操作。
- 录音波形按可用宽度计算，暂停不再更新电平；按压缩放与波形插值在减少动态时停用。
- 共用真实播放器，支持暂停 / 继续、当前位置、时长与定位；停止原播放器后才开始新播放或录音。异步下载的旧请求不能在新录音开始后突然发声。
- 进入后台完成并保存主录音、停止播放；主动关闭主录音会询问保存或继续。
- 核对草稿按 Episode 保存在本机，刷新处理状态不会覆盖用户正在核对的文字；整理前再次说明发送对象并确认。
- 来源类型显示“本人叙述 / 他人提供 / AI 推测 / 来源待核对”；工程版本信息折叠。纠正 / 删除失败不自动离开详情；删除成功立即更新当前列表和搜索结果，保留原音。
- Twin、校准、记忆纠正与独立声音授权入口保持可访问；个人声音与授权管理移入“我的”后仍复用原有能力。

## 保持的现有语义

iOS 仍然先把录音交给已配对的 Mac 转写，确认文字后才由原服务链路整理。这里的“转成文字”不会被错误描述为 iPhone 本机 ASR。

原有单个待提交录音机制保留：存在待处理录音时，录音界面会继续该记录，不静默覆盖它。远端档案仍依赖配对服务；本轮没有新增离线同步引擎、多个待提交录音队列或替换授权模型。

系统导航材质交给 SwiftUI / iOS；没有强行绘制自定义玻璃，也没有加入需要新系统才存在的 Glass API。实际 Liquid Glass 效果需在对应 SDK / 系统上编译验证。

## 验证边界

Windows 当前环境没有 Xcode，**尚未完成 SwiftUI 类型检查、模拟器构建或真机运行**。四个 Swift 文件通过 tree-sitter-swift 语法解析；七组颜色资源完成 JSON 与浅深色数值核对。语法解析不等价于编译通过。

在 Mac 上执行：

```sh
cd apps/ios
xcodebuild -project RememberMe.xcodeproj -scheme RememberMe \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

随后检查 375 / 430 pt、普通及约 200% 字号、浅深色、减少动态 / 透明度、VoiceOver；再连接配对服务检查录音、后台保存、核对授权、真实播放、删除和纠正。现有 Twin、声音与校准流程也要回归，不能只验首页。

完整设计原型和 Android 测试包在另一条基于 #78 的 `codex/mobile-ui-core` 分支 `docs/mobile-ui/`。两条分支基线不同，应分别审阅；不要为了对齐 UI 整体互相合并。
