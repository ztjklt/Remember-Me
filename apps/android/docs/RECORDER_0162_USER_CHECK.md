# 录音豆实机验证 · 0.16.2

## 官方操作

- 开始：按下录音豆侧面的自锁实体录音按钮，橙色指示灯亮起。
- 标重点：在录音过程中，快速轻敲录音豆机身触控区两下；感到轻微振动后松手。操作的是机身触控区，不是把侧面的录音按钮连续按两次。
- 结束：再按一次实体录音按钮，让按钮弹起，橙灯熄灭。
- 暂停/继续是 App 内的操作；实体录音按钮用于开始/结束。

核对日期：2026-10-16。来源：[soundcore 官方录音说明](https://service.soundcore.com/article-description/How-do-I-use-the-recording-feature-on-soundcore-Work)、[Anker Japan 官方 Work 操作说明](https://www.ankerjapan.com/pages/soundcore-work)、[soundcore 官方产品页的 Double Tap 说明](https://www.soundcore.com/uk/products/d3200-soundcore-work-ai-voice-recorder)。官方 App 的云端摘要能力不等于第三方 SDK 自动包含这些能力；下表是勿忘我自己的处理流程。

## 一次 30 秒验证

覆盖安装后打开勿忘我，进入正确的人物空间，首页选“录音豆”。首次测试保持 App 前台、手机在录音豆附近并联网。

| 步骤 | 你的操作 | 手机应出现的结果 |
| --- | --- | --- |
| 1. 连接 | 打开“设备”或“连接”，选中自己的录音豆；未绑定时按页面提示把设备放入盒中、闪灯时按盒上按钮 | “已连接”、真实电量、剩余空间条/百分比。未读到的数据为 — |
| 2. 开始 | 按下侧面实体录音按钮，确认橙灯亮 | 首页“正在录音”，计时持续增加；提示“双敲机身标重点” |
| 3. 标记 | 大约第 10 秒说“这段是我希望保留的重点：下周和家人去公园”，同时双敲机身触控区，等到振动 | “已收到重点标记”；有可靠时间信息后显示设备重点数量。录音继续，不能因标记而结束 |
| 4. 结束 | 约 30 秒时再次按实体按钮，确认按钮弹起、橙灯灭 | 自动呈现“收到录音，正在同步”和真实进度；若设备弹窗仍开着，应自动收起 |
| 5. 自动转写 | 等待，无需点试听或上传 | 同步及音频准备后显示上传/转文字状态，再自动出现“录音文字”可编辑正文 |
| 6. 看重点 | 点“设备重点 1”等入口 | 独立详情展示如“00:10.xxx · 附近文字”。该时间应接近标记时刻，附近文字应包含测试重点或其上下文；关闭后仍回到原草稿 |
| 7. 保存 | 修改识别错误，必要时补充信息，点一次“保存到记忆” | 自动显示“已保存，正在整理记忆”，无需额外滑动或点击触发 |
| 8. 查看结果 | 等待整理结束 | “已加入记忆”及记忆内容；可打开这条记忆，也可从“档案”找到这次录音 |

不要为了通过测试而在手机上补点标记。若设备振动但 App 未收到、时间明显不符或文字无关，这一环应记为未通过；保留原音，通过设备页“连接遇到问题？”导出记录供排查。

## “时间”和“文字”分别意味着什么

设备标记时间来自 SDK 毫秒列表，或由 SDK 标记音频片段与完整原音的唯一匹配确定。不会用手机触摸时间或回调到达时间充当设备时间。

“附近文字”使用 ASR 句子时间段，当前关联窗口是标记前 10 秒至后 5 秒；句子与该窗口有交集时显示完整句子，因此可能覆盖更长上下文。只有能在当前转写中唯一找到的句子才关联。这不是逐字级对齐，也不是自动识别说话重音。修改文字后不能沿用不可靠对应，保存后重新匹配。

无可靠位置时显示“设备重点待定位”；已知时间但文字无法安全关联时显示“时间已定位，文字暂未对应”。离线旧录音缺少标记片段且 SDK 没有返回时间列表时，不能保证恢复位置。已对应的重点继续作为记忆整理的关注提示；它不提高事实可信度，不修改模型参数。

## 这一轮界面取舍

设备弹窗只保留一行状态、当前录音状态、按需展开的录音列表/维护/排查；移除重复标题、重复计时说明、默认传输通道、校验摘要和重复成功通知。关闭按钮固定在标题旁。

首页录音中不再夹带旧草稿、旧记忆或话题建议；转写草稿只保留正文、保存及三个次要入口。重点详情单独展示，不挤占正文和保存按钮；长上下文按需展开。记忆完成后隐藏后台累计分析成功提示，异常仍可见，后台分析照常执行。

测试截图采用模拟器、模拟 SDK 事件或虚构合成语音，不能冒充 vivo 实物证据。最终签名包的验证结果以同版验收记录为准。
