# 0.16.1 录音体验修正

这轮按实物反馈修正三处体验：设备页的一行状态、重点来源与时间、处理流程自动呈现。

## 设备状态

设备页原来的设备名/电量固件/容量/来源解释四行，改为一行“已连接 · 电量 · 剩余空间进度条/百分比”。电量与空间仍来自 SDK 回调；未知值显示 —。固件放到展开的设备维护里。

## 重点的事实来源

实测反馈中 64.16 秒的录音有 31 个标记，服务端元数据全部为 `origin=phone`；并非 SDK 返回了 31 个重点。新版录音豆界面取消手机“标记重点”按钮，监听设备标记。旧数据保留为“手机补充”，不改写为设备标记。

官方集成文档提供 `isMark`、`onTransferFileStatusChanged.markTimeStampList` 和 `onDecodeFileMarkers`。本机 1.3.02 AAR 检查发现：D3200 文件完成路径传入空列表；DecodeAudioFileManager.decodeInOrder 仅回调文件成功，没有生成标记时间。所以只等待文档所写的最终数组，可能一直拿不到实际时间。

适配方式：保留 SDK 标记的实际音频片段 SHA-256 指纹；下载并解码校验完整原音后，在真实 160 字节、20 毫秒 Opus 帧中寻找唯一匹配，确定文件偏移。连续被标记的帧合为一段；重传去重。设备直接给出的毫秒列表继续接收。不会用手机按钮时间、回调到达时刻、未经证实的包序号换算来冒充位置。缺失/重复帧或格式不匹配时不猜测时间。

指纹和信号按账号、人物、设备、文件隔离落盘，解析完成才提交自动转写。云端返回设备/手机分别计数、时间点和对应文字；已有 AI 重点处理继续只使用可靠对应的文字。

SDK 标记表示设备发来的重点标志，不等于自动识别语气重读。这版不会凭音量或“重点”字样虚构设备标记。没有可靠位置时显示“设备重点待定位”；无实时片段且 SDK 未返回时间列表的旧离线录音，仍可能无法恢复时间。

## 自动呈现

录音结束进入同步、文字草稿出现、保存进入记忆整理时，自动收起设备弹窗、收起键盘并回到当前流程顶部。接到新录音时自动回首页。阶段不变时不会因为计时、字节进度或后台轮询反复滚动；编辑中的文字不会被刷新重置。移除设备页遗留的“确认上传”提示。

原音、既有记忆与旧手机标记保留。此版沿用原签名，可直接覆盖安装，无需 USB。测试截图必须注明模拟器和模拟 SDK/虚构语音来源，不能替代 vivo 实物标记验收。
