# 0.16.0：录完自动出文字，保存后进入记忆

## 使用方式

1. 首页选择录音豆，第一次点“连接”；连接参数与维护功能都在“设备”里。
2. 用录音豆实体按钮开始/结束。首页显示录音状态、时间和重点。
3. 结束后自动下载、校验、解码、上传、转写。无需试听或再次确认转写。手机录音完成后也进入同一流程。
4. 首页直接出现文字草稿。可以改字、点“补充信息”，也可以不改。编辑自动存到本机；机器转写已保存在服务器。
5. 点一次“保存到记忆”。服务器整理当前这一段，再结合已有有效材料生成累计人物观察。首页可打开刚保存的这条记忆；完整记录在“档案”。

## 与 0.15.2 的区别

| 之前的断点 | 本版处理 |
| --- | --- |
| 音频到手机后还要试听、勾选、点上传 | 新录音持久排队，自动上传转写；试听保留为可选 |
| 转写在另外的核对入口，改字离开可能丢失 | 首页直接读写文字草稿，账号/空间隔离保存 |
| 保存与总体理解之间还要手动操作 | 本段 MODEL 成功后，同一事务排队累计分析；App 退出不影响已提交的服务端任务 |
| 首页重复显示原音、设备文件、固件、电量、容量及调试说明 | 文字与当前进度优先；技术数据集中在设备管理 |
| 每 8 秒完整串行刷新并禁用界面，新的状态会打断播放 | 处理中只刷新录音状态；闲置降低频率；资料变化时再更新人物内容；文件读写离开主线程 |

累计分析会使用来源有效、已核对的材料，保留引用和 AI 观察属性；它不会自动把推测标为本人确认的事实。重点仍由设备时间与转写句子可靠对应后参与整理，不猜测对应位置。

## 保存与恢复

- 自动转写保存的是草稿；“保存到记忆”才提交你看过的文字和补充。
- 自动上传保留幂等键。断网或响应丢失可有限重试，已收到的录音不会因重试再建一条。
- 切换账号/人物空间会取消旧任务并清除可见内容；重新进入原空间可恢复草稿及未完成的自动上传。
- App 被系统完全结束时，本机未上传任务在重新打开后继续；已上传到服务器的任务继续处理。
- 升级不自动批量上传旧的未上传档案；可以在“档案 → 我的录音”继续处理旧文件。
- 原音、机器原稿和人工补充分别保留。保留当前 App，直接覆盖安装，不需要卸载或 USB 调试。

测试截图及测试音频会明确标注模拟/虚构来源。新版真实 vivo 与实体录音豆的最终操作体验，仍以实机验收为准。
