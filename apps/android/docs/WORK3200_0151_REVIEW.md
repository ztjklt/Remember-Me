# 0.15.1 录音豆与重点整理复核

本版面向 Android Soundcore SDK 1.3.02。源码覆盖、模拟器验证和实物验收分开记录；用户先查看本说明与截图，再决定安装验收。安装包使用既有内部签名，不需要用户开启 USB 调试。

## 重点标记能否影响 AI

能。SDK 提供实时片段 `isMark`、传输完成 `markTimeStampList` 和 `onDecodeFileMarkers`；后两者给出毫秒时间点。设备双击重点与手机“标记重点”分别保存 device/phone 来源。SDK 不提供 AI 权重或公开写入设备标记的方法。

本版让标记影响“整理优先级”：根据 ASR 句子时间轴找出重点对应文字，把重点来源 priority_weight 设为 2、其他为 1，给 AI 完整上下文并要求优先覆盖重点。随后核验输出证据，引用重点的记忆优先显示并注明来源。它不是修改模型参数，不保证每个标记一定产生一条记忆，也不提高事实/人格置信度。无时间轴、改写或重复无法唯一定位时不猜测加权。

默认匹配范围是标记前 10 秒、后 5 秒，取相交完整句子。这是 App 的规则。个人理解继续依据有证据的记忆形成；本版没有把标记当作人格真值，也没有另外实现 Twin 问答检索加权。

## 为什么之前没走通

之前实现的是独立连接/导入入口，首页手机录音与它没有完整统一；切页会释放旧设备会话。蓝牙显示已连接也不等于充电盒绑定确认完成，旧截图 binding/3 指向绑定确认超时。录音停止回调的时长、文件 ID 有各自有效条件，误用会导致状态或下载调度卡住。设备传来的是裸 Opus，收到文件仍需真正解码，不能改后缀冒充 WAV。

重点原来只保存和显示，没有保留 ASR 句子时间轴，也没有把重点对应文字放进 AI 请求。这是接入链路不完整，不是 SDK 不支持重点。本版补齐了这几层，并在云端实跑中发现、修复了 AI 改写逐字证据导致整理失败的问题；校验仍保持严格。

签名包复验还发现授权快速失败时，连接服务尚未登记前台通知就被取消，Android 会报启动超时。0.15.1 把通知登记提前到服务创建，避免这条启动/关闭竞态。0.15.0 初版保留为失败候选，不供正式验收。

## 从录音到整理，实际怎么用

1. 安装验收版后登录，在“今天”选择“录音豆”（默认来源）；“手机”仍可切换。
2. 准备连接、允许附近设备权限、扫描、选择自己的 soundcore Work。首次绑定按页面指引把录音豆放入充电盒，闪灯时按盒按钮确认。已绑定设备不要反复发起首次绑定。
3. 取出录音豆，按**录音豆本体的自锁录音按钮**开始。充电盒按钮用于绑定确认。首页应显示录音中和时长；开始/结束由实体按键完成。SDK 暂停/恢复只用于已有录音。
4. 讲约 30 秒，中间双击设备重点区，观察手机重点提示；也可点击手机“标记重点”。设备精确时间点随文件回传。
5. 再按本体按钮结束。首页应显示结束、读取本段文件、下载进度，再解码保存。百分比来自下载/设备进度；未知总量和 ASR/AI 阶段只显示阶段，不编造百分比。
6. 在首页试听，点击重点可回听对应位置；确认音质和录音内容。文件在 App 私有空间中，首页提供入口，不需要用户翻找系统文件夹。设备原文件不会自动删除。
7. 同意云端处理后上传，机器转写完成先本人核对文字。核对页能看重点与对应文字；提交后再整理记忆，结果显示有多少条记忆引用重点。
8. 记忆及证据进入既有个人理解/人物模型流程。随后可查看、纠正，再按授权参与问答；不是蓝牙一连上就已经完成内容剖析。

## 已接入的 SDK 范围

完整方法及回调见 [SOUNDCORE_1302_CAPABILITIES.md](SOUNDCORE_1302_CAPABILITIES.md)。除首页录音闭环，还接入暂停/恢复、设备状态、时间同步、蓝牙/SPP 与 Wi-Fi 下载、Find My 开关、日志查询/采集/下载/导出/删除、单个录音删除、解绑、重置及官方固件导入/组合 OTA 入口。

删除、解绑、重置、升级必须由用户选择并确认，不会为“全量接入”自动执行。交接包未包含升级固件，因此未刷机。Find My 是设备开关，本 App 未提供定位地图。

## 实物验收仍需完成

本开发环境没有连接你的 vivo 手机和录音豆。模拟器已能验证真实 App 状态机、解码和云端处理，但不能证明实体蓝牙、固件、麦克风音质、Wi-Fi 切换和后台存活。尤其要用实际下载的裸 Opus 核对格式，不能把合成测试音频等同于设备录音。

安装后逐项记录：真实设备信息 → 实体按键开始/时长 → 切到其他页再回首页仍保持连接 → 设备重点提示 → 结束/自动下载 → 清楚试听 → 上传/文字核对 → 重点记忆；再试断开重连、同一文件重复导入不重复生成。维护/OTA 分项验收，不把核心闭环通过扩大为所有硬件操作通过。

当前尚无实时字幕：SDK 能回传实时音频，但字幕还需流式解码和 ASR。当前本地解码有 8 MiB 原始文件、100 MiB PCM、120 秒处理时限，长时录音能力未通过验收。SDK 未公开从空闲远程开始/结束录音、向录音豆写入手机标记或播放 Twin 声音的完整接口。

测试记录、签名与 APK SHA256 随交付目录保存。只有完成上述实物验收，才能将本版认定为“这台手机和这颗录音豆的全流程通过”。
