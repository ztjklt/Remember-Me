# 0.16.4 对话体验

2026-10-16，用户确认沿用 Android / ECS / DeepSeek 与小米 TTS，参考 iOS 的界面与通话组织，不接入另一套 CloudBase 账号或火山 SDK。

## 使用

在「对话」进入「语音聊聊」，确认本次云端处理并允许麦克风。

- 主画面显示连接、倾听、思考、准备播报、播报或暂停状态。
- 「我来说」在思考、准备播报和播报时出现，立即停止旧输出，再接下一句。自动语音打断继续保留。
- 「暂停 / 继续」控制本次通话；「结束」释放麦克风与播放。原静音入口与暂停调用同一套停止逻辑，合并为一个明确入口。
- 右上角「本轮对话」显示识别文字和回答，回答依据按需展开。没有伪造音量、时延或百分比。
- 文字聊天的校准、表达设置及声音许可放在「对话工具」。已开始的校准任务仍直接显示。

## 借鉴范围

参考 iOS `c401834334705ed02e8a19b3f9f74ce3b08a11bc` 的 `TwinVoiceCallView.swift` 与 `TwinVoiceCall.swift`：简化主通话画面、逐步展开依据、区分连接与播报状态、隔离旧轮次回调。

Android 仍使用既有 `voice-sessions` WebSocket 协议。没有合入 iOS 服务端、人物存储、SDK、账号或接口契约；没有新增云服务费用配置或修改生产部署。文字回答仍来自当前服务器的 Twin；现有默认 `pipeline` 调用 Paraformer / Twin（微信 DeepSeek）/ 小米 TTS，原有显式实时试用选项保留。

## 客户端修复

1. 收到 `answer_ready` 只进入「准备播报」，实际 AudioTrack 播放游标推进后才显示「正在说」。
2. 完成音频只消费一次结束状态，不在后续每次播放检查时覆盖下一句话的「正在想」。
3. 字幕和错误与音频一样检查轮次。打断本地立即清空播放，并在服务端确认新轮次前拒绝旧输出。
4. 播放进度没有变化时不重复发送相同确认消息；WebSocket 自身的连接保活保持原设置。
5. 保留账号、人物、前后台和许可约束；系统减少动态效果设置可关闭呼吸光圈。

以上改善交互与客户端状态一致性，不代表模型回答质量或端到端时延已经提高。模型、检索和后台存储没有在本次修改。

## 核验方式

`VoicePresentationTest` 覆盖轮次、暂停、打断与播放状态；`VoiceExperienceTest` 在 Android 模拟器运行正式 Compose 界面、合成协议事件和原生 AudioTrack 游标。界面截图中的对话内容是测试文本，不是在线模型回答。

本轮无需录音豆。实体 vivo 的麦克风、回声、外放听感及弱网连续通话仍由实际安装后验证。
