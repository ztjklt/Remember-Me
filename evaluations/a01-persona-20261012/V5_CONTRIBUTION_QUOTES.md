# Persona v5：签名补记限定为原文摘录

本轮只改 AI Core 和离线测试，没有重启运行时或发起真实 provider 请求。v4 实际失败保留，原 18 题没有重跑或改写。生成提示为 `persona-conditional-reviewed-v5`，审阅提示为 `persona-semantic-review-v4`；模型、供应商和私有 API 字段不变。

## 已核对的 v4 失败

独立运行保存在忽略目录 `services/backend/var/a01-20261012/companion-v4-regression-20261012/`。trace `61d535d07a3645829befa2f9b13ccd24` 经两次 provider JSON 返回后，在约 11.56 秒因 `unsupported`、`attribution` 被语义审阅拒绝，没有答案。补记随后撤回。

原草稿的 ATTRIBUTED 第一点把 ASR 的歧义动作编入流畅的观察复述，未标明不确定；它不是所选补记的连续原文。第二点采用 SIMULATION，引用修电器安全界限 `u2` 回答如何理解旧物，随后又夹入补记仅是一次观察的说明，但该要点没有贡献引用。两处都应继续受审查约束，不能为了交付而放行。完整 reviewer reasoning 没有留存，因此这些是依据原文和草稿的开发助手文本审阅，不能冒称模型每个错误码的完整推理。

## 有界修复及其理由

ATTRIBUTED 的 text 必须与所选同一条签名补记中的连续原文逐字一致。不得重写标点、拼接片段、加作者解释或引用另一作者的文字。程序在引号外加实际作者、分类及“原文摘录”标签；引文中的“我”仍属于原作者或原有转述链。多位作者或不同位置的引文分别成点，各自引用。该规则阻止 AI 把有歧义的 ASR 动作改写成新的确定叙述，同时保留来源身份。

不匹配会产生安全固定类别 `contribution_quote_basis`，不在日志中输出正文或姓名。它可以使用既有的一次结构修正，仍须保留必经语义审阅，全部最多三次 provider 调用；语义 false 不重试，不变成 UNKNOWN。

生成与审阅共用的 mode_policy 标明“所选补记的连续原文”及“理解须与当前问题具体判断和情境相关”。提示优先选择完整的作者明确观察/原有解读及相邻限制，不要求讲清 ASR 歧义动作；没有相关本人理解时可以交付具名原文视角。不能只因主题相近或问题用了“你可能怎样”就强选本人 trait，不能把补记内容混入 FACT / SIMULATION。真正未知的本人新决定仍可保留未知。

这一修复是对自由改写的确定性收紧，不是移除审阅。连续子串仍可能截掉否定、人物指代或一次观察的限制；逐字摘录也不意味着 ASR 本身无误。审阅继续收到所选补记全文，并须拒绝断章取义或不相关 trait。没有用关键词或正则宣称解决语义相关性，也没有把实际问题、具体观察或预期答案硬编码到提示中。

## 离线验证

新增 `tests/test_persona_contribution_quotes.py` 共 10 项，首次 **9 failed / 1 passed**。通过既有测试改写以适应严格引文形式后，Persona 相关集合 **80 passed**；完整 AI suite **376 passed**，26.40 秒，有两项既有依赖弃用警告。测试使用现有 AI venv，代理环境只在测试进程内清除；未安装依赖或改运行时环境。

测试覆盖改写、断续拼接、标点变化、跨作者取句、分别具名的多作者原文、无相关本人 trait 的补记视角，以及修正后仍受语义否决、截去否定仍不得发布。离线回复是脚本，不证明真实模型会正确选择引文或理解相关性。

另以保存的 v4 第一个实际草稿要点和当次 ASR 原文进行无 provider 的本地渲染回放，得到 `contribution_quote_basis`，证明新的确定性规则会拦住这一实际改写。第二点的相关性仍不能由此推断为已解决。后续只安排一次独立 v5 实测，是否成功以新原件及逐项文本审阅为准，不能盲目循环修改提示并替换失败。
