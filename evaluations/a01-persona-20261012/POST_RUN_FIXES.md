# 18 题运行之后的离线修复

本文件记录 `persona-conditional-reviewed-v2` 的离线修改。它不修改或替代 [RESULTS.md](RESULTS.md) 中的 v1 实测结论，也没有据此重跑原 18 题。原始 `run.json` 的 SHA256 与独立审阅记录一致。

## 总时间预算

v1 的每次 Weixin 请求固定 45 秒，Persona 总时间只在调用前后检查 65 秒。实际 P02、P05 在审查第一次超时之后重试返回，累计约 79 秒和 76 秒，因旧总预算被丢弃。

v2 增加可读配置：

| 配置 | 默认 | 允许范围 |
| --- | --- | --- |
| `AI_PERSONA_TOTAL_TIMEOUT_SECONDS` | 90 秒 | 大于 0，不超过 90 秒 |
| `AI_PERSONA_CALL_TIMEOUT_SECONDS` | 45 秒 | 大于 0，不超过 45 秒 |

每次 provider 请求使用 `min(单次上限, 总截止时间的剩余秒数)`。总调用仍最多三次；只有 ProviderTimeout 可以网络重试，认证、限流、不可用、格式错误及语义否决都不会作为网络重试。原来至多一次的生成结构修复仍占用同一三次调用预算，并为独立审查保留一次。

WeixinChat.complete 增加可选的 `timeout_seconds`，只有 Persona 使用它。预算路径以 `asyncio.timeout` 包住异步 HTTP 请求和受大小上限约束的整个响应读取，超时取消后关闭该请求客户端，不会用后台线程继续等待再同时发重试。HTTPX 的各阶段超时同时设为不超过传入预算；其他未传预算的既有调用仍走原同步路径。总上限为 Backend 100 秒调用超时保留约 10 秒本地处理余量；操作系统极端调度/清理停顿并非硬实时保证。

## UNKNOWN 的审查适用范围

P06 的 v1 日志只有审查拒绝码 `counterexample/not_conditional/incomplete`，没有草稿，所以不能断言一定是误拒。原提示中没有足够直接地区分 UNKNOWN 和 SIMULATION 的适用检查；此次修复明确了这个歧义。

- 审查请求增加程序生成的逐点 `review_scope`。SIMULATION 必须核对条件语气及已选理解的相关反例；即便另一要点 UNKNOWN，也不能放宽这部分。
- UNKNOWN 不需要第一人称、条件模拟句式或复述无关理解反例。它依然必须通读可见资料，检查是否错漏已有事实、明确否定或能支持所问判断的相关理解；失败使用 `unsupported_unknown` / `incomplete`。
- 混合问题保留已知部分，未知只作用于缺证据的部分。语义审查返回 false 仍报错，不自动纠正、不重试语义判断、不把错误变成 UNKNOWN。
- 对应生成、输出与审查提示版本升为 v2；不更改模型或供应商。

## 验证及尚未验证的部分

先新增失败测试，再修改实现：首次 12 failed / 39 passed，其中 `3 秒生成 + 45 秒审查超时 + 31 秒审查成功` 可复现旧 65 秒丢弃问题。修改后相关 Persona、Weixin 及贡献上限共 94 passed，完整 AI suite 为 **330 passed**，有两项现存依赖弃用警告。

测试覆盖剩余预算传入、三次调用上限、超时取消与流关闭、响应大小限制、错误分类、可读配置边界、UNKNOWN/混合模式审查包，以及 false 不能绕过。模型回复为脚本或本地 MockTransport；这些测试验证确定性控制流及提示/协议，不证明真实模型此后一定正确处理 P06。

没有重启运行时，没有发出新的真实模型调用，没有改 Backend 或移动端。这两处修改的真实服务效果待另行授权的、独立标识的后续试验验证；不能把它们补算进 v1 的成功数。
