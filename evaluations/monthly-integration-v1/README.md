# 三个人物的虚构月度材料

全部故事为编写的测试素材，不代表真实患者、消防员或重病者群体。声音由小米生成；不使用真人声纹。

- manifest.json：30段原稿的哈希、模拟日期、预期隐私与更新关系；字符数不是音频时长。
- scripts：模型可见的讲述原稿，仅用来生成语音，不能作为ASR核对结果直接覆盖。
- gold：60个独立检查题、预期事实与禁止推断项。只有问题可发送问答模型，标准答案不得放入上下文。
- 实际音频、调用清单、机器转写和核对结果在忽略目录 `services/backend/var/monthly-eval/`；与团队源码分开。

运行工具位于 `tools/monthly_eval/`，当前依赖Python httpx/python-dotenv及已启动的本机Whisper服务。

```
python tools/monthly_eval/build_corpus.py
python tools/monthly_eval/speech_pipeline.py --samples
python tools/monthly_eval/product_loop.py --ingest-samples
```

先听音频、核对ASR，另存核对稿，再以 `product_loop.py --approve <episode-id> --reviewed-file <单独核对稿>` 明确提交。此命令会授权云端整理，不得在密钥缺失时把队列建立算成验收成功。三个人的记录者与读者凭据在本机 `identities.json`，可分别用于网页和Android登录，不进Git。

`speech_pipeline.py --remaining` 必须先有三个样本的sample-gate.json；真实微信调用、核对稿、记忆保存、问答来源、人工听读、180–300秒时长六项均通过才放行。这个文件必须由审阅者按证据填写，工具不会自行改成通过。`--preset` 是显式备用预置音色路线，会记入记录，不自动切换。

后续27段必须按人物内日期顺序录入。第4段纠正和第6段补充应在核对前关联第1段具体记忆；第5段为时间变化；第7段私密；第9段读者先提交问题单，第10段本人回答默认私密。勿用数据库直接修改状态代替这些产品动作。

本轮10类真实模型检查：原话、跨录音、本人纠正、时间变化、第三方转述、同名人物、隐私隔离、未知、否定不确定、改写提问。每类每个角色记录事实正确性与来源支持，不能仅看HTTP200。未来答案不得提前进入上下文。重复故事不能增加独立观察次数。

真实调用结果、合成语音听读、真人麦克风、浏览器、模拟器、真机分别记录；合成材料通过不代表真实患者使用通过。
